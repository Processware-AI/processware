# 사양 검증 (WI-VCSMS-02-05-04)

> 상위 절차: [[PRO-VCSMS-02-05_제품개발_사이버보안_엔지니어링_절차]] · 상위 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
정의된 사이버보안 사양이 상위 추상화 사양(컨셉 요구·통제)에 대해 완전·정확·일관함을 검증하여, 약점 분석 결과를 반영한 사양이 통합·검증으로 진행하기에 충분함을 확인한다.

## 2. 수행 주체
- **주 수행자**: 보안 설계자
- **검토자**: Project CS Lead
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
ISO/SAE 21434 §10.4.1([RQ-10-08])에 적용한다. 본 검증은 사양-요구 정합성 검증으로, 구현·통합의 사양 충족 확인(WI-05-05)과 구별된다. 약점 분석(WI-05-03) 반영 후 사양을 검증한다.

## 4. 입력 자료 / 산출물
- **Input**
  - [[TMP-VCSMS-02-05-01-01_사이버보안_사양서]] (약점 분석 반영본)
  - [[TMP-VCSMS-02-04-05-01_사이버보안_컨셉_및_요구사항_명세서]] (상위 추상화 사양, 대비 기준)
  - [[TMP-VCSMS-02-05-03-01_아키텍처_약점_분석서]] (처리 반영 확인)
- **Output**
  - [[TMP-VCSMS-02-05-04-01_사양_검증보고서]] 작성분 (WP-10-04)

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 약점 분석이 승인(WI-05-03 done) 상태이고 처리(설계변경·사양보완)가 반영되었는지 확인한다(entry_gate).
2. 검증 기준(상위 컨셉 요구·통제)과 검증 대상(사양서)을 정렬한다.
3. 사양 검증보고서 양식([[TMP-VCSMS-02-05-04-01_사양_검증보고서]])을 발번한다.

### 5.2 수행 단계
1. **완전성 검증** ([RQ-10-08])
   - 모든 상위 요구(CR-##)가 사양(SP-##)으로 빠짐없이 구체화되었는지 점검한다.
   - 약점 분석의 사양보완 처리가 모두 반영되었는지 점검한다.
2. **정확성 검증** ([RQ-10-08])
   - 각 사양이 상위 요구를 정확히 구체화했는지(과대·과소·왜곡 없음) 점검한다.
3. **일관성 검증** ([RQ-10-08])
   - 사양 간 상충, 사양-할당 간 불일치가 없는지 점검한다.
4. **부적합 기록·판정**
   - 부적합을 기록하고 통과/조건부/미통과를 판정한다.
   - 미통과 시 재작업 대상 WI(05-01/03)를 지정한다.
5. **검토·승인**
   - Project CS Lead 검토를 반영하고 CSM 승인을 받는다.

### 5.3 완료 조건
- [ ] entry_gate(WI-05-03 done) 충족 확인
- [ ] 완전성 점검 완료(미구체화 요구 0, 사양보완 미반영 0)
- [ ] 정확성 점검 완료(과대·과소·왜곡 처리)
- [ ] 일관성 점검 완료(상충·불일치 0)
- [ ] 부적합 기록 및 판정 명시
- [ ] CSM 승인 기록 확보

## 6. 인터페이스 부서
- **검증 엔지니어**: 통과 사양을 통합·검증 입력으로 인수([[WI-VCSMS-02-05-05_통합_검증_활동_수행]])
- **보안 설계자**: 미통과 시 사양/약점 재작업

## 7. 주의사항 / 예외 처리

### 7.1 사양 검증 미통과
- 미통과 시 통합·검증 진행을 차단하고 지정 선행 WI(05-01 사양 또는 05-03 약점)로 반려한다. 재작업 후 본 검증을 재수행한다.

### 7.2 약점 처리 미반영
- 약점 분석의 설계변경·사양보완 처리가 사양에 미반영된 항목을 발견하면, 완전성 부적합으로 기록하고 WI-05-01/03 으로 반려한다.

### 7.3 상위 요구 변경
- 검증 중 상위 컨셉 요구가 변경되면, 변경 영향 사양을 식별하고 컨셉 단계 변경 관리([[PRO-VCSMS-02-01_프로젝트_사이버보안_관리_절차]]) 연계 후 재검증한다.

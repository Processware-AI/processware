# 목표·클레임 검증 (WI-VCSMS-02-04-04)

> 상위 절차: [[PRO-VCSMS-02-04_컨셉_단계_사이버보안_엔지니어링_절차]] · 상위 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
TARA 결과·리스크 처리 결정·사이버보안 목표·클레임이 서로 정확(correct)·완전(complete)·일관(consistent)함을 검증하여, 컨셉·요구 정의로 진행하기 전 컨셉의 상위 기준이 신뢰 가능함을 확인한다.

## 2. 수행 주체
- **주 수행자**: Project CS Lead
- **검토자**: 보안 설계자
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
ISO/SAE 21434 §9.4([RQ-09-07])에 적용한다. 본 검증은 정합성 검증(review·analysis)으로, 차량 수준 실증 검증(Clause 11)과 구별된다. 부적합 발견 시 선행 WI(-01~-03)로의 재작업 연계를 다룬다.

  - [[TMP-VCSMS-02-04-03-01_사이버보안_목표_클레임_명세서]]

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 목표·클레임 명세서가 CSM 승인 완료(WI-04-03) 상태인지 확인한다(entry_gate).
2. 검증 항목 체크리스트(정확·완전·일관 3축)를 준비한다.
3. 검증보고서 양식([[TMP-VCSMS-02-04-04-01_목표_클레임_검증보고서]])을 발번한다.

### 5.2 수행 단계
1. **정확성 검증** ([RQ-09-07])
   - 목표·클레임이 대응 위협 시나리오·리스크값과 모순 없이 정확히 대응하는지 점검한다.
2. **완전성 검증** ([RQ-09-07])
   - 모든 위협 시나리오(생략 제외)가 목표 또는 클레임으로 빠짐없이 커버되는지 점검한다.
   - 클레임의 근거 가정이 모두 존재하는지 점검한다.
3. **일관성 검증** ([RQ-09-07])
   - 목표·클레임 간 상충(예: 같은 자산에 상반된 보안속성)이 없는지 점검한다.
4. **부적합 기록·판정**
   - 발견된 부적합을 기록하고, 통과/조건부/미통과를 판정한다.
   - 미통과 시 재작업 대상 WI(-01~-03)를 지정한다.
5. **검토·승인**
   - 보안 설계자 검토를 반영하고 CSM 승인을 받는다.

### 5.3 완료 조건
- [ ] entry_gate(WI-04-03 done) 충족 확인
- [ ] 정확성 점검 완료(모순 항목 처리)
- [ ] 완전성 점검 완료(미커버 위협 0, 가정 누락 0)
- [ ] 일관성 점검 완료(상충 0)
- [ ] 부적합 기록 및 판정 결과 명시
- [ ] CSM 승인 기록 확보

## 6. 인터페이스 부서
- **보안 설계자**: 검증 통과 시 컨셉·요구 정의 착수([[WI-VCSMS-02-04-05_사이버보안_컨셉_요구사항_정의_및_할당]])
- **TARA 분석가/Project CS Lead**: 미통과 시 재작업 인수

## 7. 주의사항 / 예외 처리

### 7.1 검증 미통과(재작업)
- 미통과 시 컨셉·요구 정의(WI-04-05)로 진행을 차단하고, 지정된 선행 WI 로 반려한다. 재작업 후 본 검증을 재수행한다.

### 7.2 가정 미검증 클레임
- 클레임 근거 가정이 검증 불가(외부 통제 의존)면, 가정의 유효성을 차량 수준 검증(Clause 11) 또는 공급자 합의(Clause 7)로 이연 표식하고 추적 항목으로 등록한다.

### 7.3 경미 부적합(조건부 통과)
- 후속 컨셉 단계에서 해소 가능한 경미 부적합은 조건부 통과로 판정하되, 해소 기한·책임자를 명시하고 컨셉 검증(WI-04-06)에서 종결 확인한다.

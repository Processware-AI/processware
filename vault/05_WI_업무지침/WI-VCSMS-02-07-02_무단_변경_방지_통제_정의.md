# 무단 변경 방지 통제 정의 (WI-VCSMS-02-07-02)

> 상위 절차: [[PRO-VCSMS-02-07_생산_사이버보안_통제_절차]] · 기준: [[표준프로세스_구성원칙]]

## 1. 업무 목적
생산 통제 계획에 식별된 통제 지점에 대해, 양산 산출물이 의도하지 않게 변경되거나 무단으로 조작되는 것을 방지하는 **구체적 통제 수단**을 정의한다. 통제는 사람·도구·환경·기록의 4개 축에서 빈틈없이 설계한다. (VCSMS-R-095 / [RQ-12-02])

## 2. 수행 주체
- **주 수행자**: 생산기술 담당자
- **검토자**: Cybersecurity Manager (CSM)
- **승인자**: Project CS Lead

## 3. 범위
PRO-VCSMS-02-07 §5 단계 2(통제 정의)에 적용한다. 선행 WI-VCSMS-02-07-01 의 생산 통제 계획이 승인(done)된 후 착수한다(entry gate). 물리 보안·출입통제 일반은 상위 시설보안(인터페이스 대상)을 참조하고, 본 지침은 사이버보안 산출물의 무단 변경 방지 통제만 다룬다.

## 4. 입력 자료 / 산출물
- **Input**
  - 승인된 [[TMP-VCSMS-02-07-01-01_생산_통제_계획서]] (통제 지점 식별 결과)
  - 양산 도구·설비의 접근권한·로그 사양
  - 적용 가능한 통제 라이브러리(서명·해시·봉인·접근통제 등)
- **Output**
  - [[TMP-VCSMS-02-07-02-01_무단_변경_방지_통제_정의서]] 작성분
  - 통제 ID 체계(통제-A, B …)와 계획서 통제 지점 간 매핑

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 승인된 생산 통제 계획서에서 "(c) 무단 변경 방지 통제 연계"로 표기된 통제 지점을 추출한다.
2. 각 통제 지점에서 발생 가능한 무단 변경 위협(키 교체·펌웨어 교체·락 우회·로그 위변조)을 열거한다.
3. 조직 표준 통제 라이브러리·도구 접근권한 매트릭스를 확보한다.

### 5.2 수행 단계
1. **통제 지점별 위협 식별**
   - 각 통제 지점에 대해 "무엇이 무단으로 바뀔 수 있는가"를 구체적으로 식별한다.
2. **통제 수단 정의 — 4개 축**
   - 각 위협에 대응하는 통제를 다음 축에서 정의한다 (VCSMS-R-095 / [RQ-12-02]):
     - **사람**: 작업자 권한 분리·접근 인가·이중 확인
     - **도구/설비**: 도구 접근통제·서명키 격리(HSM)·설정 잠금
     - **환경**: 생산 영역 격리·봉인·반입물 통제
     - **기록**: 변조 불가 로그·해시 검증·이력 보존
   - 각 통제에 통제 ID(통제-A, B …)를 부여하고 계획서 통제 지점과 1:1 매핑한다.
3. **유효성 확인 방법 정의**
   - 각 통제가 실제로 작동하는지 확인하는 방법(주기 점검·로그 감사·우회 시도 테스트)을 정의한다.
4. **이상 대응 규칙 정의**
   - 통제 위반·무단 변경 탐지 시 즉시 조치(라인 정지·격리·NCR 발행) 흐름을 정의한다.
5. **CSM 검토·승인**
   - CSM 이 통제의 충분성(잔존 위협)을 검토한다.
   - Project CS Lead 가 승인한다(전자결재 또는 PCB 기록).

### 5.3 완료 조건
- [ ] 계획서의 모든 통제 지점에 대해 무단 변경 위협이 식별되었다
- [ ] 각 위협에 4개 축(사람·도구·환경·기록) 관점의 통제가 정의되었다
- [ ] 모든 통제에 통제 ID가 부여되고 계획서 지점과 매핑되었다
- [ ] 통제 유효성 확인 방법이 정의되었다
- [ ] 무단 변경 탐지 시 이상 대응 규칙이 정의되었다
- [ ] CSM 검토·Project CS Lead 승인이 완료되었다

## 6. 인터페이스 부서
- **시설보안**: 생산 영역 물리 접근통제·봉인 운영
- **IT/MES 운영**: 도구 접근권한·변조 불가 로그 인프라
- **CSM 조직**: 통제 충분성·잔존 위협 검토

## 7. 주의사항 / 예외 처리

### 7.1 통제 불가능 위협(잔존 위협)
- 기술·비용 제약으로 완전한 통제가 불가능한 위협이 있으면, 잔존 위협으로 명시하고 보상 통제(탐지·사후 추적)를 정의한 뒤 CSM·Project CS Lead 의 위험 수용 결정을 기록한다.

### 7.2 통제 도구 자체의 무결성 의심
- 통제에 사용하는 도구(서명기·검증 지그) 자체가 변조되었을 가능성이 제기되면, 해당 도구를 격리하고 교정·무결성 검증(기준 샘플 대조)을 거친 후 재투입한다. 의심 기간 산출물은 보류·재검사한다.

### 7.3 양산 중 통제 우회 탐지
- 양산 중 통제 우회가 탐지되면 즉시 해당 라인을 정지하고, 영향 산출물을 격리한다. NCR 을 발행하고 PRO-VCSMS-01-04(사고 대응) 연계 여부를 CSM 이 판정한다.

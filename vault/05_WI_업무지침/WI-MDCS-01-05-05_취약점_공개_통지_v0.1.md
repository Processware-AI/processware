# 취약점 공개(규제기관·사용자 통지) (WI-MDCS-01-05-05)

> 상위 절차: [[PRO-MDCS-01-05_보안_문제해결_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
취약점 처리가 종결되었을 때 규제기관·사용자에게 취약점 기술·심각도 점수·영향 버전·해결 방안을 적시에 통지(공개)하여, 사용자가 보호 조치를 취할 수 있게 하고 규제 통지 의무를 이행한다. 협력적 공개는 ISO/IEC 29147 을 따른다. (4.1.7)

## 2. 수행 주체
- **주 수행자**: 규제/대외 통지
- **검토자**: 보안운영위원회(PSGB)
- **승인자**: 보안운영위원회(PSGB)

## 3. 범위
PRO-MDCS-01-05 §5 단계5(공개)에 적용한다. **선행조건**: WI-MDCS-01-05-04(처리) 완료. 공개 대상 판정 후 수행한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 처리 결과·해결 방안(WI-MDCS-01-05-04)
  - 분석 보고서(CVSS·영향 버전)(WI-MDCS-01-05-03)
  - 규제 통지 요건·공개 정책(ISO/IEC 29147 참조)
- **Output**
  - [[TMP-MDCS-01-05-05-01_보안권고_및_공개통지문_v0.1]] 작성분
  - 보안 권고(advisory)·공개 통지문
  - 통지 증적(규제기관·사용자)

## 5. 수행 절차

### 5.1 사전 준비
1. 공개 대상(규제기관·사용자·연구자)과 통지 요건을 확인한다.
2. 협력적 공개(29147) 비공개 합의 기간·일정을 확인한다.

### 5.2 수행 단계
1. **공개 범위 결정**
   - 규제 통지 대상 여부·사용자 통지 범위·공개 시점을 결정한다.
2. **권고문 작성**
   - 취약점 기술·CVSS·영향 버전·해결 방안·완화책을 포함한 권고문을 작성한다.
3. **규제 통지**
   - 규제 통지 대상이면 규제기관에 적시 통지한다.
4. **사용자 공개**
   - 사용자·기관에 보안 권고를 배포하고 적용 안내를 제공한다.
5. **검토·승인**
   - PSGB 가 공개 내용·시점·범위를 승인한다(통지 증적 보존).

### 5.3 완료 조건
- [ ] 공개 대상·시점·범위 결정
- [ ] 권고문에 취약점 기술·CVSS·영향 버전·해결 방안 포함
- [ ] 규제 통지 대상이면 규제기관 통지 완료
- [ ] 사용자·기관 보안 권고 배포
- [ ] 협력적 공개(29147) 합의 기간 준수
- [ ] PSGB 검토·승인 및 통지 증적 보존

## 6. 인터페이스 부서
- **법무/규제 담당**: 규제 통지 요건·기한
- **고객지원/CS**: 사용자 배포 채널
- **WI-MDCS-01-05-04(처리)**: 해결 방안 수령
- **연구자(외부)**: 협력적 공개 조율

## 7. 주의사항 / 예외 처리

### 7.1 공개 시점 조율(미패치 노출 방지)
- 패치 배포 전 공개는 악용 위험을 높이므로, 해결 방안 가용 시점과 공개 시점을 조율한다. 단, 규제 통지 의무 기한이 우선하면 이를 준수한다.

### 7.2 협력적 공개 합의 위반 방지
- 연구자와의 비공개 합의 기간을 준수하고, 불가피한 조기 공개는 연구자와 사전 협의한다(ISO/IEC 29147).

### 7.3 적극 악용 중 취약점
- 이미 악용이 진행 중이면 완화책 우선 안내를 즉시 공개하고, 패치는 후속 제공한다(사용자 보호 우선).

### 7.4 다국가·다규제 통지
- 복수 규제 관할이 있으면 각 관할의 통지 요건·기한·언어를 충족하도록 통지 계획을 수립한다.

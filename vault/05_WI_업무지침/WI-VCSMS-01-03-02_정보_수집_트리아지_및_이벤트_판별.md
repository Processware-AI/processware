# 정보 수집·트리아지 및 이벤트 판별 (WI-VCSMS-01-03-02)

> 상위 절차: [[PRO-VCSMS-01-03_지속적_사이버보안_활동_및_취약점_관리_절차]] · 상위 정책: [[POL-VCSMS-01_자동차_사이버보안_거버넌스_정책]]

## 1. 업무 목적
선정된 정보원에서 사이버보안 정보를 **수집하고 트리아지**하여, 해당 정보가 **사이버보안 이벤트에 해당하는지 판별**한다. 정의된 트리거에 따라 정보를 신속·일관되게 분류하여 후속 평가로 연결한다.

## 2. 수행 주체
- **주 수행자**: 모니터링 담당 (Monitoring Lead)
- **검토자**: 보안 분석가 (Security Analyst)
- **승인자**: Cybersecurity Manager (CSM) — 이벤트 확정 권한

## 3. 범위
PRO-VCSMS-01-03 §5 단계 2 에 적용한다. 정보 수집·트리아지·이벤트 발생 판별(§8.3 [RQ-08-03])을 다룬다. 정보원·트리거 정의는 선행 [[WI-VCSMS-01-03-01_정보원_선정_및_트리아지_트리거_정의]] 전제(entry_gate). 이벤트 평가·약점 식별은 [[WI-VCSMS-01-03-03_사이버보안_이벤트_평가_및_약점_식별]] 로 이어진다.

## 4. 입력 자료 / 산출물
- **Input**
  - 활성 정보원에서 수집된 사이버보안 정보(취약점 권고·이상 텔레메트리·연구)
  - 트리아지 트리거 정의([[WI-VCSMS-01-03-01_정보원_선정_및_트리아지_트리거_정의]] 산출물)
  - 운영 자산 인벤토리
  - ISO/SAE 21434 §8.3 [RQ-08-03] 요건
- **Output**
  - 트리아지 기록(정보→분류→판정)
  - 사이버보안 이벤트 후보 목록 (WP-08-03)
  - [[TMP-VCSMS-01-03-02-01_사이버보안_이벤트_트리아지_기록부]] 작성분

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. entry_gate 확인: WI-VCSMS-01-03-01 이 `done`(정보원·트리거 정의·승인) 인지 확인.
2. 활성 정보원에서 신규 수집 정보를 집계.
3. 트리아지 트리거·SLA 를 재확인.

### 5.2 수행 단계
1. **정보 수집·정규화**
   - 활성 정보원의 신규 정보를 수집하고 자산 매칭이 가능하도록 정규화(영향 자산·버전·심각도).
2. **트리아지 적용** ([RQ-08-03])
   - 정의된 트리거를 적용하여 정보를 우선순위 분류(P1/P2/P3) 및 SLA 내 처리.
   - 자산 무관·중복·노이즈는 사유와 함께 기각(close-as-noise).
3. **이벤트 판별**
   - 트리아지 결과가 사이버보안 이벤트 기준을 충족하는지 판별.
   - 이벤트 후보를 [[TMP-VCSMS-01-03-02-01_사이버보안_이벤트_트리아지_기록부]] 에 등록(영향 자산·근거·우선순위).
4. **분석가 교차 검토**
   - 보안 분석가가 P1/P2 이벤트 판별의 타당성을 교차 검토.
5. **CSM 이벤트 확정·연계**
   - CSM 이 이벤트를 확정하고 후속 평가(WI-01-03-03)로 연계.
   - 즉시 대응이 필요한 경우 사고대응(PRO-01-04) 연계 여부 판단.
6. **적시성 점검·기록**
   - 접수→트리아지 적시성(KPI: SLA 충족)을 점검하고 기록부를 갱신.

### 5.3 완료 조건
- [ ] 활성 정보원 신규 정보 수집·정규화(자산 매칭 가능 형태)
- [ ] 트리거 적용·우선순위 분류 및 SLA 내 처리
- [ ] 자산 무관·노이즈 기각 사유 기록
- [ ] 이벤트 후보 영향 자산·근거·우선순위 등록
- [ ] 보안 분석가 P1/P2 교차 검토 및 CSM 이벤트 확정
- [ ] 트리아지 적시성(SLA) 점검·기록부 갱신

## 6. 인터페이스 부서
- **정보원 운영(WI-01-03-01)**: 활성 정보원·트리거
- **사고대응(PRO-01-04)**: 즉시 대응 필요 이벤트 연계
- **자산관리**: 영향 자산 식별 지원

## 7. 주의사항 / 예외 처리

### 7.1 SLA 초과 위험(대량 유입)
- 정보가 대량 유입되어 SLA 내 처리가 어려운 경우:
  - 우선순위 큐로 P1 을 우선 처리하고 자원 증원을 요청.
  - SLA 초과 항목과 사유를 KPI(MAT-008)에 반영.

### 7.2 모호한 이벤트 판별
- 이벤트 해당 여부가 모호한 경우:
  - 보수적으로 이벤트 후보로 등록하여 평가 단계에서 정밀 판별.
  - 기각 시에는 근거를 반드시 기록(과소평가 방지).

### 7.3 긴급 이벤트(악용 진행 중)
- 악용이 진행 중인 긴급 이벤트를 판별한 경우:
  - 평가 절차와 병행하여 즉시 사고대응(PRO-01-04)을 가동.
  - CSM·경영진 긴급 통지(정보공유 채널 가동).

# 폐기 관련 post-development 요구사항 제공 (WI-VCSMS-02-09-04)

> 상위 절차: [[PRO-VCSMS-02-09_운영_업데이트_및_지원종료_폐기_절차]] · 기준: [[표준프로세스_구성원칙]]

## 1. 업무 목적
item 또는 component 의 폐기(decommissioning) 단계에서 사이버보안 위험을 줄이기 위한 **폐기 관련 post-development 사이버보안 요구**를 식별하여, 폐기를 수행하는 주체(정비망·재활용업체·고객)가 사용할 수 있도록 가용화한다. 폐기 시 민감 데이터·키·자격증명이 안전하게 제거되도록 한다. (VCSMS-R-101 / [RQ-14-02])

> 본 WI 는 선택(mandatory: false) — 폐기 단계가 적용되는 경우에만 수행.

## 2. 수행 주체
- **주 수행자**: Cybersecurity Manager (CSM)
- **검토자**: 개발팀·운영/필드
- **승인자**: Cybersecurity Manager (CSM) — 본인 책임 활동, 상위 검토는 PCB

## 3. 범위
PRO-VCSMS-02-09 §5 단계 4(폐기 요구 제공)에 적용한다. 선행 WI-VCSMS-02-09-03(지원 종료 통보)이 완료(done)된 후 착수한다(entry gate). 실제 폐기·재활용 공정 수행은 외부 주체(인터페이스 대상)가 담당하며, 본 지침은 사이버보안 폐기 요구의 식별·문서화·제공만 다룬다.

## 4. 입력 자료 / 산출물
- **Input**
  - 대상 item/component 의 사이버보안 케이스·자산 목록(키·자격증명·민감 데이터)
  - 지원 종료 통보서(WI-09-03)와 잔존 위험
  - 폐기 수행 주체·경로(정비망·재활용업체)
- **Output**
  - [[TMP-VCSMS-02-09-04-01_폐기_사이버보안_요구_제공서]] 작성·제공분
  - 폐기 요구 가용화 기록(제공 대상·일자·확인)

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 대상 item 의 사이버보안 자산(저장된 키·인증서·개인정보·로그)을 목록화한다.
2. 폐기 시 처리해야 할 위험(키 유출·데이터 잔존·재사용 부품 통한 공격)을 식별한다.
3. 폐기 수행 주체와 그들이 실제로 수행 가능한 절차 수준을 파악한다.

### 5.2 수행 단계
1. **폐기 사이버보안 요구 식별**
   - 안전 폐기를 위한 요구를 식별한다(키·자격증명 파기, 저장 데이터 완전 삭제, 재사용 방지 무력화). (VCSMS-R-101 / [RQ-14-02])
2. **요구 문서화**
   - 각 요구에 대해 폐기 주체가 따를 수 있는 구체 절차·검증 방법을 기재한다.
3. **검토**
   - 개발팀이 기술적 실행 가능성을, 운영/필드가 현장 적용성을 검토한다.
4. **가용화(제공)**
   - 폐기 요구를 폐기 수행 주체에게 제공한다(정비 매뉴얼·재활용 가이드·고객 안내에 포함).
   - 제공 대상·일자·확인을 기록한다.
5. **승인·종결**
   - CSM 이 요구의 충분성을 승인한다.
   - 수명주기 문서 일체를 보존(아카이브)하고 PRO 흐름을 종결한다.

### 5.3 완료 조건
- [ ] 대상 item 의 사이버보안 자산(키·자격증명·민감 데이터)이 목록화되었다
- [ ] 폐기 시 처리 위험이 식별되었다
- [ ] 폐기 사이버보안 요구가 식별·문서화되었다(파기·삭제·재사용 방지)
- [ ] 각 요구에 폐기 주체가 따를 절차·검증 방법이 기재되었다
- [ ] 폐기 요구가 폐기 수행 주체에게 제공·기록되고 CSM 승인을 받았다

## 6. 인터페이스 부서
- **정비망/딜러**: 폐기·교체 시 요구 적용
- **재활용업체**: 부품 재활용 시 무력화 절차 적용
- **개발팀**: 기술적 파기·삭제 방법 제공

## 7. 주의사항 / 예외 처리

### 7.1 폐기 주체의 실행 역량 부족
- 폐기 주체가 요구를 실행할 역량(도구·전문성)이 부족하면, 요구를 그들의 수준에 맞게 단순화하거나 OEM 회수·중앙 파기 옵션을 제공한다. 단순화로 위험이 남으면 그 한계를 명시한다.

### 7.2 물리 접근 불가 부품의 키 파기
- 물리적으로 접근·전원 인가가 불가능한 폐차 부품의 키 파기가 어려우면, 키의 원격 폐기·서버 측 무효화(인증서 폐기 목록 등록)를 대체 통제로 정의한다.

### 7.3 폐기 후 데이터 유출 사고
- 폐기된 부품에서 데이터 유출이 사후 확인되면, 잔존 위험 추적 항목을 갱신하고 영향 범위를 평가하여 사고 대응(PRO-VCSMS-01-04) 연계 여부를 CSM 이 판정한다. 폐기 요구·절차를 보완 개정한다.

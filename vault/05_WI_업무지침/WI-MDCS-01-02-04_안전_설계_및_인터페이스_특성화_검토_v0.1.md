# 안전 설계 개발 및 인터페이스 특성화·설계 검토 (WI-MDCS-01-02-04)

> 상위 절차: [[PRO-MDCS-01-02_보안_SW_개발_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
보안 아키텍처를 상세 설계로 구체화하면서 안전 설계 모범사례를 적용하고 식별된 위협 완화책을 설계에 반영하며, 물리·논리 인터페이스를 신뢰경계 관점에서 특성화하고, 설계 검토로 보안 약점을 식별·추적한다. (5.4.1, 5.4.2, 5.4.3, 5.4.4)

## 2. 수행 주체
- **주 수행자**: 보안 아키텍트 / 개발자
- **검토자**: 검토자(독립)
- **승인자**: 검토자(독립)

## 3. 범위
PRO-MDCS-01-02 §5 단계4(상세설계)에 적용한다. **선행조건**: WI-MDCS-01-02-03(아키텍처) 완료. 설계 중대 변경 시 재수행한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 보안 아키텍처 명세(WI-MDCS-01-02-03)
  - 위협 모델·위협 완화 목록(PRO-MDCS-02-01)
  - 보안 요구명세(WI-MDCS-01-02-02)
- **Output**
  - [[TMP-MDCS-01-02-04-01_보안설계_인터페이스특성화_및_설계검토_v0.1]] 작성분
  - 상세 보안 설계 문서
  - 인터페이스 특성화 분석(신뢰경계·데이터 분류)
  - 설계 검토 기록(약점 추적)

## 5. 수행 절차

### 5.1 사전 준비
1. 아키텍처 명세·위협 완화 목록·보안 요구를 확보한다.
2. 적용할 안전 설계 모범사례(최소권한·입력검증·실패안전 등)를 정리한다.

### 5.2 수행 단계
1. **안전 설계 개발**
   - 모듈·컴포넌트의 상세 설계에 안전 설계 모범사례를 적용한다.
2. **위협 완화 반영**
   - 위협 모델의 각 완화책이 설계의 구체적 메커니즘으로 반영되었는지 매핑한다.
3. **인터페이스 특성화**
   - 물리·논리 인터페이스를 식별하고, 신뢰경계·전달 데이터 분류·인증/인가·검증 책임을 특성화한다.
4. **설계 검토**
   - 독립 검토자가 설계의 보안 모범사례 준수·완화 반영·인터페이스 안전성을 검토하고 약점을 추적·종결한다.

### 5.3 완료 조건
- [ ] 상세 설계에 안전 설계 모범사례 적용
- [ ] 위협 모델 완화책이 설계 메커니즘으로 모두 반영됨(미반영 0건)
- [ ] 모든 물리·논리 인터페이스가 신뢰경계·데이터 분류 관점으로 특성화됨
- [ ] 독립 설계 검토 수행·약점 추적·종결 기록 존재

## 6. 인터페이스 부서
- **WI-MDCS-01-02-03(아키텍처)**: 아키텍처 통제 상속
- **PRO-MDCS-02-01(리스크 관리)**: 위협 완화책 제공
- **WI-MDCS-01-02-05(구현)**: 설계를 구현으로 이관

## 7. 주의사항 / 예외 처리

### 7.1 완화책 설계 미반영
- 위협 완화책이 설계에 반영되지 못하면 대체 완화 설계를 마련하거나, 불가 시 잔여 리스크로 PRO-MDCS-02-01 에 반영하고 다음 단계 진행 가부를 PSO 가 판단한다.

### 7.2 인터페이스 신뢰경계 모호
- 인터페이스의 신뢰 수준이 모호하면 보수적으로 비신뢰로 간주하여 입력 검증·인증을 강화한다.

### 7.3 외부 인터페이스 통제 불가
- 외부 시스템 인터페이스에 통제를 직접 둘 수 없으면 경계측(자사측)에서 검증·격리 통제를 적용하고 가정·잔여 리스크를 문서화한다.

### 7.4 설계-요구 추적 단절
- 설계가 보안 요구를 충족하지 못하면 설계를 보완하거나 상위(아키텍처/요구) 단계로 에스컬레이션한다.

# 외부 컴포넌트 인벤토리(SBOM) 구성·재현 (WI-MDCS-01-04-02)

> 상위 절차: [[PRO-MDCS-01-04_보안_형상관리_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
출시·시판 중인 헬스SW 의 외부 컴포넌트 목록(SBOM)을 작성·갱신하고, 취약점 추적과 보안 의무 이행을 위해 과거 릴리스의 구성을 재현할 수 있는 능력을 유지하여, 외부 컴포넌트 취약점에 신속히 대응할 기반을 확보한다. (8-REQ-002)

## 2. 수행 주체
- **주 수행자**: 형상관리 담당
- **검토자**: 보안책임자(PSO)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-01-04 §5 단계2(컴포넌트 인벤토리)에 적용한다. 각 릴리스 시 SBOM 을 작성·갱신하고 보존한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 빌드 산출물·의존성 매니페스트
  - 변경통제 이력(WI-MDCS-01-04-01)
  - SW 분류표(WI-MDCS-01-01-01)
- **Output**
  - [[TMP-MDCS-01-04-02-01_외부컴포넌트_인벤토리_SBOM_v0.1]] 작성분
  - 릴리스별 SBOM(컴포넌트·버전·출처·라이선스)
  - 재현 가능성 확인 기록

## 5. 수행 절차

### 5.1 사전 준비
1. 대상 릴리스의 빌드 산출물·의존성 정보를 확보한다.
2. SBOM 형식·도구(SPDX/CycloneDX 등)를 확인한다.

### 5.2 수행 단계
1. **컴포넌트 수집**
   - 직·간접 의존성을 포함한 외부 컴포넌트와 버전을 수집한다.
2. **SBOM 작성**
   - 컴포넌트·버전·출처·라이선스·해시를 SBOM 으로 작성한다.
3. **분류 연계**
   - 각 컴포넌트를 SW 분류(MAINTAINED/SUPPORTED/REQUIRED)와 연계한다.
4. **재현성 확인**
   - 릴리스 구성을 재현할 수 있도록 빌드 정보·고정 버전을 보존하고 재현 가능성을 확인한다.
5. **검토·보존**
   - PSO 검토 후 릴리스별 SBOM 을 보존하고 모니터링(PRO-MDCS-01-03)에 제공한다.

### 5.3 완료 조건
- [ ] 직·간접 외부 컴포넌트가 모두 수집됨
- [ ] SBOM 에 컴포넌트·버전·출처·라이선스 기재
- [ ] 각 컴포넌트가 SW 분류와 연계됨
- [ ] 릴리스 구성 재현 가능성 확인
- [ ] PSO 검토·릴리스별 SBOM 보존

## 6. 인터페이스 부서
- **PRO-MDCS-01-03(유지보수)**: SBOM 기반 취약점 모니터링
- **WI-MDCS-01-04-01(변경통제)**: 컴포넌트 변경 반영
- **DevOps**: 빌드·의존성 정보 제공

## 7. 주의사항 / 예외 처리

### 7.1 전이 의존성 누락
- 직접 의존성만 기록하면 전이(간접) 취약점을 놓치므로, 의존성 그래프 전체를 SBOM 에 포함한다.

### 7.2 재현 불가 릴리스
- 과거 릴리스 구성이 재현 불가하면 가용 정보로 최대한 복원하고, 재현 불가 사유를 기록하며 차기부터 빌드 고정·아카이브를 강화한다.

### 7.3 라이선스·출처 불명 컴포넌트
- 출처·라이선스가 불명한 컴포넌트는 사용 보류 또는 대체를 검토하고, 불가피 시 리스크로 PRO-MDCS-02-01 에 반영한다.

### 7.4 SBOM 최신성 누락
- 릴리스 후 SBOM 갱신이 누락되면 모니터링 사각이 생기므로, 릴리스 게이트(WI-MDCS-01-02-08)에서 SBOM 보유를 확인한다.

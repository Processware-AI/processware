# 취약점 조사(적용성·검증가능성·위협) (WI-MDCS-01-05-02)

> 상위 절차: [[PRO-MDCS-01-05_보안_문제해결_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
접수된 취약점을 적시에 조사하여 제품 적용성(해당 제품에 존재하는지)·검증 가능성(재현 가능한지)·관련 위협을 판정함으로써, 후속 분석·처리의 근거를 마련한다. (9.3)

## 2. 수행 주체
- **주 수행자**: 취약점 분류자(triage)
- **검토자**: 보안책임자(PSO)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-01-05 §5 단계2(조사)에 적용한다. **선행조건**: WI-MDCS-01-05-01(접수) 완료. 유효 접수 건마다 SLA 내 수행한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 접수 건(WI-MDCS-01-05-01)
  - SBOM·제품 구성·위협 모델
  - 보고된 재현 정보·PoC(있는 경우)
- **Output**
  - [[TMP-MDCS-01-05-02-01_취약점_조사_기록서_v0.1]] 작성분
  - 조사 기록(적용성·검증 가능성·관련 위협 판정)
  - 분석 연계 여부 결정

## 5. 수행 절차

### 5.1 사전 준비
1. 접수 건의 보고 내용·재현 정보를 확인한다.
2. SBOM·제품 구성·위협 모델을 확보한다.

### 5.2 수행 단계
1. **적용성 판정**
   - 취약점이 해당 제품/버전에 실제 존재하는지 판정한다.
2. **검증 가능성 평가**
   - 환경에서 재현·검증 가능한지 평가한다(PoC 재현 시도).
3. **관련 위협 식별**
   - 취약점과 연결되는 위협(공격 시나리오·자산)을 식별한다.
4. **연계 결정**
   - 적용·검증 가능 건을 분석(WI-MDCS-01-05-03)으로 연계하고, 비적용은 사유와 함께 종결한다.
5. **검토·기록**
   - PSO 가 조사 충분성·SLA 준수를 검토한다.

### 5.3 완료 조건
- [ ] 제품 적용성 판정(존재/비존재)
- [ ] 검증 가능성 평가(재현 가능/불가) 수행
- [ ] 관련 위협 식별
- [ ] 적용·검증 가능 건이 분석으로 연계됨
- [ ] 비적용 건은 사유와 함께 종결
- [ ] PSO 검토·조사 기록 보존

## 6. 인터페이스 부서
- **WI-MDCS-01-05-01(접수)**: 접수 건 수령
- **WI-MDCS-01-05-03(분석)**: 적용 건 연계
- **PRO-MDCS-02-01(리스크 관리)**: 위협 모델 참조

## 7. 주의사항 / 예외 처리

### 7.1 재현 불가하나 적용 가능
- 재현이 어렵지만 적용 가능성이 있는 경우 비적용으로 단정하지 않고, 보수적으로 분석으로 연계하여 추가 검토한다.

### 7.2 조사 지연 우려
- SLA 내 조사가 어려우면 우선순위를 재조정하고, 안전 영향이 큰 건은 자원을 우선 투입한다.

### 7.3 정보 부족
- 보고 정보가 부족하면 보고자에게 추가 정보를 요청하되(특히 연구자 협력 공개), 응답 지연 시 가용 정보로 보수적으로 조사한다.

### 7.4 다수 제품 적용 가능성
- 동일 취약점이 여러 제품에 적용될 가능성이 있으면 교차 제품 영향을 분석(WI-MDCS-01-05-03)에서 다루도록 표시한다.

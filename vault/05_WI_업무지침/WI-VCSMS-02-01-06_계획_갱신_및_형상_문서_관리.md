# 계획 갱신 및 형상·문서 관리 (WI-VCSMS-02-01-06)

> 상위 절차: [[PRO-VCSMS-02-01_프로젝트_사이버보안_관리_절차]] · 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
프로젝트 진행 중 활동 변경·정련이 식별되면 사이버보안 계획을 갱신하고, 계획·작업산출물을 형상·변경·요구사항·문서 관리(§5.4.4 경계면) 대상으로 유지하여, post-development 릴리스 시점까지 작업산출물이 정확하게 갱신되도록 한다. (§6.4.2 [RQ-06-07,09,11,12])

## 2. 수행 주체
- **주 수행자**: Project CS Lead
- **검토자**: 형상관리자(CM)
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
본 지침은 PRO-VCSMS-02-01 §5 단계 6(계획 유지)에 적용한다. 형상·변경·문서 관리의 실제 통제 메커니즘은 상위 QMS(§5.4.4)를 **참조**하며(interface_only), 본 지침은 사이버보안 계획·WP 의 갱신 트리거와 추적만 정의한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 현 사이버보안 계획 ([[TMP-VCSMS-02-01-03-01_사이버보안_계획서]])
  - 변경 트리거(테일러링 결과·재사용 분석·TARA 갱신·일정 변경)
- **Output**
  - [[TMP-VCSMS-02-01-06-01_계획_변경관리대장]] 작성분 (변경 이력)
  - 갱신된 사이버보안 계획 (버전 증분)

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 계획이 형상관리에 등록되어 있는지 확인한다.
2. 변경 트리거(WI-04 테일러링·WI-05 재사용·TARA 갱신·일정 변경)를 수집한다.

### 5.2 수행 단계
1. **변경 식별·영향 평가**
   - 활동 변경·정련 항목을 식별하고 사이버보안 계획·WP 에 미치는 영향을 평가한다([RQ-06-07]).
2. **계획 갱신**
   - 영향 범위에 따라 계획 버전을 증분(경미 v0.x→v0.(x+1), 중대 구조 변경 시 별도 협의)하고 변경 내용을 반영한다.
3. **형상·문서 관리 반영**
   - 갱신 계획과 관련 WP 를 형상관리(§5.4.4 경계면)에 등록·버전 통제한다([RQ-06-11,12]).
   - WP 가 릴리스 시점까지 정확하게 유지되도록 추적 항목을 변경관리대장에 기록한다([RQ-06-09]).
4. **승인·전파**
   - CSM 승인 후 갱신 사실을 이해관계자에게 전파한다.

### 5.3 완료 조건
- [ ] 변경 트리거 식별·영향 평가 완료
- [ ] 계획 버전 증분 + 변경 내용 반영
- [ ] 계획·WP 형상관리 등록·버전 통제
- [ ] 변경관리대장에 이력 기록
- [ ] CSM 승인 + 이해관계자 전파

## 6. 인터페이스 부서
- **형상관리(QMS)**: 형상·변경·문서 관리 통제 (§5.4.4 경계면 — 참조)
- **PMO**: 일정 변경 정합
- **TARA 분석가**: TARA 갱신 트리거 통보

## 7. 주의사항 / 예외 처리

### 7.1 미갱신 계획(변경 후 방치)
- 변경 발생 후 계획이 갱신되지 않은 경우:
  - KPI(미갱신 계획 0건) 위반으로 월간 점검에서 적발.
  - 5영업일 내 갱신을 강제하고 미준수 시 CSM 에스컬레이션.

### 7.2 형상 외부 변경(통제 우회)
- 형상관리를 거치지 않은 비공식 변경이 발견된 경우:
  - 해당 변경을 무효 처리하고 정식 변경 절차로 재진입.
  - WP 무결성 재확인.

### 7.3 릴리스 임박 변경
- 릴리스 직전 중대 변경이 식별된 경우:
  - 릴리스 게이트(PRO-02-02)를 보류하고 케이스·평가 영향 재검토.
  - 영향 없음을 논증하지 못하면 릴리스 연기.

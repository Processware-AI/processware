# 테스트 커버리지 평가 및 취약점 테스트 (WI-VCSMS-02-05-06)

> 상위 절차: [[PRO-VCSMS-02-05_제품개발_사이버보안_엔지니어링_절차]] · 상위 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
테스트를 채택한 경우 정의된 커버리지 지표로 테스트 충분성을 평가하고, 잔존 약점·취약점 최소화를 확인하는 취약점 테스트를 수행하며, 미수행 시 그 근거를 제시하여 제품개발 단계의 검증 완전성을 확보한다.

## 2. 수행 주체
- **주 수행자**: 검증 엔지니어
- **검토자**: 보안 설계자
- **승인자**: Cybersecurity Manager (CSM) (검증 엔지니어가 활동 R/A)

## 3. 범위
ISO/SAE 21434 §10.4.2([RQ-10-11], [RC-10-12], [RQ-10-13])에 적용한다. 본 지침은 커버리지 평가와 취약점(침투) 테스트, 미수행 근거 제시를 다룬다. 결과는 케이스([[PRO-VCSMS-02-02_사이버보안_케이스_평가_및_릴리스_절차]])·차량 수준 검증([[PRO-VCSMS-02-06_차량_수준_사이버보안_검증_절차]])으로 전달한다.

## 4. 입력 자료 / 산출물
- **Input**
  - [[TMP-VCSMS-02-05-05-01_통합_검증_활동_명세_및_보고서]] (통합·검증 결과, WP-10-07)
  - [[TMP-VCSMS-02-05-03-01_아키텍처_약점_분석서]] (테스트 검증 대상 약점)
  - 조직 커버리지 지표 정의(요구/구조/시나리오 커버리지 등)
- **Output**
  - [[TMP-VCSMS-02-05-06-01_테스트_커버리지_및_취약점_테스트_결과서]] 작성분

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 통합·검증 활동이 승인(WI-05-05 done) 상태인지 확인한다(entry_gate).
2. 적용 커버리지 지표와 목표값, 테스트 검증 대상 약점(WK-##)을 정리한다.
3. 결과서 양식([[TMP-VCSMS-02-05-06-01_테스트_커버리지_및_취약점_테스트_결과서]])을 발번한다.

### 5.2 수행 단계
1. **커버리지 평가** ([RQ-10-11])
   - 테스트를 채택한 경우, 정의 커버리지 지표로 달성도를 측정하고 목표 충족 여부를 평가한다.
   - 미달 시 추가 테스트 또는 미달 근거를 결정한다.
2. **취약점 테스트 수행** ([RC-10-12], 권고)
   - 잔존 약점·취약점 최소화를 확인하는 테스트(퍼징·침투·약점 회귀)를 수행한다.
   - WI-05-03 의 테스트 검증 대상 약점(WK-##)을 테스트 케이스로 포함한다.
3. **취약점 테스트 미수행 근거** ([RQ-10-13])
   - 취약점 테스트를 미수행하는 경우, 그 근거(리스크 낮음·상위 검증 대체 등)를 제시·기록한다(권고 미수행 시 의무 근거).
4. **결과 종합·잔존 처리**
   - 발견 취약점·미달 항목을 기록하고, 처리(재작업·릴리스 조건·운영 모니터링 이관) 방향을 연결한다.
5. **검토·승인**
   - 보안 설계자 검토를 반영하고 CSM 승인을 받는다.

### 5.3 완료 조건
- [ ] entry_gate(WI-05-05 done) 충족 확인
- [ ] (테스트 채택 시)커버리지 지표 달성도 평가([RQ-10-11])
- [ ] 취약점 테스트 수행 또는 미수행 근거 제시([RC-10-12]/[RQ-10-13])
- [ ] WK-## 테스트 검증 대상 약점 테스트 케이스 포함
- [ ] 발견 취약점·미달 항목 처리 방향 연결
- [ ] CSM 승인 기록 확보

## 7. 주의사항 / 예외 처리

### 7.1 커버리지 목표 미달
- 커버리지 목표 미달 시, 추가 테스트로 보완하거나 미달이 불가피하면 미달 근거·잔여 리스크를 명시하고 CSM 수용을 받는다.

### 7.2 취약점 테스트 미수행([RQ-10-13])
- [RC-10-12] 취약점 테스트를 미수행하면, "수행하지 않음"으로 비워두지 말고 미수행 근거를 반드시 제시한다(미근거 누락은 부적합).

### 7.3 신규 취약점 발견(중대)
- 중대 취약점 발견 시, 릴리스를 보류하고 약점 분석(WI-05-03)·사양(WI-05-01) 재작업 또는 사고대응([[PRO-VCSMS-01-04_사이버보안_사고_대응_절차]]) 연계 여부를 CSM 이 결정한다.

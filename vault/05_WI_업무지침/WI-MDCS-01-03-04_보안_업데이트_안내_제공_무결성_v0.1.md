# 보안 업데이트 안내·제공·무결성 검증 (WI-MDCS-01-03-04)

> 상위 절차: [[PRO-MDCS-01-03_보안_SW_유지보수_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
검증을 통과한 보안 업데이트를 MAINTAINED SW 에는 무결성 검증이 가능한 방식으로 제공하고, SUPPORTED SW 에는 호환성·대체 완화책을 안내하며, 사용자에게 적시 통보하여, 업데이트가 안전하게 적용되도록 한다. (6.3.1, 6.3.2, 6.3.3)

## 2. 수행 주체
- **주 수행자**: 보안 운영
- **검토자**: 보안책임자(PSO)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-01-03 §5 단계4(안내·제공)에 적용한다. **선행조건**: WI-MDCS-01-03-03(검증) 완료. 각 검증 합격 업데이트에 적용한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 검증 합격 업데이트(WI-MDCS-01-03-03)
  - SW 분류(MAINTAINED/SUPPORTED)
  - 업데이트 정책 SLA(WI-MDCS-01-03-01)
- **Output**
  - [[TMP-MDCS-01-03-04-01_보안_업데이트_제공_및_안내기록_v0.1]] 작성분
  - 배포 증적(무결성 검증 수단 포함)
  - 사용자 안내·통보 기록

## 5. 수행 절차

### 5.1 사전 준비
1. 업데이트 검증 합격 여부와 SW 분류를 확인한다.
2. 배포 채널·무결성 검증 수단(해시·서명)을 준비한다.

### 5.2 수행 단계
1. **MAINTAINED 제공**
   - 무결성 검증이 가능한 방식(서명·해시 공개)으로 업데이트를 배포한다.
2. **SUPPORTED 안내**
   - 직접 패치가 불가한 SUPPORTED SW 는 호환성 정보·대체 완화책을 안내한다.
3. **사용자 통보**
   - 영향·적용 방법·기한을 사용자에게 통보하고 통보 증적을 남긴다.
4. **무결성 확인 지원**
   - 사용자가 무결성을 검증할 수 있도록 검증값·방법을 제공한다.
5. **검토·기록**
   - PSO 가 제공·안내의 SLA 준수·무결성 적용을 검토하고 기록을 보존한다.

### 5.3 완료 조건
- [ ] MAINTAINED 업데이트가 무결성 검증 가능 방식으로 배포됨
- [ ] SUPPORTED SW 호환성·대체 완화책 안내 완료
- [ ] 사용자 통보(영향·방법·기한) 및 증적 보유
- [ ] 무결성 검증값·방법 제공
- [ ] 정책 SLA 준수
- [ ] PSO 검토·배포 기록 보존

## 6. 인터페이스 부서
- **WI-MDCS-01-03-03(검증)**: 검증 합격 업데이트 수령
- **고객지원/CS**: 사용자 안내·통보 채널
- **DevOps/배포**: 서명·해시 적용 배포

## 7. 주의사항 / 예외 처리

### 7.1 무결성 수단 미적용 배포 금지
- 무결성 검증 수단(서명/해시) 없이 MAINTAINED 업데이트를 배포하지 않는다. 수단 미비 시 배포를 보류하고 보완한다.

### 7.2 배포 실패·롤백
- 배포 후 문제가 발견되면 롤백 절차를 수행하고, 원인을 PRO-MDCS-01-05 로 처리하며 재배포 전 재검증한다.

### 7.3 SUPPORTED 사용자 미적용 위험
- SUPPORTED SW 안내에도 사용자가 완화책을 적용하지 않을 위험은 잔여 리스크로 PRO-MDCS-02-01 에 반영하고 동반문서에 명시한다.

### 7.4 통보 도달 실패
- 사용자 통보가 도달하지 못하면 대체 채널을 사용하고, 안전 영향이 큰 경우 PRO-MDCS-01-05(공개)와 연계한다.

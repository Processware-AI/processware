# 취약점 접수 채널 및 출처별 접수·종결 추적 (WI-MDCS-01-05-01)

> 상위 절차: [[PRO-MDCS-01-05_보안_문제해결_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
헬스SW 취약점을 내부·외부·고객 불만·연구자(ISO/IEC 29147)·광범위 출처 등 다양한 경로로 빠짐없이 접수하는 채널을 운영하고, 접수부터 종결까지 추적하여 누락 없이 처리되도록 한다. (9.2)

## 2. 수행 주체
- **주 수행자**: 취약점 분류자(triage)
- **검토자**: 보안책임자(PSO)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-01-05 §5 단계1(접수)에 적용한다. 상시 운영하며, 출처를 불문하고 모든 보안 취약점 보고를 접수한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 취약점 보고(내부·외부·고객·연구자·모니터링 연계)
  - 협력적 공개 채널 정책(ISO/IEC 29147 참조)
- **Output**
  - [[TMP-MDCS-01-05-01-01_취약점_접수_및_추적대장_v0.1]] 작성분
  - 접수 기록(출처·일시·고유 ID)
  - 종결 추적 상태

## 5. 수행 절차

### 5.1 사전 준비
1. 다채널 접수 경로(보안 메일·웹 폼·연구자 채널·CS 연계)를 운영 상태로 유지한다.
2. ISO/IEC 29147(협력적 취약점 공개) 접수 정책을 확인한다.

### 5.2 수행 단계
1. **접수**
   - 취약점 보고를 접수하고 고유 ID·출처·접수 일시를 기록한다.
2. **초기 분류(중복·범위)**
   - 중복 여부·제품 범위 해당 여부를 1차 분류한다.
3. **조사 연계**
   - 유효 보고를 조사(WI-MDCS-01-05-02)로 연계하고 SLA 시계를 시작한다.
4. **종결 추적**
   - 각 접수 건을 종결까지 상태(접수→조사→분석→처리→공개→종결) 추적한다.
5. **검토·기록**
   - PSO 가 접수 누락·SLA 준수를 검토하고 대장을 보존한다.

### 5.3 완료 조건
- [ ] 모든 출처의 접수 채널이 운영됨
- [ ] 각 보고에 고유 ID·출처·접수 일시 기록
- [ ] 중복·범위 1차 분류 수행
- [ ] 유효 보고가 조사로 연계됨
- [ ] 접수~종결 상태 추적(미추적 0건)
- [ ] PSO 검토·대장 보존

## 6. 인터페이스 부서
- **고객지원/CS**: 고객 불만 연계
- **PRO-MDCS-01-03(유지보수)**: 모니터링 발견 연계
- **WI-MDCS-01-05-02(조사)**: 유효 보고 연계
- **연구자/외부**: 협력적 공개 접수

## 7. 주의사항 / 예외 처리

### 7.1 접수 채널 장애
- 접수 채널 장애 시 대체 채널을 안내하고, 장애 기간 접수 누락이 없도록 사후 일괄 확인한다.

### 7.2 중복·무효 보고
- 중복·무효(제품 무관) 보고는 사유를 기록하고 종결하되, 보고자에게 회신한다(협력적 공개 원칙).

### 7.3 연구자 협력 공개
- 연구자 보고는 ISO/IEC 29147 원칙에 따라 응대·공개 일정을 협의하고, 비공개 합의 기간을 준수한다.

### 7.4 대량·캠페인성 보고
- 동일 취약점의 대량 보고는 대표 건으로 묶어 추적하되, 모든 보고자에게 처리 상태를 안내한다.

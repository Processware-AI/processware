# 보안 개발 계획 및 환경·코딩표준 수립 (WI-MDCS-01-02-01)

> 상위 절차: [[PRO-MDCS-01-02_보안_SW_개발_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
헬스SW 개발 프로젝트의 착수 단계에서 보안 수명주기 활동을 개발 계획에 통합하고, 개발 환경의 보안 통제와 보안 코딩 표준을 수립하며, 표준 요구를 미적용(테일러링)하는 경우 정당성을 문서화하여, 이후 개발 전 단계의 보안 기준선을 확립한다. (5.1.1, 5.1.2, 5.1.3)

## 2. 수행 주체
- **주 수행자**: 보안책임자(PSO) / 개발 리드
- **검토자**: 보안운영위원회(PSGB)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-01-02 §5 단계1(계획)에 적용한다. 프로젝트 착수 시 수립하고 주요 범위·기술 변경 시 갱신한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 제품 요구·프로젝트 범위
  - SW 분류표(WI-MDCS-01-01-01)
  - 조직 표준 코딩 가이드·개발 인프라 정보
- **Output**
  - [[TMP-MDCS-01-02-01-01_보안개발계획서_환경통제_코딩표준_v0.1]] 작성분
  - 보안 활동이 통합된 개발 계획
  - 개발 환경 보안 통제 정의
  - 보안 코딩 표준 + 테일러링 정당화(해당 시)

## 5. 수행 절차

### 5.1 사전 준비
1. 제품 요구·범위와 SW 분류를 확인한다.
2. 적용할 보안 수명주기 활동 목록을 정리한다(개발·시험·릴리스 단계별).
3. 현 개발 환경(저장소·CI/CD·접근 통제) 현황을 파악한다.

### 5.2 수행 단계
1. **보안 활동 통합 계획**
   - 각 개발 단계에 수행할 보안 활동·산출물·검토 게이트를 개발 계획에 통합한다.
   - 활동별 담당·일정·완료 기준을 정의한다.
2. **개발 환경 보안 통제**
   - 소스 저장소 접근 통제·빌드 무결성·비밀정보 관리·아티팩트 보호 통제를 정의한다.
3. **보안 코딩 표준 수립**
   - 사용 언어·플랫폼에 맞는 보안 코딩 규칙을 채택·정의한다(입력 검증·메모리·암호 사용 등).
4. **테일러링 정당화**
   - 표준 요구 중 미적용 항목이 있으면 보안 전문성을 갖춘 인력의 검토·승인을 거쳐 정당성을 문서화한다.
5. **검토·승인**
   - PSGB 검토 후 PSO 가 계획·통제·표준·테일러링을 승인한다.

### 5.3 완료 조건
- [ ] 모든 개발 단계에 보안 활동·검토 게이트가 계획에 반영됨
- [ ] 개발 환경 보안 통제(접근·빌드·비밀정보)가 정의됨
- [ ] 보안 코딩 표준이 사용 기술에 맞게 채택됨
- [ ] 테일러링 항목이 있으면 보안 전문가 검토·승인·정당화 문서화
- [ ] PSGB 검토·PSO 승인 기록 존재

## 6. 인터페이스 부서
- **DevOps/인프라**: 저장소·CI/CD 보안 통제 구현
- **PRO-MDCS-01-04(형상관리)**: 변경통제·기준선 연계
- **개발팀**: 코딩 표준 채택·준수

## 7. 주의사항 / 예외 처리

### 7.1 테일러링 남용 방지
- 테일러링은 예외이며 일괄·관행적 생략은 금지한다. 각 미적용 항목은 개별 사유·보완 통제·잔여 리스크를 명시하고 보안 전문가가 승인한다.

### 7.2 환경 통제 미비
- 개발 환경에 필수 보안 통제(예: 비밀정보 평문 저장 금지)가 없으면 개발 착수 전 보완하고, 불가피할 경우 보완 일정·임시 통제를 계획에 기록한다.

### 7.3 코딩 표준 부재 언어
- 조직 표준에 없는 신규 언어·프레임워크 도입 시 해당 보안 코딩 규칙을 신규 정의한 후 사용을 승인한다.

### 7.4 계획 중대 변경
- 아키텍처·기술 스택의 중대 변경 시 본 계획을 갱신하고 영향받는 후속 단계(아키텍처·설계·시험)를 재계획한다.

# 사이버보안 정책·규칙·프로세스 수립 (WI-VCSMS-01-01-01)

> 상위 절차: [[PRO-VCSMS-01-01_조직_사이버보안_거버넌스_운영_절차]] · 상위 정책: [[POL-VCSMS-01_자동차_사이버보안_거버넌스_정책]]

## 1. 업무 목적
차량 E/E 사이버보안 리스크에 대한 조직의 인지와 경영진의 관리 의지를 담은 **사이버보안 정책**을 정의하고, ISO/SAE 21434 요구 이행과 사이버보안 활동 수행을 가능케 하는 **규칙·프로세스**를 수립·유지한다. 지속적 개선 메커니즘을 함께 도입하여 정책·규칙이 운영 피드백으로 갱신되도록 한다.

## 2. 수행 주체
- **주 수행자**: Cybersecurity Manager (CSM)
- **검토자**: Process Control Board (PCB)
- **승인자**: 경영진 (Top Management) — 정책의 최종 승인 권한

## 3. 범위
PRO-VCSMS-01-01 §5 단계 1·2·9 에 적용한다. 정책 정의(§5.4.1 [RQ-05-01]), 규칙·프로세스 수립·유지([RQ-05-02]), 지속적 개선([RQ-05-08])을 다룬다. 책임·자원 배정은 [[WI-VCSMS-01-01-02_책임_권한_배정_및_자원_제공]], 정보공유 규칙은 [[WI-VCSMS-01-01-04_정보공유_조건_정의_및_소통채널_운영]] 로 분리한다. 변경·문서·형상 관리는 상위 QMS(§5.4.4) 를 참조하며 본 지침에서 중복 생성하지 않는다.

## 4. 입력 자료 / 산출물
- **Input**
  - ISO/SAE 21434 §5.4.1 요건 (VCSMS-R-001·002·008)
  - 조직 컨텍스트(사업영역·E/E 제품군·규제 환경: UNECE R155 등)
  - 식별된 차량 사이버보안 리스크 인지 자료
  - 운영 피드백(감사 결과·사고·취약점 처리 결과 등 — 개선 트리거 시)
- **Output**
  - 승인된 사이버보안 정책 (WP-05-01)
  - 규칙·프로세스 문서 세트 (WP-05-01)
  - [[TMP-VCSMS-01-01-01-01_사이버보안_정책_규칙_등록부]] 작성분
  - 지속적 개선 절차 기록(개선 트리거·조치·완료)

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. ISO/SAE 21434 §5.4.1 [RQ-05-01·02·08] 요건 텍스트를 적용요건 매트릭스에서 추출하여 정책에 반영할 항목 목록 작성.
2. 조직의 E/E 제품군·규제 적용 범위(R155/R156 해당 여부)와 인접 표준(ISO 26262 기능안전, ISMS) 경계면 식별.
3. 기존 정책·규칙(이전 버전 또는 상위 QMS 정책)이 있으면 현행 승인판을 백업: `vault/99_폐기_보관/{원본}_v{현재}_archived_{YYYYMMDD}.md`.

### 5.2 수행 단계
1. **정책 초안 작성**
   - 정책에 다음을 반드시 포함: (a) 차량 사이버보안 리스크 인지 선언, (b) 경영진의 관리 의지·우선순위 천명, (c) 적용 범위(item/component·수명주기 단계), (d) 정책 검토 주기(연 1회 이상).
   - 경영진 친화 어휘로 1~2 페이지 분량 작성(과도한 기술 상세 지양).
2. **규칙·프로세스 정의**
   - 정책을 실행 가능케 하는 규칙·프로세스를 식별: 거버넌스 운영(본 PRO), 감사(PRO-01-02), 지속활동(PRO-01-03), 사고대응(PRO-01-04), 프로젝트 관리(POL-02 계열)로의 진입 규칙.
   - 각 규칙을 [[TMP-VCSMS-01-01-01-01_사이버보안_정책_규칙_등록부]] 에 1행씩 등록(규칙 ID·근거 조항·소유 프로세스·검토 주기).
3. **지속적 개선 메커니즘 정의** ([RQ-05-08])
   - 개선 트리거 정의: 감사 부적합, 사고 발생, 취약점 처리 결과, 표준 개정, KPI 미달.
   - 트리거 발생 시 정책·규칙 갱신 경로를 등록부에 명시(에스컬레이션 → PCB → 경영진).
4. **PCB 검토**
   - PCB 가 정책·규칙의 완전성(§5.4.1 요건 커버), 인접 분야 정합성, 측정 가능성(KPI 연계)을 검토하고 코멘트 반영.
5. **경영진 승인**
   - 경영진에게 정책·규칙 등록부를 승인 요청(전자결재 또는 경영검토 회의록).
   - 승인 후 정책 frontmatter `status: approved`, `version` v1.0 처리.
6. **배포·등록**
   - 승인된 정책·규칙을 전사 공지채널에 게시.
   - [[MAT-001_문서관리대장]] 에 신규 Row 등록(version·updated·status).

### 5.3 완료 조건
- [ ] 정책에 리스크 인지·경영 의지·범위·검토 주기 4요소 포함 확인
- [ ] 규칙·프로세스가 거버넌스/감사/지속활동/사고대응/프로젝트 전 영역을 커버
- [ ] 지속적 개선 트리거 5종 이상 정의 및 갱신 경로 등록
- [ ] PCB 검토 코멘트 반영 완료
- [ ] 경영진 승인 기록 확보(전자결재 또는 회의록)
- [ ] 정책·규칙 등록부([[TMP-VCSMS-01-01-01-01_사이버보안_정책_규칙_등록부]]) 작성·배포·MAT-001 등록 완료

## 6. 인터페이스 부서
- **경영진**: 정책 승인·관리 의지 천명
- **QMS 부서(§5.4.4)**: 정책·규칙 문서의 형상·변경 관리 경계면
- **ISMS 부서(§5.4.6)**: 정책 산출물의 정보보안 관리 경계면
- **각 프로세스 소유 부서**: 규칙 수신·이행

## 7. 주의사항 / 예외 처리

### 7.1 표준·규제 개정에 따른 긴급 정책 갱신
- UNECE R155/R156 또는 ISO/SAE 21434 개정으로 즉시 반영이 필요한 경우:
  - CSM 이 변경 영향 요약 → 경영진 구두 승인 → 선반영.
  - 30일 이내 PCB 정식 검토·문서화로 보완.

### 7.2 규칙 충돌 (상위 QMS 와 중복·상충)
- 신규 규칙이 상위 QMS 규칙과 중복·상충 시:
  - QMS 를 정본(master)으로 두고 본 영역은 "참조" 링크로 처리(중복 생성 금지, interface_only 원칙).
  - 상충 항목은 PCB 에 회부하여 우선순위 결정.

### 7.3 정책 검토 주기 미준수
- 정의된 검토 주기(연 1회) 내 검토가 누락된 경우:
  - 즉시 임시 검토를 트리거하고 미준수 사유를 개선 기록에 등록.
  - 반복 미준수 시 경영검토 안건으로 상정.

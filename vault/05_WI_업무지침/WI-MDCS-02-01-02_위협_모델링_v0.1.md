# 위협 모델링(취약점·위협 식별, 위협모델 작성·검토) (WI-MDCS-02-01-02)

> 상위 절차: [[PRO-MDCS-02-01_보안_리스크_관리_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-02_보안_리스크_관리_방침_v0.1]]

## 1. 업무 목적
보안 맥락을 기반으로 자산의 기밀성·무결성·가용성(CIA)에 영향을 주는 취약점·위협을 식별하고, 데이터 흐름·신뢰경계·공격 벡터를 반영한 범위 특화 위협 모델을 작성·검토하여, 리스크 평가·통제의 입력을 제공한다. (7.2, 4.2)

## 2. 수행 주체
- **주 수행자**: 위협 모델링 리드 / 개발팀
- **검토자**: 개발팀(검토·검증)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-02-01 §5 단계2(위협 모델링)에 적용한다. **선행조건**: WI-MDCS-02-01-01(보안 맥락) 완료. 최소 연 1회 및 신규 위협 시 갱신한다(WI-MDCS-02-01-05 연계).

## 4. 입력 자료 / 산출물
- **Input**
  - 보안 맥락 문서(WI-MDCS-02-01-01)
  - 아키텍처·데이터 흐름·신뢰경계 정보
  - 자산 목록·기존 위협 인텔리전스
- **Output**
  - [[TMP-MDCS-02-01-02-01_위협모델_및_검토기록_v0.1]] 작성분
  - 위협 모델(자산·위협·공격 벡터·신뢰경계)
  - 개발팀 검토 기록

## 5. 수행 절차

### 5.1 사전 준비
1. 보안 맥락·아키텍처·데이터 흐름을 확보한다.
2. 자산(데이터·기능·키)과 CIA 중요도를 정리한다.

### 5.2 수행 단계
1. **자산·데이터 흐름 식별**
   - 보호 대상 자산과 데이터 흐름·신뢰경계를 도식화한다.
2. **위협 식별**
   - 각 자산·경계에 대한 위협을 식별한다(STRIDE 등 체계 활용, CIA 영향 기준).
3. **공격 벡터 분석**
   - 위협별 공격 벡터·진입점을 분석한다.
4. **위협 모델 작성**
   - 자산·위협·벡터·신뢰경계를 위협 모델로 문서화한다.
5. **개발팀 검토**
   - 개발팀이 위협 모델의 완전성·타당성을 검토·검증하고, 도출된 이슈는 9.4/9.5(문제해결)로 처리한다.
6. **검토·승인**
   - PSO 가 위협 모델을 승인하고 리스크 평가(WI-MDCS-02-01-03)로 연계한다.

### 5.3 완료 조건
- [ ] 보호 자산·데이터 흐름·신뢰경계 식별
- [ ] 자산별 위협 식별(CIA 영향 기준)
- [ ] 위협별 공격 벡터 분석
- [ ] 위협 모델 문서화(범위 특화)
- [ ] 개발팀 검토·검증 기록 존재
- [ ] PSO 승인·리스크 평가 연계

## 6. 인터페이스 부서
- **WI-MDCS-02-01-01(보안 맥락)**: 맥락 입력
- **WI-MDCS-02-01-03(리스크 추정)**: 위협 모델 연계
- **PRO-MDCS-01-05(문제해결)**: 도출 이슈 처리
- **WI-MDCS-01-02-03/04(아키텍처·설계)**: 위협 완화 반영

## 7. 주의사항 / 예외 처리

### 7.1 위협 식별 누락 위험
- 체계(STRIDE 등) 없이 임의 식별하면 누락이 생기므로, 각 자산·경계에 체계적으로 위협을 매핑한다.

### 7.2 위협 모델 과대/과소
- 범위에 비해 과도하거나 부족한 위협 모델은 리스크 평가를 왜곡하므로, 제품 범위·맥락에 특화하여 적정 수준을 유지한다.

### 7.3 검토 중 이슈 발견
- 검토 중 실제 취약점이 발견되면 PRO-MDCS-01-05(문제해결)로 처리하고 위협 모델을 갱신한다.

### 7.4 신규 위협 인텔리전스
- 신규 공격 기법·위협 정보가 입수되면 위협 모델에 반영하고, 정기 검토(WI-MDCS-02-01-05)에서 재확인한다.

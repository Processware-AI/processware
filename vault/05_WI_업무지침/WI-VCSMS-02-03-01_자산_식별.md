# 자산 식별 (피해 시나리오·사이버보안 속성) (WI-VCSMS-02-03-01)

> 상위 절차: [[PRO-VCSMS-02-03_위협분석_및_리스크평가_TARA_절차]] · 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]
> **횡단 방법론** — 컨셉(§9.4)·취약점 관리(§8.6)에서 호출되는 TARA 1단계.

## 1. 업무 목적
아이템 정의를 기반으로 피해(damage) 시나리오를 식별하고, 손상(compromise) 시 그 피해로 이어지는 사이버보안 속성(기밀성·무결성·가용성 등)을 갖는 자산을 식별하여, 이후 위협 시나리오·영향 평가의 기준선을 만든다. (§15.3 [RQ-15-01,02])

## 2. 수행 주체
- **주 수행자**: TARA 분석가
- **검토자**: 보안 설계자 / 안전 담당
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
본 지침은 PRO-VCSMS-02-03 §5 단계 1(자산 식별)에 적용한다. 컨셉 단계(§9.4 [RQ-09-03])와 취약점 관리(§8.6)에서 호출되는 재사용 가능한 1단계다. 산출물은 WI-VCSMS-02-03-02(위협 시나리오)·WI-VCSMS-02-03-03(영향 평가)의 입력이 된다.

## 4. 입력 자료 / 산출물
- **Input**
  - 아이템 정의 (경계·기능·예비 아키텍처, WP-09-01)
  - 사이버보안 관련 운용환경 정보
- **Output**
  - [[TMP-VCSMS-02-03-01-01_자산_및_피해시나리오_목록]] 작성분 (WP-15-01 피해 시나리오, WP-15-02 자산)

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 아이템 정의(경계·기능·인터페이스)와 운용환경 정보를 수집한다.
2. 자산 식별 관점(데이터·기능·통신·키·로그 등)을 정한다.

### 5.2 수행 단계
1. **자산 식별**
   - 아이템의 기능·데이터·인터페이스에서 사이버보안 속성을 갖는 자산을 식별한다([RQ-15-02]).
   - 각 자산의 사이버보안 속성(기밀성/무결성/가용성/진위성 등)을 명시한다.
2. **피해 시나리오 식별**
   - 자산의 속성 손상이 차량·승객·운영·프라이버시에 미치는 피해 시나리오를 식별한다([RQ-15-01]).
   - 피해 시나리오를 자산-속성 손상과 연결한다.
3. **검토·승인**
   - 보안 설계자·안전 담당이 누락 자산·피해를 점검하고 CSM 이 승인한다.

### 5.3 완료 조건
- [ ] 아이템의 사이버보안 속성 자산 전수 식별
- [ ] 각 자산의 사이버보안 속성 명시
- [ ] 자산-속성 손상에 대응하는 피해 시나리오 식별
- [ ] 누락 점검(보안·안전 관점)
- [ ] CSM 승인

## 6. 인터페이스 부서
- **E/E 설계팀**: 아이템 정의·아키텍처 제공
- **안전 담당(ISO 26262)**: 안전 관련 피해 시나리오 연계 (§15.5 영향 평가 입력)
- **품질(QMS)**: 산출물 형상·문서 관리 (§5.4.4 경계면)

## 7. 주의사항 / 예외 처리

### 7.1 아이템 정의 미확정
- 아이템 정의가 미확정이라 자산을 특정할 수 없는 경우:
  - 예비 아키텍처 기반으로 잠정 자산을 식별하고 "잠정" 표기.
  - 아이템 정의 확정 후 재식별(TARA 갱신).

### 7.2 자산 누락 발견 (후속 단계)
- 위협 시나리오·공격 경로 분석 중 누락 자산이 발견된 경우:
  - 본 단계로 회귀하여 자산·피해 시나리오를 보완하고 후속 단계를 재수행.

### 7.3 안전-보안 경계 자산
- 자산이 안전(ISO 26262)과 중첩되는 경우:
  - 안전 담당과 공동 식별하고 영향 평가(§15.5)에서 안전 영향등급을 ISO 26262-3 §6.4.3 으로 도출하도록 표기.

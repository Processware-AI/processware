# 보안 변경통제 및 변경이력 관리 (WI-MDCS-01-04-01)

> 상위 절차: [[PRO-MDCS-01-04_보안_형상관리_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
헬스SW 의 형상 항목 변경을 통제된 절차(요청·보안 영향 심의·승인·반영·이력 기록)로 관리하여, 무단·미검토 변경으로 인한 보안 약화를 방지하고 변경 이력의 추적성을 확보한다. (8-REQ-001)

## 2. 수행 주체
- **주 수행자**: 형상관리 담당
- **검토자**: 변경통제위원회(CCB)
- **승인자**: 변경통제위원회(CCB)

## 3. 범위
PRO-MDCS-01-04 §5 단계1(변경통제)에 적용한다. 보안 수명주기가 적용되는 형상 항목의 모든 변경에 적용한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 변경 요청(기능·버그·보안 패치·외부 컴포넌트)
  - 형상 항목 기준선·변경 영향 정보
  - 보안 리스크·위협 모델(영향 심의용)
- **Output**
  - [[TMP-MDCS-01-04-01-01_보안_변경통제_요청_및_이력대장_v0.1]] 작성분
  - 변경통제 기록(심의·승인/반려)
  - 변경 이력(누가·언제·무엇을·왜)

## 5. 수행 절차

### 5.1 사전 준비
1. 변경 대상 형상 항목과 기준선을 확인한다.
2. 변경 요청의 목적·범위를 정리한다.

### 5.2 수행 단계
1. **변경 요청 접수**
   - 변경 요청을 접수하고 고유 ID 를 부여한다.
2. **보안 영향 심의**
   - 변경이 보안(위협 모델·통제·인터페이스)에 미치는 영향을 평가한다.
3. **승인/반려**
   - CCB 가 보안 영향 평가를 근거로 승인 또는 반려를 결정한다.
4. **변경 반영·이력 기록**
   - 승인된 변경을 반영하고 변경 이력(주체·일시·내용·사유)을 기록한다.
5. **연계**
   - 보안 영향이 큰 변경은 PRO-MDCS-02-01(리스크 재평가)·PRO-MDCS-01-02(재시험)로 연계한다.

### 5.3 완료 조건
- [ ] 모든 변경이 요청 ID 로 등록됨
- [ ] 각 변경에 보안 영향 심의 수행
- [ ] CCB 승인/반려 결정 기록
- [ ] 승인 변경 대비 변경 이력 기록률 100%
- [ ] 보안 영향 큰 변경의 리스크 재평가/재시험 연계

## 6. 인터페이스 부서
- **PRO-MDCS-02-01(리스크 관리)**: 변경 보안 영향 재평가
- **PRO-MDCS-01-02(개발)**: 변경 후 재시험
- **WI-MDCS-01-04-02(SBOM)**: 컴포넌트 변경 반영

## 7. 주의사항 / 예외 처리

### 7.1 무단 변경 발견
- 변경통제를 거치지 않은 변경이 발견되면 즉시 기준선과 대조하여 영향을 평가하고, PRO-MDCS-01-05 로 처리하며 사후 변경통제로 정식 등록한다.

### 7.2 긴급 변경(보안 핫픽스)
- 긴급 보안 변경은 사전 약식 승인으로 반영하되, 정해진 시한 내 정식 CCB 승인·이력 기록을 보완한다.

### 7.3 외부 컴포넌트 변경
- 외부 컴포넌트 버전 변경은 SBOM(WI-MDCS-01-04-02)·취약점 모니터링(PRO-MDCS-01-03)에 즉시 반영한다.

### 7.4 변경 이력 누락
- 변경 이력이 누락되면 형상 재현이 불가하므로, 누락 발견 시 가용 정보로 복원하고 누락 사유를 기록한다.

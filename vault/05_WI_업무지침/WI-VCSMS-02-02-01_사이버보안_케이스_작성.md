# 사이버보안 케이스 작성 (WI-VCSMS-02-02-01)

> 상위 절차: [[PRO-VCSMS-02-02_사이버보안_케이스_평가_및_릴리스_절차]] · 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
item/component 의 사이버보안이 적절히 달성되었음을 작업산출물(증적)로 뒷받침되는 구조화된 논거(argument)로 제시하여, 사이버보안 평가·릴리스의 근거가 되는 사이버보안 케이스(WP-06-02)를 작성한다. (§6.4.7 [RQ-06-23])

## 2. 수행 주체
- **주 수행자**: Project CS Lead
- **검토자**: TARA 분석가 / 보안 설계자 / 검증 담당
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
본 지침은 PRO-VCSMS-02-02 §5 단계 1(케이스 작성)에 적용한다. 케이스는 컨셉·개발·검증(Clause 9·10·11·15)의 작업산출물을 증적으로 인용한다. 평가 수행 여부 결정은 WI-VCSMS-02-02-02 로 이어진다.

## 4. 입력 자료 / 산출물
- **Input**
  - 사이버보안 목표·클레임 (WP-09-03,04)
  - TARA 산출물 (WP-15-01~08, 특히 리스크 처리 결정)
  - 설계·구현·검증 작업산출물 (WP-10, WP-11)
- **Output**
  - [[TMP-VCSMS-02-02-01-01_사이버보안_케이스]] 작성분 (WP-06-02, 논거+증적 인덱스)

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 대상 item/component 의 사이버보안 목표·클레임·리스크 처리 결정을 수집한다.
2. 증적이 될 작업산출물(WP) 목록과 현 버전을 확인한다.

### 5.2 수행 단계
1. **논거 구조 정의**
   - 최상위 주장(item 의 사이버보안 달성)을 사이버보안 목표·클레임으로 분해한다.
   - 각 목표/클레임을 뒷받침하는 하위 논거를 구조화한다(예: 목표 → 통제 → 검증 결과).
2. **증적 인용**
   - 각 논거에 증적 WP(설계·검증·TARA 처리 결정)를 식별자·버전과 함께 인용한다([RQ-06-23]).
3. **잔여 리스크·예외 명시**
   - 보유(retain)·공유(share)로 처리된 리스크와 미해결 사항(open issue)을 케이스에 명시한다.
4. **완전성 점검·승인**
   - 모든 목표/클레임이 증적으로 닫혔는지 점검하고 CSM 이 케이스를 승인한다.

### 5.3 완료 조건
- [ ] 최상위 주장이 목표/클레임으로 분해됨
- [ ] 각 논거에 증적 WP 가 식별자·버전과 함께 인용됨
- [ ] 보유·공유 리스크 및 open issue 명시
- [ ] 목표/클레임 증적 닫힘(완전성) 점검
- [ ] CSM 승인

## 6. 인터페이스 부서
- **검증팀**: 검증 보고서(WP-11) 증적 제공
- **TARA 분석가**: 리스크 처리 결정 증적
- **품질(QMS)**: 케이스 형상·문서 관리 (§5.4.4 경계면)

## 7. 주의사항 / 예외 처리

### 7.1 증적 미완(논거 미닫힘)
- 일부 목표/클레임의 증적이 아직 미완인 경우:
  - 해당 논거를 "open"으로 표기하고 닫힘 계획·기한을 명시.
  - open 논거가 있으면 릴리스 게이트(WI-05)는 통과 불가.

### 7.2 증적 버전 불일치
- 인용된 WP 버전이 최신 형상과 다른 경우:
  - 최신 버전으로 갱신 인용하고 변경이 논거에 미치는 영향을 재평가.

### 7.3 보유 리스크 과다
- 보유(retain) 리스크가 과다하거나 정당화가 약한 경우:
  - 리스크 처리 결정(PRO-02-03 WI-07) 재검토를 요청.
  - 정당화 보강 전까지 케이스 승인 보류.

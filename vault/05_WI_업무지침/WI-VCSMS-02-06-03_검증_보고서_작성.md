# 검증 보고서 작성 (WI-VCSMS-02-06-03)

> 상위 절차: [[PRO-VCSMS-02-06_차량_수준_사이버보안_검증_절차]] · 상위 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
차량 수준 검증 수행 결과와 부적합을 종합하여 검증 보고서(WP-11-01)를 작성하고, 사이버보안 케이스([[PRO-VCSMS-02-02_사이버보안_케이스_평가_및_릴리스_절차]])의 검증 근거로 전달하여 릴리스 의사결정의 입력을 제공한다.

## 2. 수행 주체
- **주 수행자**: 검증 엔지니어
- **검토자**: Project CS Lead
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
ISO/SAE 21434 §11.4 산출물(WP-11-01)에 적용한다. 본 지침은 검증 수행 결과(WI-06-02)를 보고서로 종합·전달하는 활동을 다룬다.

## 4. 입력 자료 / 산출물
- **Input**
  - [[TMP-VCSMS-02-06-02-01_차량_수준_검증_수행기록]] (승인된 수행 결과)
  - [[TMP-VCSMS-02-06-01-01_검증_활동_선정서]] (검증 계획·근거)
- **Output**
  - [[TMP-VCSMS-02-06-03-01_차량_수준_사이버보안_검증_보고서]] 작성분 (WP-11-01)
  - 케이스 전달 기록

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 검증 수행기록이 승인(WI-06-02 done) 상태인지 확인한다(entry_gate).
2. 수행기록·선정서·증적을 보고서 구조에 맞춰 정렬한다.
3. 검증 보고서 양식([[TMP-VCSMS-02-06-03-01_차량_수준_사이버보안_검증_보고서]])을 발번한다.

### 5.2 수행 단계
1. **검증 개요·범위 기술**
   - 검증 대상·활동·환경·기간을 요약한다.
2. **검증 결과 종합**
   - 목표 적정성·달성, 클레임·운용환경 요구 유효성 결과를 종합 기술하고 증적을 참조 연결한다.
3. **부적합·잔여 리스크 기술**
   - 부적합 항목, 처리 방향(컨셉회귀·개발재작업·잔여리스크), 종결 상태를 기술한다.
4. **종합 판정·권고**
   - 차량 수준 사이버보안 유효성에 대한 종합 판정과 케이스 입력 권고(수용/조건부/거부)를 기술한다.
5. **케이스 전달**
   - 보고서를 케이스([[PRO-VCSMS-02-02_사이버보안_케이스_평가_및_릴리스_절차]])로 전달하고 전달 기록을 남긴다.
6. **검토·승인**
   - Project CS Lead 검토를 반영하고 CSM 승인을 받는다.

### 5.3 완료 조건
- [ ] entry_gate(WI-06-02 done) 충족 확인
- [ ] 검증 개요·범위 기술 완료
- [ ] 결과 종합(적정성·달성·클레임·환경) 및 증적 참조
- [ ] 부적합·잔여 리스크·종결 상태 기술
- [ ] 종합 판정·케이스 입력 권고 명시
- [ ] 케이스 전달 기록 확보
- [ ] CSM 승인 기록 확보

## 6. 인터페이스 부서
- **케이스 담당(Project CS Lead)**: 보고서를 케이스 논거로 인수([[PRO-VCSMS-02-02_사이버보안_케이스_평가_및_릴리스_절차]])
- **컨셉/개발팀**: 미종결 부적합 재작업 추적

## 7. 주의사항 / 예외 처리

### 7.1 미종결 부적합 잔존
- 부적합이 미종결인 채 보고서를 작성하는 경우, 종결 계획·책임·기한을 명시하고 케이스 릴리스 조건으로 연결한다(미종결 은폐 금지).

### 7.2 증적 불충분
- 검증 결과를 뒷받침할 증적이 불충분하면, 결과를 단정하지 말고 추가 검증(WI-06-02 재수행) 또는 한계 명시 후 권고 수위를 낮춘다.

### 7.3 보고서-케이스 추적 단절
- 보고서가 케이스의 어느 논거에 연결되는지 불명확하면, 목표·클레임 ID 기준으로 케이스 추적 키를 명시하여 단절을 방지한다.

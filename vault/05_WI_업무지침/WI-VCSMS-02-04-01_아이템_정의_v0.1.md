# 아이템 정의 (경계·기능·예비 아키텍처·운용환경) (WI-VCSMS-02-04-01)

> 상위 절차: [[PRO-VCSMS-02-04_컨셉_단계_사이버보안_엔지니어링_절차]] · 상위 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
컨셉 단계의 출발점으로서, 대상 아이템(item)의 경계·기능·예비 아키텍처와 사이버보안 관련 운용환경을 식별·기술하여, 후속 TARA([[PRO-VCSMS-02-03_위협분석_및_리스크평가_TARA_절차]])와 목표·컨셉 도출이 정확하고 완전한 입력 위에서 진행되도록 한다.

## 2. 수행 주체
- **주 수행자**: Project CS Lead
- **검토자**: 보안 설계자, TARA 분석가
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
ISO/SAE 21434 §9.3([RQ-09-01], [RQ-09-02])에 적용한다. 아이템 정의는 TARA 의 첫 입력(자산 식별·피해 시나리오)이 되므로, 본 지침은 아이템 정의 작성·검토·확정까지 다룬다. 운용환경 정보 중 정보보안 관리(ISMS) 경계면은 [RC-05-16] 원칙상 상위 L1 을 "참조"로만 연결한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 프로젝트 사이버보안 계획([[PRO-VCSMS-02-01_프로젝트_사이버보안_관리_절차]] 산출 WP-06-01)
  - 시스템/기능 요구사양, 예비 아키텍처 도면(엔지니어링 제공)
  - 운용 시나리오·외부 인터페이스 목록
- **Output**
  - [[TMP-VCSMS-02-04-01-01_아이템_정의서]] 작성분 (WP-09-01)
  - CSM 승인 기록

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 프로젝트 사이버보안 계획에서 본 아이템의 범위·신규/재사용 구분·테일러링 결정을 확인한다.
2. 엔지니어링으로부터 예비 아키텍처 도면·기능 목록·외부 인터페이스 목록을 수집한다.
3. 아이템 정의서 양식([[TMP-VCSMS-02-04-01-01_아이템_정의서]])을 신규 발번하여 메타(아이템명·프로젝트·버전)를 채운다.

### 5.2 수행 단계
1. **아이템 경계 식별** ([RQ-09-01])
   - 아이템에 포함되는 컴포넌트·ECU·기능과 아이템 외부(주변 시스템) 사이의 경계를 명시한다.
   - 경계를 가로지르는 외부 인터페이스(차내 네트워크·무선·진단 포트·백엔드 등)를 목록화한다.
2. **기능 식별** ([RQ-09-01])
   - 아이템이 제공하는 사이버보안 관련 기능·서비스를 기술한다.
   - 각 기능의 입출력·데이터 흐름을 간략히 표기한다.
3. **예비 아키텍처 식별** ([RQ-09-01])
   - 컴포넌트·인터페이스·신뢰경계를 포함한 예비 아키텍처를 기술한다(상세 설계는 Clause 10 으로 이연).
4. **운용환경 정보 기술** ([RQ-09-02])
   - 사이버보안에 영향을 줄 수 있는 운용환경(연결 차량·인프라·사용자 상호작용·물리 환경) 정보를 기술한다.
   - 가정·전제(assumptions)를 별도로 표기하여 클레임 검증 추적에 대비한다.
5. **완전성 자체 점검**
   - 경계·기능·아키텍처·운용환경·가정 4+1 영역의 누락 항목이 없는지 점검한다.
6. **검토·승인**
   - 보안 설계자·TARA 분석가 검토 의견을 반영한다.
   - CSM 에게 승인을 요청하고 승인 기록을 남긴다.

### 5.3 완료 조건
- [ ] 아이템 경계와 외부 인터페이스 목록이 빠짐없이 기재됨
- [ ] 사이버보안 관련 기능·데이터 흐름 기술 완료
- [ ] 예비 아키텍처(컴포넌트·신뢰경계) 기술 완료
- [ ] 운용환경 정보 및 가정·전제 분리 기재
- [ ] 완전성 자체 점검 누락 0건
- [ ] CSM 승인 기록 확보

## 6. 인터페이스 부서
- **시스템 엔지니어링팀**: 예비 아키텍처·기능 목록 제공
- **TARA 분석가**: 본 정의서를 자산 식별 입력으로 인수
- **정보보안팀(ISMS)**: 운용환경 정보보안 경계면 참조([RC-05-16])

## 7. 주의사항 / 예외 처리

### 7.1 예비 아키텍처 미확정
- 컨셉 초기로 아키텍처가 미확정이면, 확정된 부분만으로 정의하고 미확정 항목을 "TBD(가정 명시)"로 표기한다.
- 후속 확정 시 아이템 정의서를 개정하고 TARA 재수행 필요성을 CSM 이 판단한다.

### 7.2 재사용 아이템
- 기존 아이템 재사용 시 [[PRO-VCSMS-02-01_프로젝트_사이버보안_관리_절차]]의 재사용 분석 결과를 입력으로 받아 변경분만 갱신하고, 변경 없는 부분은 "재사용(원본 참조)"로 표기한다.

### 7.3 경계 모호 (다중 아이템 공유)
- 컴포넌트가 복수 아이템에 공유되어 경계가 모호하면, 공유 인터페이스를 별도 절로 분리 기술하고 책임 아이템을 CSM 이 지정한다.

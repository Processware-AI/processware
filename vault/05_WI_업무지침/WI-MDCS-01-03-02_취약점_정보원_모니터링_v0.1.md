# 취약점 정보원 능동 모니터링 (WI-MDCS-01-03-02)

> 상위 절차: [[PRO-MDCS-01-03_보안_SW_유지보수_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
출시된 헬스SW 와 그 외부 컴포넌트(SUPPORTED/MAINTAINED)에 대해 취약점 정보원을 능동적·정기적으로 수집·검토하고, 제품 적용성을 1차 판정하여, 신규 취약점을 적시에 문제해결 프로세스로 연계한다. (6.2.1)

## 2. 수행 주체
- **주 수행자**: 보안 운영
- **검토자**: 보안책임자(PSO)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-01-03 §5 단계2(모니터링)에 적용한다. 정해진 주기로 상시 수행한다. SBOM(PRO-MDCS-01-04)을 기준으로 모니터링 대상을 정의한다.

## 4. 입력 자료 / 산출물
- **Input**
  - SBOM·컴포넌트 인벤토리(PRO-MDCS-01-04)
  - 취약점 정보원 목록(NVD·CERT·벤더 권고·연구자)
  - 보안 업데이트 정책(WI-MDCS-01-03-01)
- **Output**
  - [[TMP-MDCS-01-03-02-01_취약점_모니터링_기록표_v0.1]] 작성분
  - 모니터링 기록(검토 일자·정보원·신규 취약점)
  - 적용성 1차 판정·문제해결 연계 건

## 5. 수행 절차

### 5.1 사전 준비
1. SBOM 에서 모니터링 대상 컴포넌트·버전을 추출한다.
2. 정보원 목록과 검토 주기를 확인한다.

### 5.2 수행 단계
1. **정보원 수집**
   - 정해진 주기로 NVD·CERT·벤더 권고·연구자 공개 등 정보원을 검토한다.
2. **매칭**
   - 신규 취약점을 SBOM 컴포넌트·버전과 매칭한다.
3. **적용성 1차 판정**
   - 매칭된 취약점이 제품에 적용 가능한지 1차 판정한다(영향 가능성).
4. **연계**
   - 적용 가능 취약점을 PRO-MDCS-01-05(문제해결)로 등록·연계한다.
5. **검토·기록**
   - PSO 가 모니터링 수행·연계 적정성을 검토하고 기록을 보존한다.

### 5.3 완료 조건
- [ ] 정해진 주기 내 모든 정보원 검토 완료
- [ ] 신규 취약점이 SBOM 과 매칭됨
- [ ] 적용 가능 취약점에 대해 적용성 1차 판정 수행
- [ ] 적용 가능 취약점이 PRO-MDCS-01-05 로 연계됨
- [ ] PSO 검토·모니터링 기록 보존

## 6. 인터페이스 부서
- **PRO-MDCS-01-04(형상관리)**: SBOM·컴포넌트 인벤토리 제공
- **PRO-MDCS-01-05(문제해결)**: 적용 가능 취약점 연계
- **외부 정보원/CERT**: 취약점 권고 수신

## 7. 주의사항 / 예외 처리

### 7.1 SBOM 부정확
- SBOM 이 부정확하면 모니터링 누락이 발생하므로, 불일치 발견 시 PRO-MDCS-01-04 로 SBOM 보정을 요청하고 보정 전까지 보수적으로 모니터링한다.

### 7.2 0-day·미공개 취약점
- 공식 정보원에 없는 0-day 가 비공식 채널로 인지되면 적용성을 즉시 평가하고 PRO-MDCS-01-05 로 우선 연계한다.

### 7.3 대량 취약점 유입
- 한 번에 다수 취약점이 유입되면 영향평가 기준(WI-MDCS-01-03-01)으로 우선순위를 정해 처리한다.

### 7.4 EOL/SUPPORTED 한계
- SUPPORTED SW 가 제조자 통제 밖이면 모니터링은 유지하되 대응은 안내·완화책 제공으로 한정하고, 잔여 리스크를 PRO-MDCS-02-01 에 반영한다.

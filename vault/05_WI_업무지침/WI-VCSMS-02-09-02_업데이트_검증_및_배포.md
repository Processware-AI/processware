# 업데이트 검증 및 배포 (WI-VCSMS-02-09-02)

> 상위 절차: [[PRO-VCSMS-02-09_운영_업데이트_및_지원종료_폐기_절차]] · 기준: [[표준프로세스_구성원칙]]

## 1. 업무 목적
개발된 차량 내 업데이트를 본 표준의 검증 활동으로 확인한 뒤에만 배포하여, 미검증 업데이트가 양산 차량에 적용되는 것을 막는다. 검증 통과 후 무결성·인증을 보장하는 방식으로 배포하고 결과를 기록한다. (VCSMS-R-099 / [RQ-13-03])

> 본 WI 는 선택(mandatory: false) — 차량 내 업데이트 역량을 운영하는 경우에만 적용.

## 2. 수행 주체
- **주 수행자**: 운영/필드
- **검토자**: 개발팀
- **승인자**: Cybersecurity Manager (CSM) — 배포 게이트 승인

## 3. 범위
PRO-VCSMS-02-09 §5 단계 2(검증·배포)에 적용한다. 선행 WI-VCSMS-02-09-01(업데이트 개발)이 완료(done)된 후 착수한다(entry gate). 배포 인프라(SUMS) 운영·통신 일반은 UNECE R156([[REF-002_UNECE_R156_SUMS_요약]], 인터페이스 대상)을 따르고, 본 지침은 사이버보안 검증 통과·배포 게이트만 다룬다.

## 4. 입력 자료 / 산출물
- **Input**
  - [[TMP-VCSMS-02-09-01-01_업데이트_개발_명세서]] (요구·역량 요건·델타 영향 평가)
  - 개발 V-model 재적용 검증 산출물
  - 배포 계획(점진 롤아웃·대상 VIN)
- **Output**
  - [[TMP-VCSMS-02-09-02-01_업데이트_검증_및_배포_기록부]] 작성분
  - 배포 결과(커버리지·실패율·롤백 건수)

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 업데이트 개발 명세서의 사이버보안 요구·역량 요건을 검증 항목으로 전개한다.
2. 검증 환경(HIL·차량 시험)과 배포 환경(스테이징·점진 롤아웃)을 준비한다.
3. 배포 중단·롤백 기준(실패율 임계값)을 사전 정의한다.

### 5.2 수행 단계
1. **검증 수행**
   - 업데이트 요구·역량 요건(무결성·롤백·safe-state)을 검증한다. (VCSMS-R-099 / [RQ-13-03])
   - 회귀 검증으로 기존 사이버보안 요구가 유지됨을 확인한다.
2. **검증 결과 판정**
   - 검증 결과(Pass/Fail)와 미충족 항목을 기록한다.
   - Fail 시 개발(WI-09-01)로 반려하고 배포하지 않는다.
3. **배포 게이트(CSM 승인)**
   - 검증 통과 시에만 CSM 이 배포를 승인한다(미검증 배포 0건 원칙).
4. **배포 실행·모니터링**
   - 무결성·인증 보장 방식으로 점진 배포하고, 실패율·롤백을 모니터링한다.
   - 사전 정의 임계값 초과 시 배포를 중단하고 원인을 분석한다.
5. **배포 결과 기록·종결**
   - 커버리지·실패율·롤백 건수를 기록하고, 미적용 차량의 잔존 위험을 추적 항목으로 남긴다.

### 5.3 완료 조건
- [ ] 업데이트 요구·역량 요건이 검증되었다(회귀 포함)
- [ ] 검증 결과(Pass/Fail)와 미충족 항목이 기록되었다
- [ ] 검증 통과 후 CSM 배포 승인을 받았다(미검증 배포 0건)
- [ ] 배포 실패율·롤백이 모니터링되고 임계값 관리되었다
- [ ] 배포 결과(커버리지·실패율)와 잔존 위험이 기록되었다

## 6. 인터페이스 부서
- **SUMS 운영(R156)**: 배포 인프라·통신
- **개발팀**: Fail 반려·재개발
- **CSM 조직**: 배포 게이트 승인

## 7. 주의사항 / 예외 처리

### 7.1 긴급 패치 배포(시간 압박)
- 사고 대응 긴급 패치는 검증을 생략하지 않되, 위험 비례로 핵심 항목 우선 검증(축약)할 수 있다. 축약 범위와 잔여 검증 일정을 CSM 이 승인하고, 배포 후 잔여 검증을 완료한다.

### 7.2 배포 중 대규모 실패
- 배포 실패율이 임계값을 초과하면 즉시 배포를 중단하고 영향 차량을 롤백한다. 원인 분석 전까지 재배포하지 않으며, 필요 시 사고 대응(PRO-VCSMS-01-04) 연계를 CSM 이 판정한다.

### 7.3 배포 커버리지 미달(장기 미적용 차량)
- 일부 차량이 장기간 업데이트 미적용 상태로 남으면, 해당 VIN 의 잔존 위험을 추적 등록하고 재배포·고객 통보 등 후속 조치를 계획한다.

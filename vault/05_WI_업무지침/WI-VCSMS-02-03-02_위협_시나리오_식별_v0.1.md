# 위협 시나리오 식별 (WI-VCSMS-02-03-02)

> 상위 절차: [[PRO-VCSMS-02-03_위협분석_및_리스크평가_TARA_절차]] · 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]
> **횡단 방법론** — TARA 2단계.

## 1. 업무 목적
식별된 자산을 기반으로 대상 자산·손상될 사이버보안 속성·손상 원인을 포함하는 위협 시나리오를 식별하여, 이후 공격 경로 분석·리스크값 결정의 대상을 정의한다. (§15.4 [RQ-15-03])

## 2. 수행 주체
- **주 수행자**: TARA 분석가
- **검토자**: 보안 설계자
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
본 지침은 PRO-VCSMS-02-03 §5 단계 2(위협 시나리오)에 적용한다. 자산 목록(WI-01)을 입력으로 받아 위협 시나리오(WP-15-03)를 생성하며, 공격 경로 분석(WI-VCSMS-02-03-04)의 입력이 된다.

## 4. 입력 자료 / 산출물
- **Input**
  - [[TMP-VCSMS-02-03-01-01_자산_및_피해시나리오_목록]] (승인)
  - 위협 식별 방법론(예: STRIDE 등 체계적 기법)
- **Output**
  - [[TMP-VCSMS-02-03-02-01_위협_시나리오_목록]] 작성분 (WP-15-03)

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 자산·피해 시나리오 목록이 승인되었는지 확인한다(entry_gate).
2. 위협 식별 방법론·체크리스트를 준비한다.

### 5.2 수행 단계
1. **위협 도출**
   - 각 자산의 손상 속성에 대해 손상 원인(위협)을 체계적으로 도출한다([RQ-15-03]).
   - 위협 시나리오를 "대상 자산 + 손상 속성 + 손상 원인" 구조로 기술한다.
2. **피해 시나리오 연결**
   - 각 위협 시나리오를 대응 피해 시나리오(WI-01)와 연결한다.
3. **중복·누락 점검**
   - 동일 위협 중복을 통합하고 자산별 위협 누락을 점검한다.
4. **검토·승인**
   - 보안 설계자 검토 후 CSM 이 위협 시나리오 목록을 승인한다.

### 5.3 완료 조건
- [ ] 각 자산-손상속성에 대한 위협 도출
- [ ] 위협 시나리오를 자산+속성+원인 구조로 기술
- [ ] 피해 시나리오 연결
- [ ] 중복 통합·누락 점검
- [ ] CSM 승인

## 6. 인터페이스 부서
- **보안 설계자**: 아키텍처 기반 위협 검토
- **취약점 관리(Clause 8)**: 알려진 위협·CVE 정보 입력
- **품질(QMS)**: 산출물 형상·문서 관리 (§5.4.4 경계면)

## 7. 주의사항 / 예외 처리

### 7.1 자산 변경에 따른 재도출
- WI-01 자산 목록이 갱신된 경우:
  - 변경 자산에 대한 위협 시나리오를 재도출하고 후속 단계를 재수행.

### 7.2 위협 과다·낮은 실현성
- 도출 위협이 과다하거나 실현성이 낮은 경우:
  - 실현 가능성 관점에서 우선순위를 부여하되 임의 삭제는 금지(공격 경로 분석에서 타당성으로 판단).

### 7.3 신규 위협 인텔리전스
- 운영 중 신규 위협(취약점·공격기법)이 보고된 경우:
  - 지속활동(PRO-VCSMS-01-03)에서 본 목록을 갱신하도록 트리거.

# 제3자 SW 공급자 보안 요구 전달 및 보증 (WI-MDCS-01-01-03)

> 상위 절차: [[PRO-MDCS-01-01_보안_거버넌스_및_일반요건_관리_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
헬스SW 에 포함되는 제3자(외부) SW 항목 중 보안에 영향을 주는 항목에 대해, 적용 가능한 보안 요구를 공급자에게 전달하고 공급자가 해당 보안 활동을 수행함을 보증받아, 외부 SW 로 인한 보안 책임 공백을 방지한다. (4.1.5)

## 2. 수행 주체
- **주 수행자**: 구매/공급자 관리
- **검토자**: 보안책임자(PSO)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-01-01 §5 단계5(제3자 보증)에 적용한다. **선행조건**: WI-MDCS-01-01-01(SW 분류)이 완료되어 외부 SW 항목과 분류가 확정되어 있어야 한다. 제조자 전용으로 통합되거나 보안 영향이 있는 외부 SW 항목에 적용한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 확정된 SW 분류표(WI-01-01-01 산출물)
  - 외부 SW 공급 계약·공급자 목록
  - 제품에 요구되는 보안 요구사항(해당 시)
- **Output**
  - [[TMP-MDCS-01-01-03-01_제3자SW_보안요구_전달_및_보증대장_v0.1]] 작성분
  - 공급자별 전달된 보안 요구·전달 증적
  - 공급자 보안 활동 보증 근거(계약 조항·증빙·서약)

## 5. 수행 절차

### 5.1 사전 준비
1. SW 분류표에서 보안 영향이 있는 외부 SW 항목을 선별한다.
2. 각 항목의 공급자·계약 형태를 확인한다.
3. 항목별로 전달해야 할 보안 요구를 식별한다(취약점 통지·패치 제공·SBOM 제출 등).

### 5.2 수행 단계
1. **대상 식별**
   - 제조자 전용 통합 또는 보안 영향 외부 SW 항목을 대상으로 확정한다.
2. **보안 요구 도출**
   - 각 대상에 적용 가능한 보안 요구(취약점 통지 의무·보안 패치 SLA·SBOM·코드 무결성 등)를 도출한다.
3. **공급자 전달**
   - 보안 요구를 공급자에게 공식 전달한다(계약·부속합의·SLA 문서).
   - 전달 일자·수단·수신 확인을 기록한다.
4. **보증 확보**
   - 공급자가 해당 보안 활동을 수행함을 보증받는다(계약 조항·증빙·자기선언·제3자 인증).
5. **검토·등록**
   - PSO 가 전달·보증의 충분성을 검토·승인하고 보증대장에 등록한다.

### 5.3 완료 조건
- [ ] 보안 영향 외부 SW 항목이 모두 식별됨(누락 0건)
- [ ] 각 대상에 적용 가능한 보안 요구가 도출·전달됨
- [ ] 전달 증적(일자·수단·수신 확인) 보유
- [ ] 공급자 보안 활동 보증 근거 확보
- [ ] PSO 검토·승인 기록 존재

## 6. 인터페이스 부서
- **법무**: 계약 보안 조항 검토
- **개발팀**: 외부 SW 통합 형태·보안 영향 정보 제공
- **형상관리 담당**: SBOM·컴포넌트 인벤토리 연계(PRO-MDCS-01-04)

## 7. 주의사항 / 예외 처리

### 7.1 공급자 미협조
- 공급자가 보안 요구 수용·보증을 거부하면 대체 공급자 검토 또는 보완 통제(자체 모니터링·격리)를 적용하고, 잔여 리스크를 PRO-MDCS-02-01(리스크 관리)에 반영한다.

### 7.2 보증 증빙 불충분
- 자기선언만 있고 검증 근거가 약한 경우 추가 증빙(인증서·취약점 대응 이력)을 요청하고, 확보 전까지 해당 항목을 모니터링 강화 대상으로 표시한다.

### 7.3 OSS(무공급자) 컴포넌트
- 공식 공급자가 없는 오픈소스는 전달 대상에서 제외하되, 제조자가 직접 취약점 모니터링·패치 책임(MAINTAINED)을 지므로 PRO-MDCS-01-03 모니터링 대상으로 등록한다.

### 7.4 계약 갱신·공급자 변경
- 공급 계약 갱신·공급자 변경 시 본 지침을 재수행하여 보안 요구 전달·보증을 갱신한다.

# 제품 보안 맥락 문서화 (WI-MDCS-02-01-01)

> 상위 절차: [[PRO-MDCS-02-01_보안_리스크_관리_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-02_보안_리스크_관리_방침_v0.1]]

## 1. 업무 목적
헬스SW 가 의도된 환경(PRODUCT SECURITY CONTEXT)에서 안전하게 동작하기 위한 환경 최소 요건·운영 가정·경계를 문서화하여, 위협 모델링과 리스크 평가의 기준 전제를 확립한다. (7.1.2)

## 2. 수행 주체
- **주 수행자**: 위협 모델링 리드
- **검토자**: 보안책임자(PSO)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-02-01 §5 단계1(보안 맥락)에 적용한다. 제품 단위로 수립하고 환경·구성 변경 시 갱신한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 제품 요구·의도된 사용
  - 배포·운영 환경 정보(네트워크·단말·연동 시스템)
  - SW 분류표(REQUIRED 항목)
- **Output**
  - [[TMP-MDCS-02-01-01-01_제품_보안맥락_문서_v0.1]] 작성분
  - 보안 맥락 문서(환경 가정·최소 요건·경계)

## 5. 수행 절차

### 5.1 사전 준비
1. 제품의 의도된 사용·배포 형태를 확인한다.
2. 운영 환경(네트워크·단말·연동)·REQUIRED SW 를 파악한다.

### 5.2 수행 단계
1. **의도된 환경 정의**
   - 제품이 안전하게 동작하도록 의도된 환경을 정의한다(네트워크 분리·접근 통제 가정 등).
2. **환경 최소 요건**
   - 사용자/운영 환경이 충족해야 할 최소 보안 요건을 명시한다(OS 버전·방화벽·인증 인프라).
3. **가정·경계 문서화**
   - 보안 가정(무엇을 환경이 보장한다고 가정하는지)과 책임 경계를 문서화한다.
4. **검토·연계**
   - PSO 검토 후 위협 모델링(WI-MDCS-02-01-02)으로 연계한다.

### 5.3 완료 조건
- [ ] 의도된 보안 환경 정의
- [ ] 환경 최소 보안 요건 명시
- [ ] 보안 가정·책임 경계 문서화
- [ ] REQUIRED SW 관련 가정 포함
- [ ] PSO 검토·위협 모델링 연계

## 6. 인터페이스 부서
- **WI-MDCS-02-01-02(위협 모델링)**: 보안 맥락 입력
- **WI-MDCS-01-02-02(보안 요구)**: 환경 요건을 요구로 반영
- **WI-MDCS-01-01-05(동반문서)**: 최소 요건 사용자 전달

## 7. 주의사항 / 예외 처리

### 7.1 과도한 환경 가정
- 환경이 보장하지 않는 것을 가정하면 위험하므로, 가정은 검증 가능하고 동반문서로 사용자에게 전달 가능한 수준으로 한다.

### 7.2 환경 변동
- 운영 환경이 가정과 달라지면(예: 인터넷 직접 노출) 보안 맥락을 갱신하고 위협 모델·리스크를 재평가한다.

### 7.3 다양한 배포 형태
- 온프레미스·클라우드·하이브리드 등 배포 형태가 다양하면 각 형태별 보안 맥락을 구분 문서화한다.

### 7.4 REQUIRED SW 가정 미충족
- REQUIRED SW 가 최소 요건을 충족하지 못할 가능성이 있으면 잔여 리스크로 식별하고 동반문서에 명시한다.

# 차량 수준 사이버보안 검증 수행 (WI-VCSMS-02-06-02)

> 상위 절차: [[PRO-VCSMS-02-06_차량_수준_사이버보안_검증_절차]] · 상위 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
선정된 검증 활동을 수행하여, 차량 수준에서 사이버보안 목표의 적정성·달성, 사이버보안 클레임 및 운용환경 요구의 유효성을 확인하고, 부적합을 식별하여 재작업 또는 보고로 연결한다.

## 2. 수행 주체
- **주 수행자**: 검증 엔지니어 (R/A)
- **검토자**: Project CS Lead
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
ISO/SAE 21434 §11.4([RQ-11-01])에 적용한다. 본 지침은 선정 활동의 검증 수행·유효성 판정을 다룬다. 검증 활동 선정은 WI-06-01 이, 보고서 작성은 WI-06-03 이 담당한다.

## 4. 입력 자료 / 산출물
- **Input**
  - [[TMP-VCSMS-02-06-01-01_검증_활동_선정서]] (승인된 검증 계획)
  - 검증 대상 차량/시스템·테스트 환경
- **Output**
  - [[TMP-VCSMS-02-06-02-01_차량_수준_검증_수행기록]] 작성분 (WP-11-01 입력)

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 검증 활동 선정서가 승인(WI-06-01 done) 상태인지 확인한다(entry_gate).
2. 검증 환경·차량 형상·도구를 검증 계획대로 준비한다.
3. 수행기록 양식([[TMP-VCSMS-02-06-02-01_차량_수준_검증_수행기록]])을 발번한다.

### 5.2 수행 단계
1. **목표 적정성 확인** ([RQ-11-01])
   - 사이버보안 목표가 차량 통합 맥락에서 여전히 적정한지(누락 위협·과대·과소 없음) 확인한다.
2. **목표 달성 확인** ([RQ-11-01])
   - 선정 활동을 수행하여 목표(CG-##)가 차량 수준에서 달성되는지 확인하고 증적을 기록한다.
3. **클레임 유효성 확인** ([RQ-11-01])
   - 사이버보안 클레임(CC-##)의 근거 가정·외부 책임이 유효한지 확인한다.
4. **운용환경 요구 유효성 확인** ([RQ-11-01])
   - 운용환경 요구·가정이 실차 환경에서 유효한지 확인한다.
5. **부적합 식별·기록**
   - 유효하지 않은 항목을 부적합으로 식별·기록하고, 재작업 연계(컨셉/개발) 또는 잔여 리스크 처리 방향을 표식한다.
6. **검토·승인**
   - Project CS Lead 검토를 반영하고 CSM 승인을 받는다.

### 5.3 완료 조건
- [ ] entry_gate(WI-06-01 done) 충족 확인
- [ ] 목표 적정성 확인 완료
- [ ] 목표 달성 확인 및 증적 기록(전 목표)
- [ ] 클레임 유효성 확인 완료
- [ ] 운용환경 요구 유효성 확인 완료
- [ ] 부적합 식별·처리 방향 표식
- [ ] CSM 승인 기록 확보

- **컨셉/개발팀**: 부적합 시 재작업 인수([[PRO-VCSMS-02-04_컨셉_단계_사이버보안_엔지니어링_절차]], [[PRO-VCSMS-02-05_제품개발_사이버보안_엔지니어링_절차]])

## 7. 주의사항 / 예외 처리

### 7.1 목표 부적정(컨셉 회귀)
- 목표 자체가 부적정(차량 맥락 누락 위협 발견 등)하면, 개발 재작업이 아니라 컨셉 단계([[PRO-VCSMS-02-04_컨셉_단계_사이버보안_엔지니어링_절차]])로 회귀하여 TARA·목표를 갱신한다.

### 7.2 클레임 무효
- 클레임 근거 가정이 실차에서 무효로 확인되면, 해당 위협을 감소(목표 도출)로 재처리하거나 공급자 합의(Clause 7)로 책임을 재확정한다.

### 7.3 환경 제약으로 검증 미완
- 실차·환경 제약으로 일부 검증이 미완이면, 미완 항목·잔여 리스크·후속 검증 시점을 명시하고 케이스([[PRO-VCSMS-02-02_사이버보안_케이스_평가_및_릴리스_절차]])에서 릴리스 조건으로 다룬다.

# 보안 통합 시험 (WI-MDCS-01-02-06)

> 상위 절차: [[PRO-MDCS-01-02_보안_SW_개발_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

> ⚠️ **권고(should) 활동** — mandatory=false. 통합 경계가 있는 제품에서 수행을 권장하며, 미수행 시 사유와 대체 검증(시스템 시험 흡수 등)을 문서화한다.

## 1. 업무 목적
서로 다른 신뢰경계·보안정책을 가진 컴포넌트가 통합될 때, 경계 간 보안정책 차이로 인한 약점(검증 누락·권한 상승·데이터 노출)을 통합 시험으로 검출하여, 시스템 시험 전에 통합 수준의 보안을 확인한다. (5.6, should)

## 2. 수행 주체
- **주 수행자**: 보안 테스터
- **검토자**: 검토자(독립)
- **승인자**: 검토자(독립)

## 3. 범위
PRO-MDCS-01-02 §5 단계6(통합)에 적용한다. **선행조건**: WI-MDCS-01-02-05(구현) 완료. 권고 활동이므로 통합 경계 유무에 따라 적용 여부를 판단한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 인터페이스 특성화 분석(WI-MDCS-01-02-04)
  - 구현물·정적분석 결과(WI-MDCS-01-02-05)
  - 신뢰경계·보안정책 정의(아키텍처)
- **Output**
  - [[TMP-MDCS-01-02-06-01_보안_통합시험_계획_및_보고서_v0.1]] 작성분
  - 통합 시험 계획·케이스
  - 통합 시험 보고서(발견·조치)

## 5. 수행 절차

### 5.1 사전 준비
1. 인터페이스 특성화에서 신뢰경계 간 통합 지점을 식별한다.
2. 각 경계의 보안정책 차이(인증·암호·권한)를 정리한다.
3. 통합 시험 환경을 구성한다.

### 5.2 수행 단계
1. **통합 시험 케이스 설계**
   - 신뢰경계 간 데이터 전달·인증 위임·권한 경계를 검증하는 케이스를 설계한다.
2. **통합 시험 실행**
   - 케이스를 실행하고 경계 간 정책 불일치로 인한 약점을 탐지한다.
3. **결과 분석·조치**
   - 발견 약점을 시정하거나 PRO-MDCS-01-05(문제해결)로 연계한다.
4. **검토 승인**
   - 독립 검토자가 통합 시험 커버리지·발견 종결을 검토·승인한다.

### 5.3 완료 조건
- [ ] 신뢰경계 간 통합 지점이 모두 식별됨
- [ ] 경계 간 정책 차이 검증 케이스 설계·실행
- [ ] 발견 약점 시정 또는 문제해결 연계·종결
- [ ] 독립 검토자 검토·승인 기록 존재
- [ ] (미수행 시) 미수행 사유·대체 검증 문서화

## 6. 인터페이스 부서
- **WI-MDCS-01-02-07(시스템 시험)**: 통합본 이관
- **PRO-MDCS-01-05(문제해결)**: 발견 약점 연계
- **개발팀**: 통합 환경 구성 지원

## 7. 주의사항 / 예외 처리

### 7.1 통합 시험 미수행(권고 활동)
- 통합 경계가 미미하여 미수행하는 경우, 그 판단 근거와 시스템 시험에서의 흡수 계획을 개발 계획(WI-MDCS-01-02-01)·본 보고서에 문서화한다.

### 7.2 경계 정책 충돌 발견
- 통합 시 신뢰경계 정책이 충돌하면(예: 한쪽이 검증을 가정) 보수적 측에 맞춰 보강하고 아키텍처/설계 단계로 피드백한다.

### 7.3 통합 환경 제약
- 실제 외부 시스템 연동이 어려우면 스텁/모의 환경으로 대체하되, 모의 한계를 기록하고 시스템 시험에서 실연동을 검증한다.

### 7.4 발견 약점 미종결
- 통합 시험 약점이 종결되지 않으면 시스템 시험(WI-MDCS-01-02-07) 진행 가부를 검토자가 판단한다.

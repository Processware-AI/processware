# 정보원 선정 및 트리아지 트리거 정의 (WI-VCSMS-01-03-01)

> 상위 절차: [[PRO-VCSMS-01-03_지속적_사이버보안_활동_및_취약점_관리_절차]] · 상위 정책: [[POL-VCSMS-01_자동차_사이버보안_거버넌스_정책]]

## 1. 업무 목적
양산·운영 중 차량의 사이버보안 정보를 수집하기 위한 **정보원을 선정**하고, 수집된 정보를 분류·우선순위화하는 **트리아지 트리거를 정의·유지**한다. 신규 위협·취약점을 누락 없이 포착하기 위한 상시 모니터링의 기반을 구축한다.

## 2. 수행 주체
- **주 수행자**: 모니터링 담당 (Monitoring Lead)
- **검토자**: Cybersecurity Manager (CSM)
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
PRO-VCSMS-01-03 §5 단계 1 에 적용한다. 정보원 선정(§8.3 [RQ-08-01]), 트리아지 트리거 정의·유지([RQ-08-02])를 다룬다. 정보 수집·이벤트 판별은 [[WI-VCSMS-01-03-02_정보_수집_트리아지_및_이벤트_판별]] 로 분리한다. 정보공유 규칙은 [[WI-VCSMS-01-01-04_정보공유_조건_정의_및_소통채널_운영]] 을 참조한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 위협 인텔리전스 소스 후보(CVE/NVD·Auto-ISAC·CERT·공급사 권고·연구 커뮤니티·내부 텔레메트리)
  - 운영 중 item/component 인벤토리·자산 목록
  - ISO/SAE 21434 §8.3 [RQ-08-01·02] 요건
- **Output**
  - 정보원 목록 (WP-08-01) — 출처·신뢰도·갱신 주기·수집 방식
  - 트리아지 트리거 정의 (WP-08-02) — 분류 기준·우선순위·SLA
  - [[TMP-VCSMS-01-03-01-01_정보원_및_트리아지_트리거_정의서]] 작성분

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 운영 중 item/component 와 사용 기술 스택(OS·라이브러리·통신 프로토콜) 인벤토리 확보.
2. 위협 인텔 소스 후보를 조사하고 접근 가능성(라이선스·계정)을 확인.
3. 정보공유 규칙([[WI-VCSMS-01-01-04_정보공유_조건_정의_및_소통채널_운영]])에서 외부 소스 사용 조건 확인.

### 5.2 수행 단계
1. **정보원 선정** ([RQ-08-01])
   - 자산 커버리지를 기준으로 정보원을 선정(취약점 DB·ISAC·공급사·내부 텔레메트리·연구).
   - 각 정보원의 출처·신뢰도·갱신 주기·수집 방식(자동 피드/수동)을 정의.
2. **수집 방식·자동화 정의**
   - 자동 수집(피드·API)과 수동 수집(권고·뉴스) 경로를 정의하고 책임자 지정.
3. **트리아지 트리거 정의** ([RQ-08-02])
   - 수집 정보를 사이버보안 이벤트 후보로 분류하는 트리거를 정의(자산 매칭·심각도·악용 가능성·노출 여부).
   - 우선순위·대응 SLA(접수→트리아지 시간)를 명시.
   - [[TMP-VCSMS-01-03-01-01_정보원_및_트리아지_트리거_정의서]] 에 기록.
4. **CSM 검토·승인**
   - CSM 이 정보원 커버리지와 트리거 적정성(누락 위험)을 검토·승인.
5. **유지·갱신 주기 설정**
   - 정보원·트리거의 정기 갱신 주기(분기 권장)와 갱신 트리거(신규 자산·신규 위협원)를 설정.
6. **활성화·점검**
   - 정보원을 활성화하고 활성률(KPI: 선정 정보원 활성률 100%)을 월 점검.

### 5.3 완료 조건
- [ ] 운영 자산 커버리지 기준 정보원 선정 및 출처·신뢰도·주기 정의
- [ ] 자동/수동 수집 경로·책임자 지정
- [ ] 트리아지 트리거(자산 매칭·심각도·악용성)·우선순위·SLA 정의
- [ ] CSM 커버리지·트리거 적정성 검토·승인
- [ ] 정보원·트리거 정기 갱신 주기·트리거 설정
- [ ] 정보원 활성화 및 활성률 100% 점검 체계 운영

## 6. 인터페이스 부서
- **정보공유 운영(WI-01-01-04)**: 외부 소스 사용 조건·채널
- **자산관리/형상관리**: item/component 인벤토리 제공
- **공급망(§7)**: 공급사 취약점 권고 수신 채널(CIA 연계)

## 7. 주의사항 / 예외 처리

### 7.1 정보원 커버리지 공백
- 특정 자산·기술에 대응하는 정보원이 없는 경우:
  - 대체 소스(연구 커뮤니티·자체 분석)를 추가하거나 공급사에 권고 채널을 요청.
  - 공백과 잔존 리스크를 CSM 에 보고.

### 7.2 트리거 과민/둔감
- 트리거가 과도한 오탐(false positive) 또는 누락(false negative)을 유발하는 경우:
  - 임계값·매칭 규칙을 조정하고 조정 이력을 정의서에 기록.
  - 둔감으로 인한 누락 위험은 우선 보수적으로 설정.

### 7.3 정보원 신뢰도 저하·중단
- 정보원이 중단되거나 신뢰도가 저하된 경우:
  - 즉시 대체 정보원으로 전환하고 활성률 점검에 반영.
  - 중단 기간의 수집 공백을 사후 보완 수집으로 메움.

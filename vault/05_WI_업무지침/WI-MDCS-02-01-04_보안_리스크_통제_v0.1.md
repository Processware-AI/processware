# 보안 리스크 통제(완화 선정·구현·효과 검증·잔여리스크) (WI-MDCS-02-01-04)

> 상위 절차: [[PRO-MDCS-02-01_보안_리스크_관리_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-02_보안_리스크_관리_방침_v0.1]]

## 1. 업무 목적
통제가 필요한 보안 리스크에 대해 적절한 완화책을 선정·구현하고 효과를 검증하며, 통제로 인한 신규/증가 리스크를 판정하고, 잔여 리스크를 문서화하여 제품 리스크 관리와 협력함으로써, 리스크를 수용 가능 수준으로 낮춘다. (7.4)

## 2. 수행 주체
- **주 수행자**: 개발팀
- **검토자**: 보안책임자(PSO) / 제품 리스크 관리자
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-02-01 §5 단계4(통제)에 적용한다. **선행조건**: WI-MDCS-02-01-03(추정·평가) 완료. 통제 필요 판정 리스크를 대상으로 한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 리스크 평가 결과(통제 필요 항목)(WI-MDCS-02-01-03)
  - 위협 모델·아키텍처·설계
  - 리스크 수용 기준(POL-MDCS-02)
- **Output**
  - [[TMP-MDCS-02-01-04-01_보안_리스크_통제_및_잔여리스크표_v0.1]] 작성분
  - 완화책 선정·구현·효과 검증 기록
  - 잔여 리스크 문서·제품 RM 협력 기록

## 5. 수행 절차

### 5.1 사전 준비
1. 통제 필요 리스크와 수용 기준을 확인한다.
2. 적용 가능한 완화 옵션(설계·구성·운영 통제)을 식별한다.

### 5.2 수행 단계
1. **완화책 선정**
   - 각 리스크에 적절한 완화책을 선정한다(효과·실현성·부작용 고려).
2. **구현**
   - 완화책을 설계·구현(WI-MDCS-01-02-04/05 연계)하거나 운영 통제로 적용한다.
3. **효과 검증**
   - 완화 효과를 시험으로 검증한다(WI-MDCS-01-02-07 연계).
4. **신규/증가 리스크 판정**
   - 통제로 인한 신규/증가 리스크를 식별·재평가한다.
5. **잔여 리스크 문서화·협력**
   - 잔여 리스크를 문서화하고 제품 리스크 관리와 협력하여 안전·유효성 관점에서 수용을 확인한다.
6. **검토·승인**
   - PSO 가 통제 적절성·잔여 리스크 수용을 승인한다.

### 5.3 완료 조건
- [ ] 통제 필요 리스크에 완화책 선정·구현
- [ ] 완화 효과 검증 수행
- [ ] 통제로 인한 신규/증가 리스크 식별·재평가
- [ ] 잔여 리스크 문서화 및 제품 RM 협력 수용 확인
- [ ] PSO 검토·승인 기록 존재

## 6. 인터페이스 부서
- **WI-MDCS-01-02-04/05(설계·구현)**: 완화책 구현
- **WI-MDCS-01-02-07(시스템 시험)**: 완화 효과 검증
- **제품 리스크 관리(연계)**: 잔여 리스크 협력(ISO 14971 향후)
- **WI-MDCS-01-01-05(동반문서)**: 잔여 리스크 전달

## 7. 주의사항 / 예외 처리

### 7.1 완화 효과 미입증
- 완화책이 효과를 입증하지 못하면 대체 완화책을 적용하거나 추가 통제를 도입하고 재검증한다(미검증 완화 인정 금지).

### 7.2 통제의 신규 리스크
- 완화책이 새로운 리스크를 만들면 이를 재평가(WI-MDCS-02-01-03)하고, 순효과가 음수면 완화책을 재설계한다.

### 7.3 수용 불가 잔여 리스크
- 잔여 리스크가 수용 불가하면 추가 완화·설계 변경을 추진하고, 불가 시 제품 출시·범위를 재검토한다.

### 7.4 안전-보안 트레이드오프
- 보안 통제가 안전·유효성과 충돌하면 제품 리스크 관리와 협력해 균형점을 찾고 결정을 문서화한다.

# 사이버보안 컨셉·통제·요구사항 정의 및 할당 (WI-VCSMS-02-04-05)

> 상위 절차: [[PRO-VCSMS-02-04_컨셉_단계_사이버보안_엔지니어링_절차]] · 상위 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
검증된 사이버보안 목표를 달성하기 위한 기술·운영 통제와 상호작용(의존성·클레임 고려)을 기술하고, 아이템·운용환경의 사이버보안 요구를 정의하여 아이템·(해당 시)컴포넌트에 할당함으로써, 후속 제품개발(Clause 10)의 사양 입력을 확정한다.

## 2. 수행 주체
- **주 수행자**: 보안 설계자
- **검토자**: Project CS Lead
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
ISO/SAE 21434 §9.5([RQ-09-08], [RQ-09-09], [RQ-09-10])에 적용한다. 통제·요구의 검증(완전·정확·일관)은 후속 WI-04-06 이 담당한다. 본 지침은 통제·요구 정의·할당까지 다룬다.

  - [[TMP-VCSMS-02-04-04-01_목표_클레임_검증보고서]] (통과 판정)

- **Output**

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 목표·클레임 검증이 통과(WI-04-04 done) 상태인지 확인한다(entry_gate).
2. 검증 통과한 목표 목록과 예비 아키텍처를 정렬한다.
3. 컨셉·요구 명세서 양식([[TMP-VCSMS-02-04-05-01_사이버보안_컨셉_및_요구사항_명세서]])을 발번한다.

### 5.2 수행 단계
1. **통제·상호작용 기술** ([RQ-09-08])
   - 각 목표 달성을 위한 기술적·운영적 통제를 기술한다.
   - 통제 간 의존성·클레임과의 상호작용을 명시한다.
2. **사이버보안 요구 정의** ([RQ-09-09])
   - 목표별로 아이템과 운용환경에 대한 사이버보안 요구를 정의한다(요구ID CR-## 부여).
   - 각 요구를 검증 가능한 형태로 기술한다.
3. **요구 할당** ([RQ-09-10])
   - 각 요구를 아이템·(해당 시)컴포넌트에 할당한다.
   - 운용환경 요구는 외부 책임 주체(사용자·인프라·백엔드)에 할당 표기한다.
4. **추적성 연결**
   - 위협→목표→통제→요구→할당의 추적 사슬을 연결한다.
5. **검토·승인**
   - Project CS Lead 검토를 반영하고 CSM 승인을 받는다.

### 5.3 완료 조건
- [ ] entry_gate(WI-04-04 done) 충족 확인
- [ ] 모든 목표에 통제·상호작용 기술(누락 0)
- [ ] 모든 목표에 사이버보안 요구(CR-##) 정의(누락 0)
- [ ] 모든 요구가 아이템·컴포넌트·외부주체에 할당(미할당 0)
- [ ] 목표↔통제↔요구↔할당 추적 사슬 연결 확인
- [ ] CSM 승인 기록 확보

## 6. 인터페이스 부서
- **Project CS Lead**: 컨셉 검증(WI-04-06) 착수 검토
- **시스템 엔지니어링팀**: 할당 컴포넌트 사양화 인수([[PRO-VCSMS-02-05_제품개발_사이버보안_엔지니어링_절차]])
- **운영/인프라 책임팀**: 운용환경 요구 인수

## 7. 주의사항 / 예외 처리

### 7.1 목표 미충족 통제 공백
- 특정 목표에 달성 통제가 식별되지 않으면, 컨셉을 미완으로 표기하고 목표 재검토(WI-04-04 연계) 또는 추가 통제 연구를 CSM 에 보고한다.

### 7.2 운용환경 요구 책임 불명
- 운용환경 요구의 외부 책임 주체가 불명확하면, 임의 할당 금지. Clause 7 공급자 인터페이스 합의(CIA) 또는 운영팀 협의로 책임을 확정한 뒤 할당한다.

### 7.3 통제 간 상충
- 통제가 서로 상충(예: 가용성 우선 통제 vs 기밀성 우선 통제)하면, 우선순위·트레이드오프를 명시하고 CSM 결정으로 조정한다.

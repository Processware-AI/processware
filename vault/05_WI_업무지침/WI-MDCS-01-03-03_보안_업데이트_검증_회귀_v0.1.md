# 보안 업데이트 검증(효과·회귀) (WI-MDCS-01-03-03)

> 상위 절차: [[PRO-MDCS-01-03_보안_SW_유지보수_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
생성된 보안 업데이트가 의도한 취약점을 실제로 해결하는지 효과를 검증하고, 기능·성능·안전·유효성에 의도치 않은 영향(회귀)이 없음을 확인하여, 업데이트 배포 전에 품질을 보증한다. (6.2.2)

## 2. 수행 주체
- **주 수행자**: 검증 인력
- **검토자**: 개발자
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-01-03 §5 단계3(검증)에 적용한다. 각 보안 업데이트 배포 전에 수행한다. 업데이트 생성은 PRO-MDCS-01-05(문제해결)에서 이루어진다.

## 4. 입력 자료 / 산출물
- **Input**
  - 보안 업데이트(패치)·대상 취약점 정보
  - 회귀 시험 스위트·영향 범위 분석
  - 영향평가 결과(WI-MDCS-01-03-01 정책 기준)
- **Output**
  - [[TMP-MDCS-01-03-03-01_보안_업데이트_검증_및_회귀시험표_v0.1]] 작성분
  - 효과 검증 결과(취약점 해결 확인)
  - 회귀 시험 결과(영향 없음 확인)

## 5. 수행 절차

### 5.1 사전 준비
1. 업데이트 대상 취약점과 기대 효과를 확인한다.
2. 영향 범위를 분석하여 회귀 시험 범위를 결정한다.

### 5.2 수행 단계
1. **효과 검증**
   - 패치 적용 후 대상 취약점이 더 이상 악용되지 않음을 검증한다(재현 시도·완화 확인).
2. **회귀 시험**
   - 영향 범위의 기능·성능·안전 관련 항목에 회귀 시험을 실행한다.
3. **결과 판정**
   - 효과·무회귀가 모두 충족되면 배포 가능으로 판정한다.
4. **검토·승인**
   - 개발자 검토 후 PSO 가 검증 결과를 승인한다(부적합 시 재패치).

### 5.3 완료 조건
- [ ] 대상 취약점 해결 효과 검증(재현 불가 확인)
- [ ] 영향 범위 회귀 시험 실행·통과
- [ ] 안전·유효성 관련 회귀 항목 확인
- [ ] 효과·무회귀 모두 충족 시 배포 가능 판정
- [ ] 개발자 검토·PSO 승인 기록 존재

## 6. 인터페이스 부서
- **PRO-MDCS-01-05(문제해결)**: 패치 생성·근본 원인 정보
- **WI-MDCS-01-03-04(제공)**: 검증 합격 업데이트 이관
- **품질/임상(연계)**: 안전·유효성 회귀 판정 지원

## 7. 주의사항 / 예외 처리

### 7.1 회귀 발생
- 회귀가 발생하면 배포를 보류하고 패치를 재작업(PRO-MDCS-01-05)하거나 회귀 영향을 완화하는 추가 조치 후 재검증한다.

### 7.2 효과 미입증
- 패치가 취약점을 해결하지 못하면 근본 원인 재분석을 요청하고 재패치 후 검증한다(미입증 업데이트 배포 금지).

### 7.3 긴급 패치의 축약 검증
- 긴급(상) 영향 패치는 핵심 효과·안전 회귀에 한정한 축약 검증으로 배포하되, 전체 회귀는 사후 보완 검증한다.

### 7.4 안전·유효성 영향 의심
- 업데이트가 안전·유효성에 영향을 줄 수 있으면 PRO-MDCS-02-01(리스크 관리) 및 제품 리스크 관리와 협력하여 평가한다.

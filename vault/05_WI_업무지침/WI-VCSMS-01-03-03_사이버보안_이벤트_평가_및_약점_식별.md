# 사이버보안 이벤트 평가 및 약점 식별 (WI-VCSMS-01-03-03)

> 상위 절차: [[PRO-VCSMS-01-03_지속적_사이버보안_활동_및_취약점_관리_절차]] · 상위 정책: [[POL-VCSMS-01_자동차_사이버보안_거버넌스_정책]]

## 1. 업무 목적
확정된 사이버보안 이벤트를 **평가**하여 해당 item/component 에 존재할 수 있는 **약점(weakness)을 식별**한다. 이벤트가 실제 제품 구성에 어떤 결함·노출을 의미하는지 분석하여 후속 취약점 분석으로 연결한다.

## 2. 수행 주체
- **주 수행자**: 보안 분석가 (Security Analyst)
- **검토자**: Cybersecurity Manager (CSM)
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
PRO-VCSMS-01-03 §5 단계 3 에 적용한다. 사이버보안 이벤트 평가·약점 식별(§8.4 [RQ-08-04])을 다룬다. 이벤트 판별은 선행 [[WI-VCSMS-01-03-02_정보_수집_트리아지_및_이벤트_판별]] 전제(entry_gate). 약점의 취약점 여부 분석은 [[WI-VCSMS-01-03-04_약점_분석_및_취약점_식별]] 로 이어진다.

## 4. 입력 자료 / 산출물
- **Input**
  - 확정된 사이버보안 이벤트([[WI-VCSMS-01-03-02_정보_수집_트리아지_및_이벤트_판별]] 산출물)
  - 영향 item/component 의 설계·아키텍처·구성 정보
  - (해당 시) 기존 TARA 산출물·사이버보안 케이스(PRO-VCSMS-02 계열)
  - ISO/SAE 21434 §8.4 [RQ-08-04] 요건
- **Output**
  - 이벤트 평가 결과
  - 식별된 약점 목록 (WP-08-04) — 위치·성격·관련 자산
  - [[TMP-VCSMS-01-03-03-01_이벤트_평가_및_약점_식별서]] 작성분

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. entry_gate 확인: WI-VCSMS-01-03-02 가 `done`(이벤트 확정) 인지 확인.
2. 영향 item/component 의 설계·구성·인터페이스 정보를 수집.
3. 기존 TARA·케이스에서 관련 자산·위협 시나리오를 조회.

### 5.2 수행 단계
1. **이벤트 컨텍스트 분석**
   - 이벤트가 가리키는 결함·악용 기법·영향 범위를 분석하고 영향 자산에 매핑.
2. **약점 식별** ([RQ-08-04])
   - 이벤트에 비추어 item/component 에 존재 가능한 약점(설계·구현·구성 결함)을 식별.
   - 각 약점의 위치(컴포넌트·인터페이스)·성격·관련 자산을 기술.
   - [[TMP-VCSMS-01-03-03-01_이벤트_평가_및_약점_식별서]] 에 기록.
3. **기존 분석 대조**
   - 기존 TARA·케이스의 자산·위협 시나리오와 대조하여 신규성 여부·기존 통제 적용 여부 확인.
4. **영향 잠정 평가**
   - 약점이 실현될 경우의 잠정 영향(안전·운영·재무·프라이버시)을 약식 평가하여 우선순위화.
5. **CSM 검토·승인**
   - CSM 이 약점 식별의 완전성(이벤트 대비 누락 없음)을 검토·승인.
6. **연계**
   - 식별된 약점을 약점 분석(WI-01-03-04)으로 연계.

### 5.3 완료 조건
- [ ] 이벤트 컨텍스트(결함·기법·영향 범위) 분석·자산 매핑 완료
- [ ] 약점별 위치·성격·관련 자산 기술
- [ ] 기존 TARA·케이스 대조(신규성·기존 통제 적용 여부)
- [ ] 약점 실현 시 잠정 영향 약식 평가·우선순위화
- [ ] CSM 약점 식별 완전성 검토·승인
- [ ] 약점 분석(WI-01-03-04) 연계 완료

## 6. 인터페이스 부서
- **설계/개발 부서**: item/component 설계·구성 정보 제공
- **TARA 운영(PRO-VCSMS-02-03)**: 기존 자산·위협 시나리오 참조
- **사고대응(PRO-01-04)**: 긴급 약점 시 연계

## 7. 주의사항 / 예외 처리

### 7.1 설계 정보 부족(공급사 컴포넌트)
- 영향 컴포넌트의 설계 정보가 부족한 경우(OTS·공급사):
  - 공급사에 정보를 요청(CIA·§7 연계)하고, 가용 정보 한도 내에서 약점을 보수적으로 식별.
  - 정보 부족과 잔존 불확실성을 기록.

### 7.2 다수 약점·연쇄 영향
- 하나의 이벤트가 다수 약점·연쇄 영향을 시사하는 경우:
  - 약점을 개별 식별하되 연쇄 관계(체인)를 함께 기록하여 분석 단계에서 종합 평가.

### 7.3 긴급 약점(악용 가능·운영 중)
- 운영 중 즉시 악용 가능한 약점을 식별한 경우:
  - 분석 완료를 기다리지 않고 사고대응(PRO-01-04)·취약점 즉시 처리를 병행 가동.

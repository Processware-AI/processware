# 보안 이슈 처리·변경영향 검토·교차통지 (WI-MDCS-01-05-04)

> 상위 절차: [[PRO-MDCS-01-05_보안_문제해결_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
분석된 취약점에 대해 문제해결(패치)과 의도된 환경 명세 갱신 중 적절한 처리를 결정하고, 변경이 안전·보안·유효성에 미치는 영향을 검토하며, 교차 제품·제3자에게 통지하여, 취약점을 추적 가능하게 처리한다. (9.5-REQ-001~005)

## 2. 수행 주체
- **주 수행자**: 개발자
- **검토자**: 보안책임자(PSO)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-01-05 §5 단계4(처리)에 적용한다. **선행조건**: WI-MDCS-01-05-03(분석) 완료. 처리 결과는 검증(PRO-MDCS-01-03)·공개(WI-MDCS-01-05-05)로 연계된다.

## 4. 입력 자료 / 산출물
- **Input**
  - 분석 보고서(WI-MDCS-01-05-03)
  - 위협 모델·환경 명세(PRO-MDCS-02-01)
  - 교차 제품·제3자 컴포넌트 정보
- **Output**
  - [[TMP-MDCS-01-05-04-01_보안이슈_처리_및_통지기록_v0.1]] 작성분
  - 처리 결정(패치/환경 명세 갱신)·변경 영향 검토
  - 교차·제3자 통지 기록

## 5. 수행 절차

### 5.1 사전 준비
1. 분석 결과와 권고 처리 방향을 확인한다.
2. 변경 영향 검토 범위(안전·보안·유효성)를 정한다.

### 5.2 수행 단계
1. **처리 방식 결정**
   - 문제해결(패치) vs 의도된 환경 명세 갱신(보안 가정 변경) 중 적절한 방식을 결정한다.
2. **변경 영향 검토**
   - 처리 변경이 안전·보안·유효성에 미치는 영향을 검토한다(신규 리스크 식별).
3. **처리 실행 연계**
   - 패치는 변경통제(WI-MDCS-01-04-01)·검증(PRO-MDCS-01-03)으로, 환경 갱신은 위협 모델·동반문서 갱신으로 연계한다.
4. **교차·제3자 통지**
   - 교차 제품 라인·영향 받는 제3자(공급자·통합사)에게 통지한다.
5. **검토·승인**
   - PSO 가 처리 적정성·영향 검토·통지 완전성을 승인한다.

### 5.3 완료 조건
- [ ] 처리 방식(패치/환경 명세 갱신) 결정·근거 기록
- [ ] 변경의 안전·보안·유효성 영향 검토(신규 리스크 식별)
- [ ] 패치는 변경통제·검증으로, 환경 갱신은 위협모델·동반문서로 연계
- [ ] 교차 제품·제3자 통지 완료
- [ ] PSO 검토·승인 기록 존재

## 6. 인터페이스 부서
- **WI-MDCS-01-04-01(변경통제)**: 패치 변경 등록
- **PRO-MDCS-01-03(유지보수)**: 패치 검증·배포
- **PRO-MDCS-02-01(리스크 관리)**: 신규 리스크·위협모델 갱신
- **WI-MDCS-01-05-05(공개)**: 공개 대상 연계

## 7. 주의사항 / 예외 처리

### 7.1 처리 변경의 신규 리스크
- 처리(패치·환경 갱신)가 새로운 보안 리스크를 만들면 이를 식별·평가하고 PRO-MDCS-02-01 로 반영하며, 수용 불가 시 대안을 모색한다.

### 7.2 환경 명세 갱신 선택 시
- 패치 대신 환경 명세 갱신(보안 가정 변경)을 택하면, 사용자에게 새로운 운영 요건을 동반문서로 명확히 전달한다(미전달 금지).

### 7.3 교차·제3자 통지 실패
- 영향 받는 제3자에게 통지가 도달하지 못하면 대체 경로를 사용하고, 안전 영향이 큰 경우 규제 통지(WI-MDCS-01-05-05)를 병행한다.

### 7.4 처리 지연
- 수용 가능 잔여 리스크로 즉시 처리하지 않는 경우, 정식 승인·정기 검토(WI-MDCS-01-05-06) 대상으로 등록한다.

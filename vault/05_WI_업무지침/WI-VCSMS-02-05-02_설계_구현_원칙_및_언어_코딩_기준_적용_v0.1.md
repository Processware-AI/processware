# 설계·구현 원칙 및 언어·코딩 기준 적용 (WI-VCSMS-02-05-02)

> 상위 절차: [[PRO-VCSMS-02-05_제품개발_사이버보안_엔지니어링_절차]] · 상위 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
설계·모델링·프로그래밍 표기/언어 선정 시 명확성·모듈성·보안기법·복원력 등 사이버보안 기준을 고려하고, 언어가 충족하지 못하는 기준을 가이드라인·개발환경으로 보완하며, 약점 도입을 회피·최소화하는 검증된 설계·구현 원칙을 적용하여 구현 단계의 약점 유입을 줄인다.

## 2. 수행 주체
- **주 수행자**: 개발자
- **검토자**: 보안 설계자
- **승인자**: 보안 설계자

## 3. 범위
ISO/SAE 21434 §10.4.1([RQ-10-04], [RQ-10-05], [RC-10-06])에 적용한다. 본 지침은 표기·언어 선정 기준과 보완 가이드라인·원칙 적용을 다룬다. 약점 식별 분석은 후속 WI-05-03 가 담당한다.

## 4. 입력 자료 / 산출물
- **Input**
  - [[TMP-VCSMS-02-05-01-01_사이버보안_사양서]] (할당 사양)
  - 조직 코딩 가이드라인·정적분석 도구 설정·개발환경 기준
- **Output**
  - [[TMP-VCSMS-02-05-02-01_언어_코딩_기준_적용_확인서]] 작성분 (WP-10-03)

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 사양서(WP-10-01)에서 본 컴포넌트에 할당된 사양을 확인한다(entry_gate WI-05-01 done).
2. 적용 대상 언어·표기·개발환경과 조직 코딩 가이드라인을 식별한다.
3. 적용 확인서 양식([[TMP-VCSMS-02-05-02-01_언어_코딩_기준_적용_확인서]])을 발번한다.

### 5.2 수행 단계
1. **표기·언어 선정 기준 평가** ([RQ-10-04])
   - 선정 언어·표기에 대해 명확성·모듈성·보안기법 지원·복원력 등 기준 충족 여부를 평가한다.
2. **보완 가이드라인·환경 결정** ([RQ-10-05])
   - 언어가 충족하지 못하는 기준에 대해 코딩 가이드라인·정적분석 규칙·개발환경 설정으로 보완 방안을 결정한다.
3. **검증된 설계·구현 원칙 적용** ([RC-10-06], 권고)
   - 입력 검증·최소권한·안전한 기본값 등 검증된 원칙을 적용하고 적용 항목을 기록한다.
4. **적용 점검**
   - 정적분석·코드리뷰 체크리스트로 가이드라인 준수를 점검하고 위반 항목을 기록·시정한다.
5. **검토·승인**
   - 보안 설계자 검토를 받고 적용 확인서를 확정한다.

### 5.3 완료 조건
- [ ] entry_gate(WI-05-01 done) 충족 확인
- [ ] 언어·표기 선정 기준 평가 완료
- [ ] 미충족 기준에 보완 가이드라인·환경 결정
- [ ] 검증된 설계·구현 원칙 적용 항목 기록([RC-10-06])
- [ ] 정적분석·코드리뷰 위반 항목 시정 완료
- [ ] 보안 설계자 승인 기록 확보

## 6. 인터페이스 부서
- **보안 설계자**: 아키텍처 약점 분석에 본 적용 결과 활용([[WI-VCSMS-02-05-03_아키텍처_약점_분석]])
- **품질/도구팀**: 정적분석 도구·개발환경 운영([RQ-05-14] 도구관리 경계면 참조)

## 7. 주의사항 / 예외 처리

### 7.1 레거시 언어 제약
- 사양상 변경 불가한 레거시 언어가 기준을 충족 못하면, 가이드라인·정적분석·런타임 보호로 보완하고 잔존 제약을 약점 분석(WI-05-03) 입력으로 등록한다.

### 7.2 권고 원칙 미적용
- [RC-10-06] 권고 원칙을 미적용하는 경우, 미적용 근거를 적용 확인서에 명시한다(권고이나 미적용 시 추적 필요).

### 7.3 가이드라인 위반 미시정
- 정적분석 위반이 일정 내 시정 불가하면, 잔존 위반을 약점으로 등록하고 약점 분석·검증(WI-05-03,06)에서 처리한다.

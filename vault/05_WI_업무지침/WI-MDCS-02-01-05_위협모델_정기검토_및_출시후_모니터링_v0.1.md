# 위협모델 정기 검토(연1회) 및 출시후 리스크 모니터링 (WI-MDCS-02-01-05)

> 상위 절차: [[PRO-MDCS-02-01_보안_리스크_관리_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-02_보안_리스크_관리_방침_v0.1]]

## 1. 업무 목적
위협 모델을 최소 연 1회 및 신규 위협 발생 시 검토·갱신하고, 출시 후 보안 정보를 수집하여 통제 효과를 검토하며, 교차 제품·제3자에 통지하여, 변화하는 위협 환경에 리스크 관리를 지속 유지한다. (7.2-REQ-004, 7.5)

## 2. 수행 주체
- **주 수행자**: 보안 검증 인력
- **검토자**: 보안책임자(PSO)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-02-01 §5 단계5(모니터링)에 적용한다. 연 1회 정기 + 신규 위협 발생 시 수행한다. 출시 후 운영 단계 전반에 적용한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 현 위협 모델(WI-MDCS-02-01-02)
  - 출시후 보안 정보(취약점 모니터링·사고·인텔리전스)(PRO-MDCS-01-03/05)
  - 리스크 통제 운영 데이터
- **Output**
  - [[TMP-MDCS-02-01-05-01_위협모델_정기검토_및_출시후_모니터링표_v0.1]] 작성분
  - 위협 모델 갱신 로그
  - 통제 효과 검토·교차/제3자 통지 기록

## 5. 수행 절차

### 5.1 사전 준비
1. 현 위협 모델·통제 운영 데이터를 확보한다.
2. 출시 후 보안 정보(취약점·사고·신규 공격 기법)를 수집한다.

### 5.2 수행 단계
1. **출시후 정보 검토**
   - 수집된 보안 정보로 신규 위협·변화를 식별한다.
2. **위협 모델 갱신**
   - 신규 위협을 위협 모델에 반영하고, 최소 연 1회 전체 검토를 수행한다.
3. **통제 효과 검토**
   - 운영 데이터로 기존 통제의 효과를 검토하고 약화된 통제를 보강한다.
4. **재평가 연계**
   - 변동된 리스크를 리스크 추정·평가(WI-MDCS-02-01-03)로 연계한다.
5. **교차·제3자 통지**
   - 신규 위협·통제 변화를 교차 제품·제3자에게 통지한다.
6. **검토·기록**
   - PSO 가 검토 수행·갱신 적정성을 승인하고 다음 검토 시점을 정한다.

### 5.3 완료 조건
- [ ] 출시후 보안 정보 수집·검토
- [ ] 위협 모델 갱신(연 1회 + 신규 위협 반영)
- [ ] 기존 통제 효과 검토·보강
- [ ] 변동 리스크 재평가 연계
- [ ] 교차 제품·제3자 통지
- [ ] PSO 검토·승인 및 다음 검토 시점 확정

## 6. 인터페이스 부서
- **PRO-MDCS-01-03(유지보수)**: 취약점 모니터링 정보
- **PRO-MDCS-01-05(문제해결)**: 사고·취약점 정보
- **WI-MDCS-02-01-02/03(위협 모델·평가)**: 갱신·재평가 연계
- **PRO-MDCS-01-01(정기 검토)**: 거버넌스 정기 검토 연계

## 7. 주의사항 / 예외 처리

### 7.1 검토 주기 누락
- 연 1회 검토가 누락될 우려가 있으면 정기 주기를 일정에 등록하고, 신규 중대 위협 발생 시 즉시 임시 검토한다.

### 7.2 통제 약화 발견
- 운영 중 통제가 약화(우회·무력화)된 것이 발견되면 즉시 보강하고, 영향이 크면 PRO-MDCS-01-05 로 처리한다.

### 7.3 신규 위협 폭증
- 신규 위협이 대량 발생하면 영향평가 기준으로 우선순위를 정해 위협 모델·통제를 단계적으로 갱신한다.

### 7.4 교차/제3자 통지 누락
- 교차 제품·제3자 통지가 누락되면 동일 위협이 타 제품에 잔존하므로, 통지 대상·완료를 체크리스트로 관리한다.

# 보안 시스템 시험(기능·위협완화·취약점·침투) (WI-MDCS-01-02-07)

> 상위 절차: [[PRO-MDCS-01-02_보안_SW_개발_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
통합된 헬스SW 에 대해 보안 기능을 검증하고, 위협 완화책의 효과를 시험하며, 취약점 시험(정적·동적·스캔)과 침투 시험을 수행하고 테스터의 객관성을 문서화하여, 릴리스 전 시스템 수준의 보안을 확인한다. (5.7.1, 5.7.2, 5.7.3, 5.7.4, 5.7.5)

## 2. 수행 주체
- **주 수행자**: 보안 테스터(개발과 객관성 확보)
- **검토자**: 검토자(독립)
- **승인자**: 검토자(독립)

## 3. 범위
PRO-MDCS-01-02 §5 단계7(시스템 시험)에 적용한다. **선행조건**: WI-MDCS-01-02-05(구현) 완료. 릴리스 전 필수 수행하며, 발견 사항은 PRO-MDCS-01-05 로 종결해야 한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 통합본(또는 시스템 빌드)
  - 보안 요구명세(WI-MDCS-01-02-02)
  - 위협 모델·완화 목록(PRO-MDCS-02-01)
- **Output**
  - [[TMP-MDCS-01-02-07-01_보안_시스템시험_계획_및_보고서_v0.1]] 작성분
  - 시험 계획·케이스(기능·완화·취약점·침투)
  - 시험 보고서·스캔/SCA/침투 보고서
  - 테스터 객관성 문서

## 5. 수행 절차

### 5.1 사전 준비
1. 보안 요구·위협 완화 목록을 시험 추적 매트릭스로 정리한다.
2. 테스터의 개발 독립성·객관성을 확인하고 문서화한다(이해상충 관리).
3. 시험 환경·도구(동적분석·스캐너·침투 도구)를 준비한다.

### 5.2 수행 단계
1. **보안 기능 시험**
   - 각 보안 요구의 기능이 정상 동작하는지 검증한다.
2. **위협 완화 효과 시험**
   - 각 위협 완화책이 의도한 위협을 실제로 차단하는지 시험한다.
3. **취약점 시험**
   - 정적분석·의존성 스캔·동적분석으로 취약점을 탐지한다.
4. **침투 시험**
   - 공격자 관점에서 침투 시험을 수행하고 악용 가능성을 평가한다.
5. **발견 처리**
   - 모든 발견을 PRO-MDCS-01-05(문제해결)로 등록·처리하고 종결을 추적한다.
6. **검토 승인**
   - 독립 검토자가 시험 커버리지·객관성·발견 종결을 검토·승인한다.

### 5.3 완료 조건
- [ ] 모든 보안 요구·위협 완화에 시험 케이스가 매핑됨(작성률 100%)
- [ ] 기능·완화·취약점·침투 시험 실행 완료
- [ ] 테스터 객관성(개발 독립성) 문서화
- [ ] 모든 발견이 PRO-MDCS-01-05 로 등록·추적됨
- [ ] 미해결(고위험) 발견 0건(릴리스 전)
- [ ] 독립 검토자 검토·승인 기록 존재

## 6. 인터페이스 부서
- **PRO-MDCS-01-05(문제해결)**: 발견 등록·처리
- **PRO-MDCS-02-01(리스크 관리)**: 완화 효과·신규 리스크 피드백
- **WI-MDCS-01-02-08(릴리스)**: 시험 결과 이관

## 7. 주의사항 / 예외 처리

### 7.1 테스터 객관성 부족
- 동일 인력이 개발·시험을 겸하면 이해상충을 관리한다(가능하면 분리, 불가 시 독립 검토자 교차 확인). 객관성 확보 수준을 문서화한다(5.7.5).

### 7.2 침투 시험 범위·법적 제약
- 침투 시험은 사전 승인된 범위·환경에서만 수행하고, 운영 환경·실데이터 사용을 금지한다. 외부 전문가 활용 시 계약·범위를 문서화한다.

### 7.3 미해결 발견과 릴리스
- 고위험 발견이 미해결이면 릴리스(WI-MDCS-01-02-08)를 진행할 수 없다. PRO-MDCS-01-05 로 종결하거나 수용 가능 잔여 리스크로 정식 승인받아야 한다.

### 7.4 완화 효과 미입증
- 위협 완화책이 시험에서 효과를 입증하지 못하면 완화책을 재설계(WI-MDCS-01-02-04)하거나 추가 통제를 도입하고 재시험한다.

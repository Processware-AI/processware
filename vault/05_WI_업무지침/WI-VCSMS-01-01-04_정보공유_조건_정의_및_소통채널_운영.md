# 정보공유 조건 정의 및 소통채널 운영 (WI-VCSMS-01-01-04)

> 상위 절차: [[PRO-VCSMS-01-01_조직_사이버보안_거버넌스_운영_절차]] · 상위 정책: [[POL-VCSMS-01_자동차_사이버보안_거버넌스_정책]]

## 1. 업무 목적
내부·외부 사이버보안 정보공유의 **요구/허용/금지 상황을 정의**하고, 인접·연계 분야를 식별하여 **소통채널을 수립·운영**한다. 공유 데이터의 정보보안 관리를 타 당사자와 정렬하여, 적시 정보교환과 정보보호를 동시에 달성한다.

## 2. 수행 주체
- **주 수행자**: Process Owner
- **검토자**: Cybersecurity Manager (CSM)
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
PRO-VCSMS-01-01 §5 단계 5·7 에 적용한다. 인접 분야 식별·소통채널 수립(§5.4.1 [RQ-05-05]), 정보공유 요구/허용/금지 정의(§5.4.3 [RQ-05-09]), 공유 데이터 정보보안 정렬([RC-05-10], should)을 다룬다. 정보보안 관리시스템(ISMS) 자체는 §5.4.6 상위 참조(interface_only). 정책·규칙 수립은 선행 [[WI-VCSMS-01-01-01_사이버보안_정책_규칙_프로세스_수립]] 전제.

## 4. 입력 자료 / 산출물
- **Input**
  - 승인된 사이버보안 정책([[WI-VCSMS-01-01-01_사이버보안_정책_규칙_프로세스_수립]] 산출물)
  - 조직 맵(인접 분야: 기능안전·품질·법무·홍보·공급망·규제기관·ISAC 등)
  - ISO/SAE 21434 §5.4.1·5.4.3 [RQ-05-05·09], [RC-05-10] 요건
- **Output**
  - 정보공유 규칙(요구/허용/금지 매트릭스)
  - 소통채널 정의서(채널·당사자·트리거·정보보안 등급)
  - [[TMP-VCSMS-01-01-04-01_정보공유_규칙_및_소통채널_정의서]] 작성분

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. entry_gate 확인: WI-VCSMS-01-01-01 이 `done`(정책 승인) 인지 확인.
2. 조직 내·외 인접 분야와 정보교환 당사자 목록 작성(내부: 기능안전·품질·법무, 외부: 공급망·규제기관·ISAC·CERT).
3. 정보보안 분류 기준(상위 ISMS) 확보.

### 5.2 수행 단계
1. **인접 분야 식별·통합 방안** ([RQ-05-05])
   - 사이버보안과 연계되는 인접 분야를 식별하고, 기존 프로세스 통합 방안·정보교환 조율 방식을 정의.
2. **정보공유 조건 정의** ([RQ-05-09])
   - 정보 유형별로 공유가 **요구(의무)/허용/금지**되는 상황을 매트릭스로 정의.
   - 예: 취약점 정보의 대외 공개 조건, 사고 정보의 규제기관 통보 의무, 영업비밀 금지 항목.
   - [[TMP-VCSMS-01-01-04-01_정보공유_규칙_및_소통채널_정의서]] 의 정보공유 매트릭스에 기록.
3. **소통채널 수립**
   - 각 당사자와의 소통채널(정기 회의·핫라인·포털·표준 인터페이스)을 정의.
   - 채널별 트리거(언제 가동), 책임자, 정보보안 등급을 명시.
4. **정보보안 정렬** ([RC-05-10], should)
   - 공유 데이터의 보호 수준을 타 당사자와 합의(분류·암호화·접근통제).
   - 상위 ISMS 정책과 정합(§5.4.6 참조, 중복 생성 금지).
5. **검토·승인**
   - CSM 이 규칙·채널의 완전성·법규 정합(개인정보·영업비밀·규제 통보 의무)을 검토·승인.
6. **운영·배포**
   - 정의서를 관련 당사자에 배포하고 채널을 가동.
   - 위반 모니터링 체계를 운영(KPI: 정보공유 규칙 위반 0건).

### 5.3 완료 조건
- [ ] 인접 분야·정보교환 당사자 목록 작성 및 통합 방안 정의
- [ ] 정보 유형별 요구/허용/금지 매트릭스 완성
- [ ] 소통채널별 트리거·책임자·정보보안 등급 명시
- [ ] 공유 데이터 정보보안 정렬(분류·보호 수준) 합의 및 상위 ISMS 정합
- [ ] 법규 통보 의무(규제기관·고객) 반영 확인
- [ ] CSM 검토·승인 및 채널 가동·배포 완료

## 6. 인터페이스 부서
- **ISMS 부서(§5.4.6)**: 정보보안 분류·보호 정본 — 본 지침은 정렬만
- **법무**: 통보 의무·영업비밀·개인정보 법규 검토
- **홍보/대외**: 대외 공개·공시 창구
- **공급망/구매**: 외부 당사자 정보교환(CIA 연계, §7.4.3)

## 7. 주의사항 / 예외 처리

### 7.1 법규 통보 의무 충돌
- 정보공유 금지(영업비밀)와 규제 통보 의무가 충돌하는 경우:
  - 법무 검토를 거쳐 법규 의무를 우선(통보)하되 공개 범위를 최소화.
  - 충돌 사례를 정의서에 등록하여 후속 판단 기준화.

### 7.2 긴급 정보공유(사고·취약점)
- 사고·중대 취약점으로 즉시 공유가 필요한 경우:
  - 사전 정의된 핫라인·긴급 채널을 가동(사고대응 PRO-01-04·지속활동 PRO-01-03 연계).
  - 사후 정의서에 가동 이력 기록.

### 7.3 외부 당사자 정보보안 미정렬
- 외부 당사자가 합의된 보호 수준을 충족하지 못하는 경우:
  - 공유 범위를 축소하거나 추가 보호조치(익명화·접근 제한)를 조건화.
  - 미정렬 리스크를 CSM 에 보고.

# 갭 종결 활동 수행(보안요구·시험·위협모델·리스크통제·운영지침) (WI-MDCS-01-06-02)

> 상위 절차: [[PRO-MDCS-01-06_과도기_헬스SW_관리_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
갭 분석에서 식별된 미충족 항목을 종결하기 위해 시스템 보안 요구·시스템 시험·보안 맥락/위협 모델·리스크 통제·운영/계정 지침을 보완 생성하고, 전체 잔여 보안 리스크를 평가하여, 전환SW 의 Annex F 적합 수준을 끌어올린다. (F.2-REQ-003)

## 2. 수행 주체
- **주 수행자**: 개발자
- **검토자**: 보안책임자(PSO)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-01-06 §5 단계2(갭 종결)에 적용한다. **선행조건**: WI-MDCS-01-06-01(갭 분석) 완료. 갭 분석에서 도출된 갭 목록을 대상으로 한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 갭 분석 보고서(WI-MDCS-01-06-01)
  - 기존 산출물·제품 구성
  - 관련 활동 지침(WI-MDCS-01-02-*, WI-MDCS-02-01-*)
- **Output**
  - [[TMP-MDCS-01-06-02-01_갭_종결_활동_기록표_v0.1]] 작성분
  - 보완 생성된 보안 산출물(요구·시험·위협모델·통제·운영지침)
  - 전체 잔여 보안 리스크 평가

## 5. 수행 절차

### 5.1 사전 준비
1. 갭 목록과 종결 우선순위를 확인한다.
2. 보완 활동에 필요한 표준 활동 지침을 식별한다.

### 5.2 수행 단계
1. **보안 요구 보완**
   - 시스템 보안 요구를 생성한다(WI-MDCS-01-02-02 재사용).
2. **시스템 시험 보완**
   - 취약점·침투를 포함한 시스템 시험을 수행한다(WI-MDCS-01-02-07 재사용).
3. **보안 맥락·위협 모델 보완**
   - 보안 맥락·위협 모델을 작성한다(WI-MDCS-02-01-01·02 재사용).
4. **리스크 통제 보완**
   - 리스크 통제를 선정·구현·검증한다(WI-MDCS-02-01-04 재사용).
5. **운영/계정 지침 보완**
   - 운영·계정 관리 지침을 동반문서에 반영한다.
6. **전체 잔여 리스크 평가**
   - 종결 후 전체 잔여 보안 리스크를 평가한다.
7. **검토·승인**
   - PSO 가 갭 종결 완전성·잔여 리스크를 검토·승인한다.

### 5.3 완료 조건
- [ ] 갭 목록의 각 갭에 대해 종결 활동 수행
- [ ] 보안 요구·시스템 시험·위협 모델·리스크 통제·운영지침 산출물 보완
- [ ] 미종결 갭은 사유·보완 통제·잔여 리스크로 처리
- [ ] 전체 잔여 보안 리스크 평가 수행
- [ ] PSO 검토·승인 기록 존재

## 6. 인터페이스 부서
- **PRO-MDCS-01-02(개발)**: 요구·시험 활동 재사용
- **PRO-MDCS-02-01(리스크 관리)**: 위협 모델·통제·잔여 리스크
- **WI-MDCS-01-06-03(정당화)**: 잔여 리스크 연계

## 7. 주의사항 / 예외 처리

### 7.1 종결 불가 갭
- 레거시 제약으로 종결이 불가한 갭은 보완 통제·잔여 리스크로 처리하고 WI-MDCS-01-06-03(계속 사용 정당화)에서 정당화한다.

### 7.2 시험 중 신규 취약점 발견
- 시스템 시험 보완 중 신규 취약점이 발견되면 PRO-MDCS-01-05(문제해결)로 처리하고 종결을 추적한다.

### 7.3 안전·유효성 영향
- 갭 종결 조치가 안전·유효성에 영향을 주면 제품 리스크 관리와 협력하여 평가한다.

### 7.4 종결 범위 변동
- 종결 중 추가 갭이 발견되면 갭 목록을 갱신하고 WI-MDCS-01-06-01 갭 분석을 보완한다.

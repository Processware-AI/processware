# 사이버보안 목표·클레임 도출 (WI-VCSMS-02-04-03)

> 상위 절차: [[PRO-VCSMS-02-04_컨셉_단계_사이버보안_엔지니어링_절차]] · 상위 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
리스크 처리 결정([[WI-VCSMS-02-04-02_TARA_수행_호출_및_처리_옵션_결정]])에 따라, 감소 결정 위협에는 사이버보안 목표를, 공유·(가정기반)보유 결정 위협에는 사이버보안 클레임을 명시하여, 후속 컨셉·요구의 상위 기준을 확정한다.

## 2. 수행 주체
- **주 수행자**: Project CS Lead
- **검토자**: 보안 설계자
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
ISO/SAE 21434 §9.4([RQ-09-05], [RQ-09-06])에 적용한다. 목표·클레임은 위협 시나리오와 1:1 또는 1:N 추적이 가능해야 하며, 본 지침은 그 도출·기술·추적 연결까지 다룬다.

## 4. 입력 자료 / 산출물
- **Input**
  - [[TMP-VCSMS-02-04-02-01_리스크_처리_결정서]] 확정본 (목표/클레임 분기 표식 포함)
  - [[TMP-VCSMS-02-04-01-01_아이템_정의서]] (운용환경 가정·전제)
- **Output**
  - [[TMP-VCSMS-02-04-03-01_사이버보안_목표_클레임_명세서]] 작성분 (WP-09-03,04)

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 리스크 처리 결정서가 CSM 승인 완료(WI-04-02) 상태인지 확인한다(entry_gate).
2. 분기 표식(목표/클레임)을 위협 시나리오별로 추출한다.
3. 목표·클레임 명세서 양식([[TMP-VCSMS-02-04-03-01_사이버보안_목표_클레임_명세서]])을 발번한다.

### 5.2 수행 단계
1. **사이버보안 목표 명시** ([RQ-09-05])
   - 감소 결정 위협마다 달성하고자 하는 보안 상태(목표)를 명시한다.
   - 각 목표에 식별자(CG-##)를 부여하고 대응 위협 시나리오를 추적 연결한다.
2. **사이버보안 클레임 명시** ([RQ-09-06])
   - 공유·(가정기반)보유 결정 위협마다 클레임(가정·외부 책임 전제)을 명시한다.
   - 각 클레임에 식별자(CC-##)를 부여하고 근거 가정(아이템 정의 §4.1)을 연결한다.
3. **목표·클레임 속성 기술**
   - 각 목표·클레임에 대상 자산·보안속성(기밀성·무결성·가용성 등)·수용 잔여리스크를 기술한다.
4. **추적성 확인**
   - 모든 감소 위협이 목표로, 모든 공유·보유 위협이 클레임으로 빠짐없이 전환되었는지 대조한다.
5. **검토·승인**
   - 보안 설계자 검토를 반영하고 CSM 승인을 받는다.

### 5.3 완료 조건
- [ ] entry_gate(WI-04-02 done) 충족 확인
- [ ] 모든 감소 위협 → 목표(CG-##) 전환(누락 0)
- [ ] 모든 공유·보유 위협 → 클레임(CC-##) 전환(누락 0)
- [ ] 각 목표·클레임에 대상 자산·보안속성 기술
- [ ] 위협↔목표/클레임 추적성 대조 완료
- [ ] CSM 승인 기록 확보

## 6. 인터페이스 부서
- **보안 설계자**: 목표·클레임을 컨셉·요구 도출 입력으로 인수([[WI-VCSMS-02-04-05_사이버보안_컨셉_요구사항_정의_및_할당]])
- **CSM**: 목표·클레임 승인

## 7. 주의사항 / 예외 처리

### 7.1 분기 누락 위협 발견
- 처리 결정서에 분기 표식이 없는 위협을 발견하면, WI-04-02 로 반려하여 처리 옵션·분기를 보완받는다.

### 7.2 클레임 가정 미존재
- 클레임의 근거 가정이 아이템 정의에 없으면, 임의 가정 생성 금지. 아이템 정의서(WI-04-01)에 가정을 추가 등록한 뒤 클레임을 도출한다.

### 7.3 목표 측정 불가
- 목표가 정성적이어서 후속 검증이 곤란하면, 검증 가능한 형태(보안속성·임계조건)로 재기술하고 검증 기준을 명시한다.

# 컨셉 검증 (WI-VCSMS-02-04-06)

> 상위 절차: [[PRO-VCSMS-02-04_컨셉_단계_사이버보안_엔지니어링_절차]] · 상위 정책: [[POL-VCSMS-02_차량_사이버보안_엔지니어링_정책]]

## 1. 업무 목적
정의된 통제·사이버보안 요구·할당 결과가 사이버보안 목표·클레임에 대해 완전·정확·일관함을 검증하여, 컨셉 단계 산출물을 제품개발(Clause 10)로 전달하기에 충분함을 확인한다.

## 2. 수행 주체
- **주 수행자**: Project CS Lead
- **검토자**: 보안 설계자
- **승인자**: Cybersecurity Manager (CSM)

## 3. 범위
ISO/SAE 21434 §9.5([RQ-09-11])에 적용한다. 컨셉 단계의 최종 검증으로, 통과 시 산출물을 [[PRO-VCSMS-02-05_제품개발_사이버보안_엔지니어링_절차]]로 전달한다. 미통과 시 WI-04-05(또는 상위)로 재작업 연계를 다룬다.

## 4. 입력 자료 / 산출물
- **Input**
  - [[TMP-VCSMS-02-04-05-01_사이버보안_컨셉_및_요구사항_명세서]]
  - [[TMP-VCSMS-02-04-03-01_사이버보안_목표_클레임_명세서]] (대비 기준)
- **Output**
  - [[TMP-VCSMS-02-04-06-01_컨셉_검증보고서]] 작성분 (WP-09-07)
  - 개발 전달 결정 기록

## 5. 수행 절차 (단계별)

### 5.1 사전 준비
1. 컨셉·요구 명세서가 CSM 승인 완료(WI-04-05 done) 상태인지 확인한다(entry_gate).
2. 검증 기준(목표·클레임 명세서)과 검증 대상(컨셉·요구 명세서)을 정렬한다.
3. 검증보고서 양식([[TMP-VCSMS-02-04-06-01_컨셉_검증보고서]])을 발번한다.

### 5.2 수행 단계
1. **완전성 검증** ([RQ-09-11])
   - 모든 목표·클레임이 통제·요구로 빠짐없이 다뤄졌는지 점검한다.
   - 모든 요구가 할당되었는지 점검한다.
2. **정확성 검증** ([RQ-09-11])
   - 통제·요구가 대응 목표를 실제로 달성하는지(논리적 충분성) 점검한다.
3. **일관성 검증** ([RQ-09-11])
   - 통제·요구 간, 할당 간 상충이 없는지 점검한다.
4. **부적합 기록·판정**
   - 부적합을 기록하고 통과/조건부/미통과를 판정한다.
   - 미통과 시 재작업 대상 WI 를 지정한다.
5. **개발 전달 결정**
   - 통과 시 산출물을 제품개발 절차로 전달하도록 결정·기록한다.
6. **검토·승인**
   - 보안 설계자 검토를 반영하고 CSM 승인을 받는다.

### 5.3 완료 조건
- [ ] entry_gate(WI-04-05 done) 충족 확인
- [ ] 완전성 점검 완료(미다룸 목표/클레임 0, 미할당 요구 0)
- [ ] 정확성 점검 완료(논리적 충분성 확인)
- [ ] 일관성 점검 완료(상충 0)
- [ ] 부적합 기록 및 판정 명시
- [ ] (통과 시)개발 전달 결정 기록
- [ ] CSM 승인 기록 확보

## 6. 인터페이스 부서
- **제품개발팀**: 통과 산출물 인수([[PRO-VCSMS-02-05_제품개발_사이버보안_엔지니어링_절차]])
- **보안 설계자/Project CS Lead**: 미통과 시 재작업 인수

## 7. 주의사항 / 예외 처리

### 7.1 컨셉 검증 미통과
- 미통과 시 개발 전달을 차단하고 지정 선행 WI 로 반려한다. 재작업 후 본 검증을 재수행한다.

### 7.2 선행 조건부 부적합 미해소
- WI-04-04 에서 조건부 통과로 이연된 부적합이 해소되지 않았으면, 컨셉 검증을 통과로 판정할 수 없다. 해소 또는 정식 리스크 수용(CSM 결정) 후 진행한다.

### 7.3 부분 전달(테일러링)
- 일부 컴포넌트만 개발 준비된 경우, 전달 가능한 부분만 분리 전달하고 미준비분의 전달 시점·조건을 명시한다([[PRO-VCSMS-02-01_프로젝트_사이버보안_관리_절차]] 테일러링 연계).

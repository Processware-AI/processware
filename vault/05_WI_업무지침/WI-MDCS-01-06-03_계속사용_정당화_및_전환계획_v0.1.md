# 계속 사용 정당화 및 완전 적합 전환 계획 수립 (WI-MDCS-01-06-03)

> 상위 절차: [[PRO-MDCS-01-06_과도기_헬스SW_관리_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
갭 종결 후 평가된 전체 잔여 보안 리스크에 근거하여 전환SW 의 계속 사용을 정당화·문서화하고, 비업그레이드 컴포넌트의 정당성을 기록하며, 릴리스 문서로 잔여 리스크를 사용자에게 전달하고, 완전 적합(Clause 6~9)으로의 전환 계획을 수립한다. (F.3-REQ-001~004, F.4-REQ-001)

## 2. 수행 주체
- **주 수행자**: 보안운영위원회(PSGB)
- **검토자**: 보안책임자(PSO)
- **승인자**: 보안운영위원회(PSGB)

## 3. 범위
PRO-MDCS-01-06 §5 단계3(정당화·전환 계획)에 적용한다. **선행조건**: WI-MDCS-01-06-02(갭 종결) 완료.

## 4. 입력 자료 / 산출물
- **Input**
  - 갭 종결 기록·전체 잔여 리스크 평가(WI-MDCS-01-06-02)
  - 비업그레이드 컴포넌트 목록
  - 릴리스 문서·동반문서
- **Output**
  - [[TMP-MDCS-01-06-03-01_계속사용_정당화_및_전환계획서_v0.1]] 작성분
  - 계속 사용 정당화 문서(버전·잔여 리스크 근거)
  - 완전 적합 전환 계획(Clause 6~9 충족 일정)

## 5. 수행 절차

### 5.1 사전 준비
1. 갭 종결 결과·전체 잔여 리스크를 확인한다.
2. 비업그레이드 컴포넌트와 그 정당성 근거를 정리한다.

### 5.2 수행 단계
1. **계속 사용 정당화**
   - 대상 버전과 전체 잔여 리스크를 근거로 계속 사용 정당성을 문서화한다.
2. **비업그레이드 정당성**
   - 업그레이드하지 않은 컴포넌트의 정당성·리스크를 문서화한다.
3. **잔여 리스크 전달**
   - 릴리스 문서·동반문서에 잔여 리스크를 명시하여 사용자에게 전달한다.
4. **전환 계획 수립**
   - 완전 적합(Clause 6~9 출시후 활동 포함)으로의 전환 일정·마일스톤을 수립한다.
5. **검토·승인**
   - PSO 검토 후 PSGB 가 정당화·전환 계획을 승인한다.

### 5.3 완료 조건
- [ ] 대상 버전·전체 잔여 리스크 근거의 계속 사용 정당화 문서화
- [ ] 비업그레이드 컴포넌트 정당성·리스크 문서화
- [ ] 릴리스 문서·동반문서에 잔여 리스크 전달 명시
- [ ] 완전 적합(Clause 6~9) 전환 계획·일정 수립
- [ ] PSO 검토·PSGB 승인 기록 존재

## 6. 인터페이스 부서
- **PRO-MDCS-02-01(리스크 관리)**: 잔여 리스크 정식 승인
- **WI-MDCS-01-01-05(동반문서)**: 잔여 리스크 전달 반영
- **PRO-MDCS-01-03/01-05(출시후 활동)**: 전환 계획 Clause 6~9 연계

## 7. 주의사항 / 예외 처리

### 7.1 정당화 불가(수용 불가 리스크)
- 잔여 리스크가 수용 불가하면 계속 사용을 정당화하지 않고 사용 중지·대체를 결정한다(무리한 정당화 금지).

### 7.2 잔여 리스크 미전달
- 잔여 리스크가 릴리스 문서·동반문서에 전달되지 않으면 출시·운영을 보류하고 보완한다.

### 7.3 전환 계획 지연
- 전환 계획 일정이 지연되면 사유·재계획을 PSGB 에 보고하고, 지연 기간 잔여 리스크를 재평가한다.

### 7.4 규제 요건 변화
- 전환 기간 중 규제 요건이 변경되면 정당화·전환 계획을 갱신하고 규제 통지(WI-MDCS-01-05-05)와 정합성을 맞춘다.

# 보안 업데이트 정책 수립(전달 시간대·영향평가 기준) (WI-MDCS-01-03-01)

> 상위 절차: [[PRO-MDCS-01-03_보안_SW_유지보수_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
출시된 헬스SW 의 보안 업데이트를 적시·일관되게 제공하기 위해, 업데이트 전달·검증 시간대(SLA)와 영향평가 기준(영향·인지도·익스플로잇 가능성·배포량·외부 통제 가용성)을 정책으로 규정한다. (6.1.1)

## 2. 수행 주체
- **주 수행자**: 보안책임자(PSO)
- **검토자**: 보안운영위원회(PSGB)
- **승인자**: 보안책임자(PSO)

## 3. 범위
PRO-MDCS-01-03 §5 단계1(정책 수립)에 적용한다. 제품/제품군 단위로 수립하고 규제 변화·제품 컨텍스트 변경 시 갱신한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 제품 컨텍스트(사용 환경·임상 중요도·배포 규모)
  - SW 분류표(MAINTAINED/SUPPORTED 구분)
  - 규제·계약상 대응 기한 요구
- **Output**
  - [[TMP-MDCS-01-03-01-01_보안_업데이트_정책서_v0.1]] 작성분
  - 전달·검증 시간대(SLA) 정의
  - 영향평가 기준·등급 체계

## 5. 수행 절차

### 5.1 사전 준비
1. 제품 컨텍스트와 SW 분류를 확인한다.
2. 규제·계약상 대응 기한 요구를 수집한다.

### 5.2 수행 단계
1. **영향평가 기준 정의**
   - 취약점 영향·인지도·익스플로잇 가능성·배포량·외부 통제 가용성을 평가 요소로 정의하고 등급화한다.
2. **전달·검증 SLA 설정**
   - 영향 등급별 검증·전달 목표 시간대(SLA)를 설정한다.
3. **분류별 대응 정의**
   - MAINTAINED(업데이트 제공)·SUPPORTED(안내) 별 대응 방식을 정의한다.
4. **검토·승인**
   - PSGB 검토 후 PSO 가 정책을 승인하고 배포한다.

### 5.3 완료 조건
- [ ] 영향평가 요소(5종)가 모두 정의·등급화됨
- [ ] 영향 등급별 전달·검증 SLA 설정
- [ ] MAINTAINED/SUPPORTED 별 대응 방식 정의
- [ ] PSGB 검토·PSO 승인 기록 존재
- [ ] 정책 배포 확인

## 6. 인터페이스 부서
- **규제/대외**: 규제 대응 기한 요구 제공
- **보안 운영**: SLA 운용 가능성 검토
- **PRO-MDCS-01-05(문제해결)**: 영향평가 기준 공유

## 7. 주의사항 / 예외 처리

### 7.1 SLA 충돌(규제 vs 운영)
- 규제 요구 기한이 운영 가능 SLA 보다 짧으면 규제 기한을 우선하고, 그 충족을 위한 자원·프로세스 보강을 계획한다.

### 7.2 영향평가 기준 모호
- 영향 등급 경계가 모호한 사례는 보수적으로 상위 등급으로 분류하고, 사례를 정책 개정 입력으로 축적한다.

### 7.3 SUPPORTED SW 업데이트 한계
- SUPPORTED SW 는 제조자가 직접 업데이트를 제공하지 못하므로, 정책에 안내·대체 완화책 제공 방식을 명시한다.

### 7.4 정책 미준수 발생
- 운영 중 SLA 미준수가 반복되면 PRO-MDCS-01-01(정기 검토)로 보고하여 정책·자원을 재검토한다.

# 보안 아키텍처 명세 및 방어심층화 검토 (WI-MDCS-01-02-03)

> 상위 절차: [[PRO-MDCS-01-02_보안_SW_개발_프로세스_절차_v0.1]] · 상위 방침: [[POL-MDCS-01_헬스SW_제품_보안_거버넌스_방침_v0.1]]

## 1. 업무 목적
보안 요구를 충족하는 안전 아키텍처를 명세하고, 방어 심층화(다층 방어) 관점에서 보안 통제를 계층별로 배정하며, 악조건(공격·오류) 하의 거동을 검토하여, 단일 통제 실패가 전체 보안 붕괴로 이어지지 않는 아키텍처를 확립한다. (5.3.1, 5.3.2, 5.3.3)

## 2. 수행 주체
- **주 수행자**: 보안 아키텍트
- **검토자**: 검토자(독립)
- **승인자**: 검토자(독립)

## 3. 범위
PRO-MDCS-01-02 §5 단계3(아키텍처)에 적용한다. **선행조건**: WI-MDCS-01-02-02(보안 요구) 완료. 아키텍처 중대 변경 시 재수행한다.

## 4. 입력 자료 / 산출물
- **Input**
  - 보안 요구명세(WI-MDCS-01-02-02)
  - 위협 모델(PRO-MDCS-02-01)
  - 제품 보안 맥락·신뢰경계 정보
- **Output**
  - [[TMP-MDCS-01-02-03-01_보안아키텍처_명세_및_검토보고서_v0.1]] 작성분
  - 보안 아키텍처 명세(컴포넌트·신뢰경계·통제 배치)
  - 방어심층화 계층 매핑
  - 아키텍처 검토 보고서(악조건 거동 포함)

## 5. 수행 절차

### 5.1 사전 준비
1. 보안 요구·위협 모델·보안 맥락을 확보한다.
2. 시스템의 주요 컴포넌트·데이터 흐름·신뢰경계를 식별한다.

### 5.2 수행 단계
1. **아키텍처 명세**
   - 컴포넌트·인터페이스·신뢰경계와 각 보안 통제의 배치를 명세한다.
2. **방어심층화 배정**
   - 각 위협에 대해 다층 방어(예방·탐지·복구) 계층에 통제를 배정하고, 단일 실패점을 식별·완화한다.
3. **요구-아키텍처 추적**
   - 각 보안 요구가 아키텍처의 어느 통제로 충족되는지 추적한다.
4. **악조건 거동 검토**
   - 공격·통제 실패·예외 입력 시 시스템 거동을 검토하고 안전 측 동작(fail-safe/fail-secure)을 확인한다.
5. **아키텍처 검토**
   - 독립 검토자가 방어심층화 충분성·요구 충족·악조건 거동을 검토하고 약점을 추적·종결한다.

### 5.3 완료 조건
- [ ] 컴포넌트·신뢰경계·통제 배치가 명세됨
- [ ] 위협별 방어심층화 계층 배정 및 단일 실패점 완화
- [ ] 모든 보안 요구가 아키텍처 통제로 추적됨
- [ ] 악조건(공격·실패·예외) 거동 검토 및 안전 측 동작 확인
- [ ] 독립 검토자의 아키텍처 검토·약점 종결 기록 존재

## 6. 인터페이스 부서
- **PRO-MDCS-02-01(리스크 관리)**: 위협 모델·신뢰경계 제공
- **개발팀**: 구현 제약·기술 타당성 협의
- **WI-MDCS-01-02-04(설계)**: 아키텍처를 설계로 구체화

## 7. 주의사항 / 예외 처리

### 7.1 단일 실패점 잔존
- 방어심층화가 불가능하여 단일 실패점이 남으면 사유·보완 통제·잔여 리스크를 문서화하고 PRO-MDCS-02-01 로 리스크를 반영한다.

### 7.2 요구-아키텍처 추적 단절
- 보안 요구를 충족할 아키텍처 통제가 없으면 아키텍처를 보완하거나 요구를 재검토(WI-MDCS-01-02-02)한다. 미해결 추적 단절 상태로 다음 단계 진행 금지.

### 7.3 외부/레거시 컴포넌트 제약
- 변경 불가한 외부·레거시 컴포넌트로 인해 통제 배치가 제약되면 경계 통제(격리·프록시·모니터링)로 보완하고 잔여 리스크를 기록한다.

### 7.4 위협 모델 갱신 반영
- 검토 중 신규 위협이 식별되면 PRO-MDCS-02-01 로 위협 모델 갱신을 요청하고 아키텍처를 재검토한다.

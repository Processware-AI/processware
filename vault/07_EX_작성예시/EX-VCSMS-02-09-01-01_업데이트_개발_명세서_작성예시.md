# 업데이트 개발 명세서 작성예시 (EX-VCSMS-02-09-01-01)

> 원본 양식: [[TMP-VCSMS-02-09-01-01_업데이트_개발_명세서]]

> ⚠️ 이 파일은 **교육·가이드용 샘플** 입니다. 실제 기록으로 사용하지 마세요. 실제 기록은 `08_REC_기록/` 에 REC 로 생성.

## 1. 업데이트 식별 (예시)
| 항목 | 예시값 |
|---|---|
| 업데이트 ID / 버전 | UPD-2026-TCU-031 / fw v3.2.1 |
| 트리거 유형 | 보안패치 |
| 긴급도 | 높음 (CVE 대응) |
| 작성자 / 작성일 | 한개발 (개발팀) / 2026-09-10 |
| 승인자(CSM) / 승인일 | 이보안 / 2026-09-14 |

## 2. 영향 범위 (예시)
| 대상 item/component | 차종 | VIN 범위 | 비고 |
|---|---|---|---|
| TCU Gen3 펌웨어 | EV-2026 북미향 | 2026-MY 전체 | 약 12만대 |

## 3. 업데이트 사이버보안 요구 (예시)
| 요구 ID | 내용 | 대상 취약점/위험 |
|---|---|---|
| UPR-031-01 | TLS 라이브러리 패치(버퍼 오버플로 제거) | CVE-2026-XXXX |
| UPR-031-02 | 패치 후 서명 검증 경로 무결성 유지 | 회귀 위험 |

## 4. 델타 영향 평가 (예시)
| 항목 | 내용 |
|---|---|
| 영향받는 기존 위협/자산 | 통신 채널(자산), 원격 코드 실행 위협 |
| 델타 TARA 수행 여부·결과 | 수행, 위협 잔존 리스크 등급 하향(High→Low) |
| 잔존 위험 | 패치 미적용 차량의 노출(배포 커버리지 의존) |

## 5. 업데이트 역량 요건 (예시)
| 역량 요건 | 충족 방식 | R156 정합 |
|---|---|---|
| 무결성·인증 배포 | 서명된 업데이트 패키지, 디바이스 서명 검증 | R156 §7 적합 |
| 롤백 | A/B 파티션 자동 롤백 | 적합 |
| 실패 안전(safe-state) | 업데이트 실패 시 이전 펌웨어 유지·재시도 | 적합 |

## 6. 검토·승인 (예시)
| 역할 | 성명 | 의견 | 결과 | 일자 |
|---|---|---|---|---|
| 검토(운영/필드) | 조필드 | 배포 단계 점진 롤아웃 권고 | 승인의견 | 2026-09-12 |
| 승인(CSM) | 이보안 | 긴급도 높음, 축약 검증 범위 승인 | 승인 | 2026-09-14 |

## 작성 시 유의사항
- 보안패치라도 패치가 새 회귀 위험을 만들 수 있으므로 델타 영향 평가를 생략하지 않는다.
- 롤백·safe-state 항목은 "지원함"이 아니라 충족 방식(A/B 파티션 등)을 구체적으로 적는다.
- VIN 범위·대수를 명시해 배포 커버리지·잔존 위험을 정량적으로 드러낸다.

## 잘못된 작성 사례
> ❌ 역량 요건 롤백: "가능" — 방식 불명, 검증 불가
> ✅ 역량 요건 롤백: "A/B 파티션 자동 롤백, 실패 시 이전 펌웨어 유지" — 메커니즘 명시

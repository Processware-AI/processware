# 보안 설계·인터페이스 특성화·설계검토 작성예시 (EX-MDCS-01-02-04-01)

> 원본 양식: [[TMP-MDCS-01-02-04-01_보안설계_인터페이스특성화_및_설계검토_v0.1]]

> ⚠️ 이 파일은 **교육·가이드용 가상 샘플** 입니다.

## 작성 안내
- 작성자 / 작성일 / 결재 경로: 가상인물 B(보안 아키텍트) / 2026-05-22 / 작성→독립 검토→승인

## 1. 모듈별 안전 설계
| 모듈 | 안전 설계 메커니즘 | 적용 모범사례 |
|---|---|---|
| 인증 모듈 | 토큰 단기 만료 + 리프레시 회전 | 최소권한, 실패안전 |
| 데이터 액세스 | 파라미터 바인딩 ORM, 컬럼 암호화 | 입력 검증, 심층 방어 |

## 2. 위협 완화책 설계 반영 매핑
| 위협/완화책 | 설계 반영 메커니즘 | 반영 여부 |
|---|---|---|
| T-자격증명탈취 / MFA·토큰단기화 | 인증 모듈 토큰 회전 설계 | 반영 |
| T-SQL인젝션 / 파라미터화 | ORM 바인딩 + 입력 검증 | 반영 |
| T-잔존데이터 / 안전삭제 | 폐기 시 키 파기 루틴 | 반영 |

## 3. 인터페이스 특성화
| 인터페이스 | 유형(물리/논리) | 신뢰경계 | 전달 데이터 분류 | 인증/검증 책임 |
|---|---|---|---|---|
| 앱↔API | 논리(HTTPS) | 비신뢰→DMZ | 환자 데이터(민감) | API 게이트웨이 |
| API↔DB | 논리(내부) | 신뢰망 | 환자 데이터(민감) | 서비스 계정 최소권한 |
| 단말 USB 디버그 | 물리 | 비신뢰 | 없음(릴리스 시 비활성) | 릴리스 빌드 차단 |

## 4. 설계 검토 약점 추적
| # | 약점 | 심각도 | 조치 | 종결 여부 |
|---|---|---|---|---|
| 1 | 리프레시 토큰 폐기 경로 미정의 | 중 | 로그아웃 시 토큰 무효화 설계 추가 | 종결 |

## 작성 시 유의사항
- 위협 모델의 모든 완화책이 구체적 설계 메커니즘으로 반영되었는지 "반영 여부" 로 확인한다.
- 인터페이스는 신뢰경계와 데이터 분류, 인증/검증 책임 주체를 명시한다.
- 디버그/물리 인터페이스는 릴리스 시 비활성 여부까지 특성화한다.

## 잘못된 작성 사례
> ❌ 완화책 "반영 여부" 칸 공란 → 위협-설계 추적 불완전
> ✅ 각 완화책에 "반영/미반영" + 설계 메커니즘 명시
> ❌ 물리 디버그 인터페이스 누락 → 릴리스 빌드 차단 여부 미검토

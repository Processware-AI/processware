## 2. 사이버보안 자산 목록 (예시)
| 자산 | 저장 위치 | 민감도 | 폐기 처리 필요 여부 |

| 디바이스 개인키 | TCU 보안 요소(SE) | 높음 | 예(파기) |

## 3. 폐기 시 처리 위험 (예시)
| 위험 | 설명 |
|---|---|
| 키 유출 | 폐차 부품에서 개인키 추출 시 차량 사칭·통신 위조 가능 |
| 데이터 잔존 | 위치 로그 잔존 시 개인정보 유출 |
| 부품 재사용 공격 | 폐기 부품을 타 차량에 이식해 인증 우회 시도 |

## 4. 폐기 사이버보안 요구 (예시)
| 요구 ID | 요구 내용 | 수행 절차 | 검증 방법 | 수행 주체 |
|---|---|---|---|---|
| DSR-01 | 디바이스 개인키 파기 | 정비툴로 SE 키 소거 명령 실행 | 소거 후 키 read 실패 확인 | 정비망 |
| DSR-02 | OTA 인증서 서버 측 무효화 | CRL(폐기 목록)에 인증서 등록 | CRL 등록 확인 | OEM 서버 운영 |
| DSR-03 | 저장 데이터 완전 삭제 | 정비툴 secure-wipe 실행 | 무작위 섹터 read 검증 | 정비망 |

|---|---|---|---|

| 재활용업체 협회 | 폐차 사이버보안 가이드 | 2027-05-22 | 협회 접수 회신 |

|---|---|---|---|---|

| 검토(운영/필드) | 조필드 | 정비망 secure-wipe 교육 필요 | 조건부 | 2027-05-13 |
| 승인(CSM) | 이보안 | 교육 병행 조건 승인 | 승인 | 2027-05-14 |

## 작성 시 유의사항
- 물리 접근이 어려운 부품의 키는 서버 측 무효화(CRL 등) 대체 통제를 반드시 함께 정의한다(§7.2).
- 각 폐기 요구에 "검증 방법"을 적어 실제 파기 여부를 확인 가능하게 한다.
- 폐기 주체(정비망/재활용업체)별로 실행 가능한 수준으로 절차를 기술한다.

## 잘못된 작성 사례
> ❌ 요구: "데이터 삭제" — 방법·검증 불명, 잔존 위험
> ✅ 요구: "secure-wipe 실행 후 무작위 섹터 read 검증" — 절차·검증 명시

## 작성 안내
- 작성자 / 작성일 / 결재 경로: 김보안(개발SW팀) / 2026-05-04 / 작성→PSO 검토→PSO 승인

## 1. 제품·적용성 식별
| 항목 | 내용 |
|---|---|
| 제품/제품군 | CareSync 원격 혈당 모니터링 SW |
| 제품 버전 | v3.2 |
| 적용 범위 (전체/일부) | 제품 전체 (모바일 앱 + 클라우드 백엔드) |
| 제외 항목 및 사유 | 사내 분석용 BI 대시보드 — 환자 데이터 비접촉·외부 노출 없음, 보안 영향 없어 제외 |
| 의도된 사용·배포 형태 | 환자 스마트폰 설치형 앱 + 제조자 운영 클라우드 |

## 2. SW 항목 분류표
| # | SW 항목명 | 출처(자체/외부/OTS) | 분류(MAINTAINED/SUPPORTED/REQUIRED) | 분류 근거(업데이트 책임 주체) | 비고 |
|---|---|---|---|---|---|
| 1 | CareSync 모바일 앱 코어 | 자체 | MAINTAINED | 제조자가 직접 보안 패치 개발·배포 |  |
| 2 | CareSync 클라우드 API 서버 | 자체 | MAINTAINED | 제조자 운영·직접 패치 |  |
| 3 | OpenSSL 1.1.x | 외부 OSS | MAINTAINED | 제조자가 번들·재빌드하여 패치 제공 | SBOM 추적 대상 |
| 4 | 단말 OS(Android/iOS) | REQUIRED | REQUIRED | 사용자 환경 제공, 제조자 통제 밖 | 최소 버전 요건 동반문서 명시 |
| 5 | 클라우드 관리형 DB 엔진 | 외부 OTS(관리형) | SUPPORTED | 제조자가 취약점 모니터링, 패치는 클라우드 제공자 적용 |  |

## 작성 시 유의사항
- MAINTAINED/SUPPORTED/REQUIRED 는 "누가 보안 업데이트를 개발·제공하는가" 를 기준으로 판정한다.
- 제외 항목은 반드시 사유를 적어 사후 검토가 가능하게 한다.
- 외부 OSS 라도 제조자가 재빌드·번들해 패치하면 MAINTAINED 이다(항목 3 참고).

## 잘못된 작성 사례
> ❌ 4행을 "MAINTAINED" 로 표기 — 단말 OS 패치는 제조자가 통제하지 못하므로 REQUIRED 가 맞음
> ✅ "REQUIRED — 사용자 환경 제공, 제조자 통제 밖, 최소 버전 요건 동반문서 명시"
> ❌ 분류 근거 칸을 비움 — 후속 모니터링 책임 판정 불가

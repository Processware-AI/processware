# 취약점 모니터링 기록표 작성예시 (EX-MDCS-01-03-02-01)

> ⚠️ 이 파일은 **교육·가이드용 가상 샘플** 입니다. CVE 번호는 가상입니다.

## 작성 안내
- 작성자 / 작성일 / 결재 경로: 최운영(보안운영팀) / 2026-05-25 / 작성→PSO 검토

## 1. 모니터링 대상·주기
| 항목 | 내용 |
|---|---|
| 대상 제품/SBOM 참조 | CareSync v3.2 / SBOM-CS32-v1 |
| 검토 주기 | 주 1회(긴급 권고 시 수시) |
| 정보원 목록 | NVD, KISA, 벤더 보안권고, OSS GitHub Advisory |

## 2. 모니터링 기록
| 검토 일자 | 정보원 | 신규 취약점(CVE) | 매칭 컴포넌트/버전 | 적용 가능 여부 | PRO-01-05 연계 ID |
|---|---|---|---|---|---|
| 2026-05-19 | NVD | CVE-가상-2026-1001 | OpenSSL 1.1.1k | 적용(원격) | VUL-2026-052 |
| 2026-05-19 | GitHub Advisory | CVE-가상-2026-1010 | log 라이브러리 1.2 | 미적용(미사용 기능) | — |
| 2026-05-26 | 벤더 권고 | 가상-Authly-SA-03 | 인증 SDK 2.1 | 적용(인증 필요) | VUL-2026-058 |

## 작성 시 유의사항
- 매칭은 SBOM 의 정확한 버전 기준으로 한다(버전 불일치 시 SBOM 보정 요청).
- "미적용" 판정도 사유(미사용 기능 등)를 기록해 추적성을 남긴다.
- 적용 가능 건은 반드시 PRO-MDCS-01-05 연계 ID 를 남긴다.

## 잘못된 작성 사례
> ❌ "취약점 여러 건 확인" 만 기재 — CVE·컴포넌트·연계 누락
> ✅ CVE 번호 + 매칭 버전 + 적용성 + 연계 ID 명시
> ❌ 적용 가능인데 연계 ID 공란 → 처리 누락 위험

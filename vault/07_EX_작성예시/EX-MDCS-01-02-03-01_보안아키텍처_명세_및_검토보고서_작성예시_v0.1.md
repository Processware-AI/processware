# 보안 아키텍처 명세 및 검토보고서 작성예시 (EX-MDCS-01-02-03-01)

> 원본 양식: [[TMP-MDCS-01-02-03-01_보안아키텍처_명세_및_검토보고서_v0.1]]

> ⚠️ 이 파일은 **교육·가이드용 가상 샘플** 입니다.

## 작성 안내
- 작성자 / 작성일 / 결재 경로: 가상인물 B(보안 아키텍트) / 2026-05-16 / 작성→독립 검토→승인

## 1. 아키텍처 개요
| 항목 | 내용 |
|---|---|
| 제품/버전 | CareSync v4.0 |
| 아키텍처 다이어그램 참조 | ARCH-CS40-v1 (별첨) |

## 2. 컴포넌트·신뢰경계·통제 배치
| 컴포넌트 | 신뢰경계 | 배치된 보안 통제 |
|---|---|---|
| 모바일 앱 | 단말(비신뢰) | 입력 검증, 키스토어, 루팅 탐지 |
| API 게이트웨이 | DMZ | TLS, 인증/인가, 레이트리밋, WAF |
| 데이터 서비스 | 내부 신뢰망 | 최소권한, 필드 암호화, 감사 로깅 |

## 3. 방어심층화 계층 매핑
| 위협 | 예방 계층 | 탐지 계층 | 복구 계층 | 단일 실패점/완화 |
|---|---|---|---|---|
| 자격증명 탈취 | MFA, 토큰 단기화 | 이상 로그인 탐지 | 세션 강제 종료 | 인증서버 다중화 |
| 데이터 유출 | 필드 암호화, 최소권한 | 감사 로그 모니터링 | 키 회전 | 단일 키관리 → HSM 이중화 |

## 4. 요구-아키텍처 추적 및 악조건 거동
| 요구 ID | 충족 통제 | 악조건 거동(fail-safe/secure) |
|---|---|---|
| SR-001 | MFA + 토큰 단기화 | 인증 실패 시 접근 거부(fail-secure) |
| SR-002 | 필드 암호화 + HSM | 키 접근 불가 시 복호화 차단 |

## 5. 검토 발견·약점 추적
| # | 약점 | 심각도 | 조치 | 종결 여부 |
|---|---|---|---|---|
| 1 | 키관리 단일 실패점 | 중 | HSM 이중화 설계 반영 | 종결 |
| 2 | 레이트리밋 우회 경로 | 하 | 게이트웨이 정책 보강 | 종결 |

## 작성 시 유의사항
- 각 위협은 예방·탐지·복구의 다층 통제로 매핑해 단일 실패점을 식별·완화한다.
- 악조건 거동은 fail-secure(접근 거부) 방향을 명시한다.
- 모든 보안 요구 ID 가 아키텍처 통제로 추적되는지 확인한다.

## 잘못된 작성 사례
> ❌ 위협별 통제를 "암호화" 한 계층만 기재 — 방어심층화(다층) 미충족
> ✅ 예방(MFA)+탐지(이상탐지)+복구(세션종료) 3계층 매핑
> ❌ 약점을 "진행중" 으로 둔 채 승인 — 약점 종결 후 승인해야 함

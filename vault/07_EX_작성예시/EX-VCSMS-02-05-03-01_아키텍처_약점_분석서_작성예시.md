# 아키텍처 약점 분석서 작성예시 (EX-VCSMS-02-05-03-01)

> 원본 양식: [[TMP-VCSMS-02-05-03-01_아키텍처_약점_분석서]]

> ⚠️ 이 파일은 **교육·가이드용 샘플** 입니다. 실제 기록으로 사용하지 마세요. 실제 기록은 `08_REC_기록/` 에 REC 로 생성. (가상 RKE 예시)

## 0. 문서 정보
| 항목 | 내용 |
|---|---|
| 컴포넌트/아키텍처명 | BCM RKE 인증 모듈 |
| 분석 방법 | 아키텍처 검토 + CWE 매핑 + STRIDE |
| 분석자 / 분석일 | 이설계 / 2026-06-14 |

## 1. 약점 식별 ([RQ-10-07])
| 약점ID | 위치 | 설명 |
|---|---|---|
| WK-01 | RF 수신 파서 | 가변길이 페이로드 경계검사 누락 가능(CWE-120) |
| WK-02 | 진단 인터페이스 | 인증 없는 디버그 명령 노출 가능(STRIDE: Elevation) |
| WK-03 | 카운터 저장소 | 비휘발성 메모리 카운터 롤백 공격 여지 |

## 2. 약점 영향·관련 사양
| 약점ID | 영향 사양 | 영향 자산 |
|---|---|---|
| WK-01 | SP-01 | RF 인증 메시지 |
| WK-02 | SP-03 | FOB 키/디버그 채널 |
| WK-03 | SP-01 | 카운터 신선도 |

## 3. 처리 방향
| 약점ID | 처리 | 근거·보상통제 |
|---|---|---|
| WK-01 | 설계변경 | 경계검사 추가, 정적분석 룰 강화 |
| WK-02 | 사양보완 | SP-03 에 진단 인증 요구 추가(WI-05-01 피드백) |
| WK-03 | 수용 | 롤백 난도 높음, 모니터링 보상통제. CSM 수용 |

## 4. 결재
| 역할 | 성명 | 결정 | 일자 |
|---|---|---|---|
| 작성(보안 설계자) | 이설계 | 작성완료 | 2026-06-14 |
| 검토(Project CS Lead) | 김보안 | 이상없음 | 2026-06-14 |
| 검토(개발자) | 최개발 | 반영가능 | 2026-06-14 |
| 승인(CSM) | 정관리 | 승인 | 2026-06-14 |

## 작성 시 유의사항
- WI-05-02 잔존 위반·제약을 약점 후보로 반드시 포함
- 사양 결함 기인 약점은 WI-05-01 사양 보완으로 피드백(WI §7.1)
- 수용 약점은 잔여 리스크 근거+보상통제+CSM 결정 필수(WI §7.2)

## 잘못된 작성 사례
> ❌ 약점만 나열하고 처리 방향 미결
> ✅ 약점별 처리(설계변경/사양보완/테스트/수용) 결정
> ❌ 운영 단계 약점을 본 분석서에 혼입
> ✅ 운영 약점은 PRO-VCSMS-01-03 으로 이관, 참조만

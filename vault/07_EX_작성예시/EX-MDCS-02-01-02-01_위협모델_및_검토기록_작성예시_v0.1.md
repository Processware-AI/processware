# 위협모델 및 검토기록 작성예시 (EX-MDCS-02-01-02-01)

> 원본 양식: [[TMP-MDCS-02-01-02-01_위협모델_및_검토기록_v0.1]]

> ⚠️ 이 파일은 **교육·가이드용 가상 샘플** 입니다.

## 작성 안내
- 작성자 / 작성일 / 결재 경로: 가상인물 A(위협모델링 리드) / 2026-05-12 / 작성→개발팀 검토→PSO 승인

## 1. 위협 모델 개요
| 항목 | 내용 |
|---|---|
| 제품/버전 | CareSync v4.0 |
| 데이터 흐름도 참조 | DFD-CS40-v1 |
| 보안 맥락 참조 | 보안맥락 문서 v1 |

## 2. 자산·신뢰경계
| 자산 | CIA 중요도 | 신뢰경계 |
|---|---|---|
| 환자 혈당 데이터 | C:상 I:상 A:중 | 단말↔DMZ↔내부 |
| 인증 토큰 | C:상 I:상 | 단말↔DMZ |
| 알람 트리거 로직 | I:상 A:상 | 내부 |

## 3. 위협·공격 벡터
| 위협 ID | 대상 자산 | 위협 유형 | CIA 영향 | 공격 벡터/진입점 |
|---|---|---|---|---|
| T-01 | 인증 토큰 | Spoofing | C,I | 탈취된 토큰 재사용(앱↔API) |
| T-02 | 환자 데이터 | Information Disclosure | C | 권한 우회 API 호출 |
| T-03 | 알람 로직 | Tampering | I,A | 변조된 임계값 주입 |

## 4. 개발팀 검토 기록
| 검토 항목 | 결과 | 도출 이슈/연계 |
|---|---|---|
| 신뢰경계 누락 여부 | 보완(USB 디버그 경계 추가) | — |
| T-02 실제 재현 | 재현됨 | VUL-2026-060 연계(문제해결) |

## 작성 시 유의사항
- 자산별 CIA 중요도를 명시하고, 위협을 체계(STRIDE)로 매핑한다.
- 검토 중 실제 재현된 위협(T-02)은 문제해결로 연계한다.
- 공격 벡터에 진입점·신뢰경계를 함께 적는다.

## 잘못된 작성 사례
> ❌ 위협을 "해킹 위험" 처럼 모호하게 기재 → 통제 설계 불가
> ✅ "T-01 Spoofing / 토큰 재사용 / 앱↔API 진입점" 구체화
> ❌ 개발팀 검토 없이 PSO 승인 → 7.2 검토 요구 미충족

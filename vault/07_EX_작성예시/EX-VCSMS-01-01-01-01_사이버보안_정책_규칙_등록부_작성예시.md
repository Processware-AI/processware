# 사이버보안 정책·규칙 등록부 작성예시 (EX-VCSMS-01-01-01-01)

> 원본 양식: [[TMP-VCSMS-01-01-01-01_사이버보안_정책_규칙_등록부]]

> ⚠️ 이 파일은 **교육·가이드용 샘플** 입니다. 실제 기록으로 사용하지 마세요. 실제 기록은 `08_REC_기록/` 에 REC 로 생성.

## 1. 작성 안내 (예시)
- 작성자 / 작성일 / 결재 경로: 김보안(CSM) / 2026-06-20 / CSM → PCB → 경영진
- 근거: ISO/SAE 21434 §5.4.1 [RQ-05-01·02·08]

## 2. 정책 요지 (예시)
| 항목 | 내용 |
|---|---|
| 정책명 | 자동차 사이버보안 거버넌스 정책 v1.0 |
| 리스크 인지 선언 | 당사 E/E 제품의 차량 사이버보안 위협을 전 수명주기 리스크로 인지함 |
| 경영 관리 의지 | 경영진은 사이버보안을 품질·안전과 동등한 최우선 관리 항목으로 둔다 |
| 적용 범위 | 당사가 설계·생산하는 모든 item/component, 컨셉~폐기 단계 |
| 검토 주기 | 연 1회(매년 1분기 경영검토 연계) |
| 정책 버전 | v1.0 (2026-06-20 승인) |

## 3. 규칙·프로세스 등록 항목 (예시)
| 규칙 ID | 규칙·프로세스명 | 근거 조항 | 소유 프로세스 | 검토 주기 | 상태 |
|---|---|---|---|---|---|
| RULE-GOV-01 | 거버넌스 운영 규칙 | §5.4.1 | PRO-VCSMS-01-01 | 연 1회 | 운영 |
| RULE-AUD-01 | 독립 감사 규칙 | §5.4.7 | PRO-VCSMS-01-02 | 연 1회 | 운영 |
| RULE-CONT-01 | 지속활동·취약점 관리 규칙 | §8.3~8.6 | PRO-VCSMS-01-03 | 분기 | 운영 |

## 4. 지속적 개선 메커니즘 ([RQ-05-08]) (예시)
| 개선 트리거 | 갱신 경로(에스컬레이션) | 책임자 |
|---|---|---|
| 감사 부적합 발행 | CSM 검토 → PCB 안건 → 경영진 승인 | CSM |
| KPI 목표 미달(2분기 연속) | CSM 분석 → PCB 검토 | CSM |
| 표준 개정 공표 | CSM 영향평가 → PCB → 경영진 | CSM |

## 5. 검토·승인 (예시)
| 구분 | 성명/역할 | 결정 | 일자 | 기록 ID |
|---|---|---|---|---|
| 검토(PCB) | PCB 의장 외 4인 | 조건부승인 → 반영 후 승인 | 2026-06-18 | PCB-2026-014 |
| 승인(경영진) | 대표이사 | 승인 | 2026-06-20 | EAPP-2026-0331 |

## 6. 작성 시 유의사항
- 정책 요지는 경영진 친화 어휘로 1~2 페이지 분량을 넘기지 않는다(기술 상세는 규칙 문서로 분리).
- 규칙 ID 는 추적 가능한 고유 식별자를 부여(영역·유형 약어 + 일련번호).
- 개선 트리거는 측정 가능한 조건으로 기술("성능 나쁨" ❌ → "KPI 목표 미달 2분기 연속" ✅).

## 7. 잘못된 작성 사례
> ❌ "보안 강화" — 리스크 인지·범위 불명확
> ✅ "당사 E/E 제품의 차량 사이버보안 위협을 전 수명주기 리스크로 인지함" — 대상·범위 명시
> ❌ 검토 주기 공란 — §5.4.1 정책 검토 의무 미충족
> ✅ "연 1회(매년 1분기 경영검토 연계)" — 주기·연계 시점 명시

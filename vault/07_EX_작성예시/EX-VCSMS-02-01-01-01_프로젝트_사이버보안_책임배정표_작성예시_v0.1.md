# 프로젝트 사이버보안 책임배정표 작성예시 (EX-VCSMS-02-01-01-01)

> 원본 양식: [[TMP-VCSMS-02-01-01-01_프로젝트_사이버보안_책임배정표]]

> ⚠️ 이 파일은 **교육·가이드용 샘플** 입니다. 실제 기록으로 사용하지 마세요. 실제 기록은 `08_REC_기록/` 에 REC 로 생성.

## 1. 프로젝트 식별 (예시)
| 항목 | 예시값 | 작성 요령 |
|---|---|---|
| 프로젝트명 / 헌장번호 | 차세대 게이트웨이 ECU "GW-X2" / PRJ-2026-014 | 양산 프로그램 코드 명시 |
| 대상 item/component 범위 | 중앙 게이트웨이 item, 텔레매틱스 통신 인터페이스 | item/component 단위로 |
| 적용 단계 | 컨셉~개발 (생산은 별도 차수) | 본 차수 적용 범위 한정 |
| 작성일 / 버전 | 2026-06-14 / v0.1 | |

## 2. 역할·책임 배정 (RACI) (예시)
| 역할 | 담당자 | R/A/C/I | 의사결정 권한 | 보고선 | 비고 |
|---|---|---|---|---|---|
| Project CS Lead | 김보안 (CS팀) | R/A | 계획 확정, 진척 보고 | CSM 직속 | |
| TARA 분석가 | 이위협 (CS팀) | R | 리스크값 산정 | CS Lead | |
| 보안 설계자 | 박설계 (E/E설계팀) | C | 통제 설계 | 설계팀장 | |
| 검증 담당 | 최검증 (검증팀) | R | 검증 활동 선정 | 검증팀장 | |
| 독립 평가 Assessor | 정독립 (품질본부) | R/A | 수용/조건부/거부 권고 | **개발라인과 분리(품질본부)** | 독립성 확보 |

## 3. 진척 추적·계획 유지 책임 (예시)
| 항목 | 담당자 | 비고 |
|---|---|---|
| 진척 추적 | 김보안 (CS Lead) | 주간 리뷰 |
| 계획 유지·갱신 | 김보안 (CS Lead) | 변경 발생 시 5영업일 내 갱신 |

## 4. 자원 확인 (예시)
| 자원 항목 | 확보 여부 | 미확보 시 조치 |
|---|---|---|
| 인시(공수) | Y (분석가 0.5 FTE) | — |
| 도구/환경 | N (TARA 도구 라이선스 미확보) | 경영진 에스컬레이션, 7/1까지 확보 |
| 예산 | Y | — |

## 5. 전파·승인 (예시)
| 항목 | 예시값 |
|---|---|
| 전파 대상 부서 | E/E설계팀, 검증팀, 품질본부, 구매팀, 기능안전팀 |
| 수신 확인 | 2026-06-15 배포, 전원 수신 회신 |
| 승인자 / 승인일 | 경영진 CTO 홍길동 / 2026-06-16 |

## 작성 시 유의사항
- 독립 평가 Assessor 는 반드시 개발라인과 다른 보고선에 둔다(이해상충 차단).
- 자원 미확보 항목은 공란으로 두지 말고 "N + 조치·기한"을 명시한다.
- 담당자는 직책이 아닌 실명+소속으로 기재한다(책임 추적성).

## 잘못된 작성 사례
> ❌ "독립 평가 — CS Lead 겸임" — 이해상충, 겸임 금지 위반
> ✅ "독립 평가 — 품질본부 정독립, 개발라인과 분리"
> ❌ "자원: 확보" — 무엇을 얼마나 확보했는지 불명
> ✅ "인시 0.5 FTE 확보 / 도구 라이선스 N → 7/1 확보 예정"

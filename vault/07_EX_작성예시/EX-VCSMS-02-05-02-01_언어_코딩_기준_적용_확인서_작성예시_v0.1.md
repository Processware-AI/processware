# 언어·코딩 기준 적용 확인서 작성예시 (EX-VCSMS-02-05-02-01)

> 원본 양식: [[TMP-VCSMS-02-05-02-01_언어_코딩_기준_적용_확인서]]

> ⚠️ 이 파일은 **교육·가이드용 샘플** 입니다. 실제 기록으로 사용하지 마세요. 실제 기록은 `08_REC_기록/` 에 REC 로 생성. (가상 RKE 예시)

## 0. 문서 정보
| 항목 | 내용 |
|---|---|
| 컴포넌트명 | BCM RKE 인증 모듈 |
| 언어/표기 | C (MISRA C:2012 적용) |
| 작성자 / 작성일 | 최개발 / 2026-06-14 |

## 1. 언어·표기 선정 기준 평가 ([RQ-10-04])
| 기준 | 언어 | 충족(O/X) |
|---|---|---|
| 명확성 | C | O |
| 모듈성 | C | O |
| 메모리 안전(복원력) | C | X (언어 자체 미보장) |

## 2. 보완 가이드라인·환경 ([RQ-10-05])
| 미충족 기준 | 보완 방안 |
|---|---|
| 메모리 안전 | MISRA C:2012 + 정적분석(Polyspace) + 경계검사 매크로 |

## 3. 검증된 설계·구현 원칙 적용 ([RC-10-06])
| 적용 원칙 | 적용(O/X) | 미적용 근거 |
|---|---|---|
| 입력검증 | O | - |
| 최소권한 | O | - |
| 안전한 기본값 | O | - |
| 심층방어 | O | - |
| 공격표면 최소화 | X | 진단 인터페이스 유지 필요(운영 요건), 약점 등록 |

## 4. 적용 점검
| 점검 항목 | 결과 |
|---|---|
| 정적분석 위반 총 건 / 시정 건 | 12 / 11 |
| 미시정 잔존(약점 등록) | 1건 (WI-05-03 입력 등록) |

## 5. 결재
| 역할 | 성명 | 결정 | 일자 |
|---|---|---|---|
| 작성(개발자) | 최개발 | 작성완료 | 2026-06-14 |
| 승인(보안 설계자) | 이설계 | 승인 | 2026-06-14 |

## 작성 시 유의사항
- 언어가 못 채우는 기준은 "X"로 솔직히 표기 후 §2 보완 명시
- 권고 원칙([RC-10-06]) 미적용은 반드시 근거 기재
- 미시정 위반은 약점으로 등록해 WI-05-03 으로 인계(누락 금지)

## 잘못된 작성 사례
> ❌ 모든 기준 "O" 로 형식 기재
> ✅ 메모리 안전 X + 정적분석 보완 명시 (현실 반영)
> ❌ 위반 11/12 인데 잔존 1건 미등록
> ✅ 잔존 위반 약점 등록 + 인계 명시

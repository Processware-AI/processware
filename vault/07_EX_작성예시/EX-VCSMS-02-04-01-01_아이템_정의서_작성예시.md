# 아이템 정의서 작성예시 (EX-VCSMS-02-04-01-01)

## 1. 아이템 경계 ([RQ-09-01])
### 1.1 포함 컴포넌트
| 컴포넌트/ECU/기능 | 포함/제외 | 비고 |
|---|---|---|
| RKE 수신 ECU(BCM 내) | 포함 | 본 아이템 핵심 |
| 키 포브(FOB) | 포함 | 외부 송신기 |
| 도어락 액추에이터 | 제외 | 인접 시스템(인터페이스만) |

### 1.2 외부 인터페이스
| 인터페이스 | 유형 | 방향 |
|---|---|---|
| RF 433MHz 무선 채널 | 무선 | In |
| CAN-Body 버스 | 차내망 | 양방향 |
| OBD-II 진단 포트 | 진단 | 양방향 |

## 2. 기능 ([RQ-09-01])
| 기능/서비스 | 입력 | 출력 | 데이터 흐름 |
|---|---|---|---|
| 원격 잠금/해제 | FOB 버튼 RF 신호 | 도어락 명령 | FOB→RF→BCM→CAN→액추에이터 |
| 롤링코드 인증 | RF 페이로드 | 인증 결과 | BCM 내부 검증 |

## 3. 예비 아키텍처 ([RQ-09-01])
FOB(송신) → RF 수신부 → BCM 내 RKE 인증 모듈(신뢰경계 ①) → CAN 게이트웨이(신뢰경계 ②) → 액추에이터. 신뢰경계 ①은 암호 인증, ②는 메시지 무결성 검증 지점으로 식별. 상세 설계는 Clause 10 이연.

## 4. 운용환경 정보 ([RQ-09-02])
차량 정차/주행 중 상시 동작. FOB 는 사용자가 휴대(분실·복제 위협 환경). 주차장·공공장소 등 RF 도청 가능 환경 가정. 백엔드 연결 없음(로컬 인증).

### 4.1 가정·전제 (Assumptions)
| 가정 | 근거 |
|---|---|
| FOB 비밀키는 제조 시 안전 주입됨 | 공급사 생산 보안 인수 |
| OBD 포트는 정비 환경에서만 물리 접근 | 운용 시나리오 |

## 작성 시 유의사항
- 경계 표에서 "제외" 컴포넌트라도 인터페이스가 있으면 §1.2 에 반드시 기재
- 가정·전제는 클레임 검증 추적에 쓰이므로 근거와 함께 명시
- 미확정 아키텍처는 "TBD(가정 명시)"로 표기 (WI §7.1)

## 잘못된 작성 사례
> ❌ "RKE 시스템 전체" — 경계가 모호, 포함/제외 미구분
> ✅ 컴포넌트별 포함/제외 + 외부 인터페이스 목록화
> ❌ 운용환경에 가정을 섞어 서술 — 검증 추적 불가
> ✅ 운용환경(§4)과 가정·전제(§4.1) 분리 기재

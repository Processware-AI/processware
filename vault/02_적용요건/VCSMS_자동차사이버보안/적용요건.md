# ACSMS 적용요건 — ISO/SAE 21434:2021 자동차 사이버보안 엔지니어링

> 상위 기준: [[표준프로세스_구성원칙]] · 문서체계: [[01_문서체계]] · 분류: [[07_표준분류레지스트리]]

## 1. 표준 개요

### 1.1 목적
ISO/SAE 21434 는 도로차량 전기·전자(E/E) 시스템의 **사이버보안 엔지니어링**을 위한 요구사항을 규정한다. 차량 컨셉 단계부터 개발·생산·운영·유지보수·지원종료·폐기에 이르는 전(全) 수명주기에 걸쳐 사이버보안 리스크를 체계적으로 관리하도록 한다. 조직 차원의 거버넌스, 프로젝트 차원의 관리, 분산(공급망) 활동, 지속적 활동, 위협분석·리스크평가(TARA) 방법론을 포괄한다.

### 1.2 적용범위
- 양산 도로차량의 E/E 시스템, 그 구성요소(item·component) 및 인터페이스의 사이버보안 엔지니어링.
- 사후 양산(post-development) 활동 — 생산, 운영·유지보수, 지원종료, 폐기 포함.
- 제외: 특정 기술/솔루션의 사이버보안 처방, 도로 인프라·후방 서버(backend) 자체의 보안 구현 세부.

### 1.3 구조 (`phase_lifecycle`)
ISO/SAE 21434 는 HLS(Annex SL) 구조가 아니라 **수명주기 단계(phase) 기반**으로 조직된다. 본선(normative) 조항은 Clause 5–15 이며 Clause 1–4 는 범위·인용·용어·일반사항, Annex A–H 는 전부 **informative**(지침·예시)다.

| 조항군 | 단계 성격 | 비고 |
|---|---|---|
| Clause 5 | 조직 거버넌스 (전사) | 정책·문화·역량·도구·감사 |
| Clause 6 | 프로젝트 관리 (프로젝트) | 계획·테일러링·케이스·평가·릴리스 |
| Clause 7 | 분산 활동 (공급망) | 역량평가·RFQ·인터페이스 합의(CIA) |
| Clause 8 | 지속적 활동 (상시) | 모니터링·이벤트·취약점 관리 |
| Clause 9–11 | 컨셉·개발·검증 (V-model) | 아이템정의·목표·컨셉·설계·통합·검증 |
| Clause 12–14 | 생산·운영·종료 (post-dev) | 생산통제·사고대응·업데이트·지원종료 |
| Clause 15 | TARA 방법론 (횡단) | 자산→위협→영향→경로→타당성→리스크값→처리 |

### 1.4 통합방식 (`interface_only`)
VCSMS 는 **독립 영역코드 체계**로 빌드한다. HLS(L1) 경영시스템의 POL/PRO 에 본 요건을 병합하지 않으며, 다음 경계면(interface)에서만 상위 L1 을 **"참조" 링크**로 연결한다.

| 경계면 | 상위 L1 (HLS) | VCSMS 측 근거 조항 |
|---|---|---|
| 리스크 거버넌스 | §6.1 | Clause 6 (프로젝트 사이버보안 관리) |
| 공급자 관리 | §8.4 | Clause 7 (분산 사이버보안 활동) |
| 변경/형상/문서/요구사항 관리 | §7.5 / §8.5 | §5.4.4 (QMS) — [RQ-05-11] |
| 정보보안 관리 (ISMS) | ISO 27001 | §5.4.6 — [RC-05-16] |
| 역량 관리 | §7.2 | §5.4.2 — [RQ-05-07] |
| 내부심사 | §9.2 | §5.4.7 (조직 사이버보안 감사) — [RQ-05-17] |

> interface_with (레지스트리): **ISO 26262**(기능안전·영향등급 도출 §15.5), **UNECE R155**(CSMS 규제), **UNECE R156**(SW 업데이트 SUMS), **Automotive SPICE**(프로세스 성숙도), **ISO/IEC 27001**(정보보안). 상세는 REF 참조.
